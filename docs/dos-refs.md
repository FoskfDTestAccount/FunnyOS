## 一、INT 10h —— 视频服务

M4 只做文本模式,所以下面只列与文本模式有关的。

| AH | 功能 | 入口 | 出口 |
|---|---|---|---|
| `00h` | 设置视频模式 | AL = 模式 | — |
| `01h` | 设置光标形状 | CH = 起始扫描线,CL = 结束扫描线 | — |
| `02h` | 设置光标位置 | DH = 行,DL = 列,BH = 页 | — |
| `03h` | 读光标位置与形状 | BH = 页 | DH/DL = 位置,CX = 形状 |
| `05h` | 选择活动页 | AL = 页 | — |
| `06h` | 窗口上滚 | AL = 行数,**BH = 填入属性**,CH/CL = 左上行/列,DH/DL = 右下行/列 | — |
| `07h` | 窗口下滚 | 同 `06h` | — |
| `08h` | 读光标处的字符与属性 | BH = 页 | AL = 字符,AH = 属性 |
| `09h` | 在光标处写字符**与属性** | AL = 字符,BH = 页,BL = 属性,CX = 重复次数 | — |
| `0Ah` | 在光标处写字符(**保留属性**) | AL = 字符,BH = 页,CX = 重复次数 | — |
| `0Eh` | 电传输出 | AL = 字符,BH = 页 | — |
| `0Fh` | 取当前模式 | — | AL = 模式,AH = 列数,BH = 活动页 |

### 三处容易写错的地方

**一、`06h`/`07h` 的 `BH` 不是页号,是填入属性。** 这是这两个功能在整个 `INT 10h` 里唯一一处 `BH` 不代表页的地方。而且:

- **`AL = 0` 表示"整个窗口填满属性"**,不是"滚 0 行"。滚 0 行是"什么都不做"——**两者差一整屏**,而它们的区别**只在 `AL=0` 时看得出来**。
- 窗口由 `CH/CL`(左上)和 `DH/DL`(右下)给出,**不是整屏**。

**二、`09h`/`0Ah` 不动光标,`0Eh` 动。** 这是两条不同的规则,不要合并成一条。

**三、`0Eh` 在文本模式下不写属性字节。** 它把字符写进目标单元、**保留那个单元上原有的属性**,`BL` 只在图形模式下作为前景色有意义。这不只是细节:在空白屏(属性已经是 `07h`)上打字,两种实现看起来一样;而先在整屏写满彩色属性、再用 `0Eh` 在上面打字,用 `BL` 的实现会把颜色擦掉,真机不会。

其它确认过的:

- `0Eh` 执行控制字符(响铃、回车等)而不是把它们当可打印字符打出来。
- `0Eh` **在屏幕底部时靠内部转调 `06h` 完成上滚**——也就是说 `0Eh` 和 `06h` 的滚动语义必须是同一份,不要在两处各写一遍。
- `0Eh` **不影响 `BX`/`CX`/`DX` 与段寄存器**;`SI`/`DI` **可能被改**。
- `09h`/`0Ah` 与 `0Eh` 的区别是:`09h`/`0Ah` 是"用明确属性写、光标不动",`0Eh` 是"电传式、光标前进"。

| 问题 | 结论 | 出处 |
|---|---|---|
| `0Eh` 往哪一页写 | **活动页**,不是 `BH` | **两个仓库里是同一句注释**:`case 0x0E:`(vgabios)/ `handle_100e()`(SeaBIOS)都写着 *"Ralf Brown Interrupt list is WRONG on bh(page) / We do output only on the current page !"*。实现:vgabios 传 `0xff` 当页号,函数开头 `if (page == 0xff) page = read_byte(BIOSMEM_SEG, BIOSMEM_CURRENT_PAGE);`;SeaBIOS 用 `get_cursor_pos(GET_BDA(video_page))` |
| `0Eh` 的 `BS` | 列退一格、**到 0 为止**,不爬到上一行 | **两份独立实现逐字一致**:vgabios `case 8: if (xcurs > 0) xcurs--;`,SeaBIOS `case 8: if (pcp->x > 0) pcp->x--;` |
| `0Eh` 的 `TAB` | **规则作废**,见下面**注一** | 两份都不做这件事 |
| `0Eh` 上滚时新行填什么属性 | **两份不一致**(原条目成立);vgabios 动态、SeaBIOS 固定 `0x07` | vgabios 读格子:`address = SCREEN_MEM_START(...) + (xcurs + (ycurs-1)*nbcols)*2; attr = read_byte(..., address+1);`;SeaBIOS 是常数:`vgafb_clear_chars` 里 `u16 attr = ((ca.use_attr ? ca.attr : 0x07) << 8) \| ca.car;`,滚动传的 `use_attr` 为 0 → **`0x07`** |
| `0Eh` 文本模式下不写属性字节 | **两个仓库都证实** | SeaBIOS 传 `{regs->al, regs->bl, 0}`、vgabios 传 `NO_ATTR`;`vgafb_write_char` 在 `use_attr == 0` 时只写字符那一个字节 |
| `00h` 的 `AL` bit 7 = 不清屏 | **规则成立** | vgabios `biosfn_set_video_mode`:`Bit8u noclearmem = mode & 0x80;` … `if (noclearmem == 0x00) { memsetw(...) }`;SeaBIOS `handle_1000`:`if (regs->al & 0x80) flags \|= MF_NOCLEARMEM;` |
| **新:`0Fh` 返回的 `AL` 带 bit 7** | `AL = 模式 \| (0040:0087 的 bit 7)` | vgabios `biosfn_get_video_mode`(汇编:`mov bx,#BIOSMEM_VIDEO_CTL; mov ah,[bx]; and ah,#0x80; … or al,ah`);SeaBIOS `handle_100f`。**`BIOSMEM_VIDEO_CTL` = `0040:0087`、`BIOSMEM_NB_ROWS` = `0040:0084`**(`vgatables.h`) |
| **新:`06h`/`07h` 的越界矩形是"夹取",不是"拒绝"** | 左下右下越界 → **夹到屏幕内**;左上大于右下 → 原样返回 | vgabios `biosfn_scroll` 开头:`if(rul>rlr)return; if(cul>clr)return; … if(rlr>=nbrows)rlr=nbrows-1; if(clr>=nbcols)clr=nbcols-1;`;SeaBIOS `verify_scroll` 同样:`if (lry >= nbrows) lry = nbrows-1; if (lrx >= nbcols) lrx = nbcols-1; … if (wincols <= 0 \|\| winrows <= 0) return;` |
| **新:`06h`/`07h` 的四个寄存器** | `CL`=左上**列**、`CH`=左上**行**、`DL`=右下**列**、`DH`=右下**行** | SeaBIOS `verify_scroll`:`u8 ulx = regs->cl, uly = regs->ch, lrx = regs->dl, lry = regs->dh;` —— 两条独立实现都是这个映射 |
| **新:窗口高度与"清窗"的分界** | `行数 >= 窗口高度` → **清窗**(不是滚动) | SeaBIOS `verify_scroll`:`if (lines >= winrows) lines = 0;`;vgabios 在行循环里用 `(i+nblines>rlr)\|\|(nblines==0)` 得到同样结果 |

**注一:`TAB` 那条规则作废 —— 它不在任何一份源码里。**

- vgabios 的循环**条件是反的**:
  ```c
  case '\t':
   do { biosfn_write_teletype(' ',page,attr,flag);
        biosfn_get_cursor_pos(page,&dummy,&cursor);
        xcurs=cursor&0x00ff; }while(xcurs%8==0);
  ```
  它在**列是 8 的倍数时继续**——所以从列 0 出发只写**一个**空格、停在列 1;从列 7 出发写两个、停在列 9。**这不是制表位,是 vgabios 的一个 bug**(写成 `!= 0` 才是"补到下一个制表位")。
- SeaBIOS **根本没有 `case '\t'`**(只有 7、8、`'\r'`、`'\n'` 和 default),TAB 落到默认分支,**被当成一个字形打出去**。
- **所以本机原来那条"补空格到下一个 8 的倍数"两边都不是。** 处置:**保留这个行为,但不再声称它有出处** —— 它是一个**我们的选择**(理由:它是终端该有的行为,而且 SeaBIOS 那样打一个字形会让光标只动一格);同时记下后果:**依赖 `0Eh` 的 TAB 的程序在真机上三种行为都不一致**,所以几乎没有程序会依赖它。

**注二:上滚属性那条,原条目是对的 —— 而 D(本节的查证者)中间提出的"更正"是错的,错法值得记。**

D 读到 SeaBIOS 的 `write_teletype` 传 `struct carattr attr = {' ', 0, 0}`,**从 `use_attr` 这个名字推断第三个字段的含义**,断言"不改属性"。**不对**:同一个文件里的 `vgafb_clear_chars` 写的是

```c
u16 attr = ((ca.use_attr ? ca.attr : 0x07) << 8) | ca.car;
```

——**这个标志在两个函数里含义不同**:`vgafb_write_char` 里 `use_attr == 0` 是"不碰属性字节",`vgafb_clear_chars` 里是"**用 0x07**"。**读调用点、按参数名推断被调函数的语义,就被这一处抓了个正着。** 所以:**原条目(两份不一致)成立**,vgabios 动态、SeaBIOS 固定 `0x07`。

**注三:`09h`/`0Ah` 走到屏底之后怎么办。** 两份都**不停**:

- vgabios `biosfn_write_char_attr`(文本分支)是**一次 `memsetw` 写 `count` 个字**——不问行尾、不回绕、不停(图形分支反而有 `while ((count-- > 0) && (xcurs < nbcols))` 的边界);
- SeaBIOS `handle_1009` 是 `while (count--) write_char(&cp, ca);`,而 `write_char` **只回绕、不上滚** —— 越过最底行之后它继续往后写。

**所以差别只在"最后一行之后"**:页面内存是线性的,B 的回绕与它们的线性推进**逐字节相同**;越过之后它们写进**下一页的内存**,而 **B 停住**。B 的选择更安全,而且是**决定**不是事实——应标成决定。

**注四(新):`06h`/`07h` 越界矩形,B 与两份源码都不同。** 两份都**夹取**(`rlr >= nbrows → nbrows-1`),而 B 是**拒绝**(`bottom >= BIOS10_ROWS || right >= st->columns → return`)。B 的注释给了理由("一个要求滚 rows 10..40 的程序有 bug,悄悄滚一半会掩盖它"),那是一个理由,但**现在有两条独立实现夹取**。可达的情形是具体的:**40 列模式 + `DL = 79`**(一个按 80 列写的清屏),硬件夹到 39 并清屏,B **什么都不做**。这一条应转给 B。

## 四、INT 13h —— 磁盘服务

| AH | 功能 |
|---|---|
| `00h` | 复位磁盘系统 |
| `01h` | 取上次操作的状态 |
| `02h` | 读扇区 |
| `03h` | 写扇区 |
| `04h` | 校验扇区 |
| `08h` | 取驱动器参数 |
| `15h` | 取磁盘类型 |

`02h`/`03h`/`04h` 的入口:

| 寄存器 | 含义 |
|---|---|
| AL | 要读的扇区数,**资料给的取值域是 1–128** |
| CH | 柱面号低八位 |
| CL | **位 0–5 是扇区号(从 1 开始)**,位 6–7 是柱面号的第九、第十位 |
| DH | 磁头号(软盘 0–1,硬盘 0–15) |
| DL | 驱动器号(软盘 0/1,硬盘 `80h`/`81h`) |
| ES:BX | 数据缓冲区 |

柱面的打包方式,资料给的公式是:

```
CX := ((cylinder and 255) shl 8) or ((cylinder and 768) shr 2) or sector
sector := CX and 63
```

### 状态怎么报

**用进位标志,不是用 AH。**

- **CF = 0** → 完成,`AH = 0`。
- **CF = 1** → 出错,`AH` = 错误码。

`AL` 在出口处是"实际传输的扇区数",资料明确说它**不总是可靠**。

确认过的错误码:

| 码 | 含义 |
|---|---|
| `00h` | 无错误 |
| `01h` | 功能号或驱动器不可用 |
| `02h` | 找不到地址标记 |
| `03h` | 磁盘写保护(软盘) |
| `04h` | **扇区没找到** |
| `09h` | **DMA 跨 64 KiB 边界** |
| `10h` | 不可纠正的 CRC/ECC 读错误 |
| `80h` | 超时(设备无响应) |

### `08h` 的出口(2026-10-01 补充查证,由任务 D 指出缺这一块)

程序**按返回值算容量**,所以这一组是承重值,不是装饰。

| 寄存器 | 含义 |
|---|---|
| `CF` | 成功为 0、失败为 1(F 置位时 `AH` = `07h`) |
| `AH` | 成功时为 `00h` |
| `CH` | **最大柱面号的低八位** |
| `CL` | **位 5–0 是最大扇区号(六位,从 1 起)**;位 7–6 是最大柱面号的第九、第十位 |
| `DH` | **最大磁头号**(从 **0** 起,要加一才是磁头数) |
| `DL` | 这组连续驱动器的数量 |
| `BL` | 驱动器类型(仅 AT/PS2 软盘)`01h`=360K、`02h`=1.2M、`03h`=720K、**`04h`=1.44M** |
| `ES:DI` | 指向 11 字节的软盘参数表(仅软盘) |

**出口寄存器的排布和 `02h` 的入口是同一套** —— 目的就是让一个程序把 `08h` 的结果直接喂给 `02h`,所以两边的解码必须写成同一份。

**这一组是"最后一个的下标"不是"个数"**:`DH` 从 0 起、`CL` 的扇区从 1 起,而 `DL` 却是数量。这条不对称是真的,不是笔误。

`15h`(取磁盘类型)**没有查到出口格式**,所以本机不实现(报 `01h`,让程序退回 `08h`)。在它被查证之前,任何按记忆写的类型码都是在编。

**本机在 `08h` 上还没做的两件事(已知缺口,不是疏忽 —— 2026-10-01 由任务 D 报出并留档):**

| 没做 | 为什么 |
|---|---|
| `ES:DI` → 软盘参数表 | 需要一段 11 字节的表**放在 guest 内存里**,而放在哪儿是一个接口决定(真机在 ROM 里,并且 `IVT[1Eh]` 指向它)。M4 里没有任何东西读它,而把表塞进一个随便挑的地址,是在用一个"看起来对"的东西替掉一个"明确没做"的东西。**留给 M5**,那时磁盘要开始讲介质类型 |
| `IVT[1Eh]` 仍指向本机的桩 | 同上 —— 真机上 `1Eh` 不是中断、是**一个指针**。M4 里没有程序 `INT 1Eh`,也没有程序读那 11 个字节;**但它确实是一个知道有这回事的人会去看的地方**,所以记在这里 |

**`BL`(驱动器类型)已实现,值为 `04h`(1.44M),与本机几何一致** —— 它是一个我们知道、也拥有的值,和上面两条不同。**实现位置:`dos/bios/bios13.c` 的 `08h` 分支,提交 `4fb5efc`。**

> **写"已实现"的时候要把位置写出来,这句话就是为什么。** 上面那个"已实现"是在**决定要补 `BL` 的那一刻**写进这份文件的,而实现它的提交在**之后** —— 于是有一轮的时间里,这句话描述的是一个还不存在的实现。任务 C 的审查正好落在那个窗口里,它报了"三处不一致",而我**先入为主地按"它的基准太旧"驳回了**,没有去看**它那棵树上这份文件到底怎么写的**。
>
> 准确的说法是「两次改动先后错开,审查落在中间」,而不是「文档说谎」,也不是「审查看错了」。**写参考文件的人最容易犯的错,是把"将要实现"写成"已实现"** —— 因为在他脑子里那件事已经定了。而这份文件存在的全部理由是它能被拿去核对,所以**"已实现"必须能指到一个文件和一次提交**。

### 两处行为

- **多扇区读会跨磁头、跨柱面继续**:读到柱面最后一个扇区之后,在下一个磁头的第一个扇区继续;最后一个磁头之后,在下一个柱面的第一个磁头继续。
- **DMA 传输不能跨 64 KiB 物理地址边界**(8237 的限制),所以 `09h` 是一个真实存在的拒绝理由。

### 没查到的

`AL = 0` 的含义。资料给的取值域是 1–128,**没有提到 0 这个特例**。流传的"`AL = 0` 表示 18 扇区"在这批资料里**没有出处**,所以它属于"记忆",不是"事实"。

`04h` 校验到底做不做比较也有分歧:一份资料说硬盘上**不与内存比较**(与软盘不同),另一份没这么说。

**来源:** [BIOS-interrupts (课程手册 PDF)](https://jyywiki.cn/pages/OS/manuals/BIOS-interrupts.pdf)、[AMI Hi-Flex BIOS Technical Reference 1993 (bitsavers)](http://galileo.mirrorservice.org/sites/www.bitsavers.org/pdf/americanmegatrends/Hi-Flex_ISA_and_EISA_Hi-Flex_AMIBIOS_Technical_Reference_1993.pdf)、[INT 13H — Wikipedia](https://en.wikipedia.org/api/rest_v1/page/pdf/INT_13H)。

## 五、INT 16h —— 键盘服务

| AH | 功能 | 出口 |
|---|---|---|
| `00h` | 读一个键(**没有键时等待**) | AH = 扫描码,AL = ASCII;**没有 ASCII 的键(功能键、方向键)给 AL = 0**,扫描码仍在 AH。键**被取走** |
| `01h` | 检查有没有键 | **ZF = 0 有、ZF = 1 没有**;有的话同样填 AH/AL。键**不被取走**(有一份资料说没有时 `AX = 0`) |
| `02h` | 取换挡状态 | **AL** = 换挡状态字节(即 `0040:0017`) |

### 一处来源分歧

`02h` 返回的标志字节在**哪一半寄存器**里,资料不一致:一份维基表格写 `AH`,而详细的技术资料一致写 **`AL`**。**以 `AL` 为准**,并把分歧记在这里。

`02h` **不返回扫描码**,也不返回 ASCII。这一点和 `00h`/`01h` 不同,容易顺手写成一样的。

**来源:** [INT 16H — Wikipedia](https://en.m.wikipedia.org/wiki/Int_16h)、[AMI Hi-Flex BIOS Technical Reference 1993 (bitsavers)](http://galileo.mirrorservice.org/sites/www.bitsavers.org/pdf/americanmegatrends/Hi-Flex_ISA_and_EISA_Hi-Flex_AMIBIOS_Technical_Reference_1993.pdf)。

## 六、INT 1Ah —— 时间服务

| AH | 功能 | 出口 |
|---|---|---|
| `00h` | 读系统时钟计数 | CX:DX = 自午夜以来的滴答数,AL = 午夜标志 |
| `01h` | 设置系统时钟计数 | — |
| `02h` | 读 RTC 时间 | 需要 CMOS 时钟 |
| `04h` | 读 RTC 日期 | 同上 |

- 计数以 **18.2 Hz**(资料给的是 18.2065)递增,**一天是 `0x1800B0` 个滴答**(1 573 040)。
- **午夜时计数归零**,`AL` 是"自上次读以来过了午夜"的标志。
- 计数在 `0040:006C`(双字),由 `INT 08h` 的处理程序更新;**`INT 1Ah` 只是原子地读那块内存**。回绕/午夜标志在 `0040:0070`。
- **`00h` 不改变 `BX`/`SI`/`DI`/`BP` 与段寄存器。**

### 一个真机的怪癖

**真 BIOS 把午夜标志"置位"而不是"累加"。** 所以如果连续两个午夜之间没有任何人去读这个计数,第二个午夜会丢——DOS 的日期可能因此不前进。这是真行为的缺陷,**按真机做**,别"修"它;但要写进注释和报告,免得下一个人把它当 bug 去修。

**来源:** [INT 1A,0 — Read System Clock Counter (Yale)](http://www.cs.yale.edu/flint/feng/research/BIOS/Resources/assembly/int1a-0.html)、[INT 1A - TIME - GET SYSTEM TIME](http://ics.p.lodz.pl/~mceg/telekom/RTC%20-%20Bios.pdf)、[MEMORY.LST (Ralf Brown's list, 内存区)](https://raw.githubusercontent.com/sebras/rbil/release-54/MEMORY.LST)。

## 七、BIOS 数据区(段 `0040`)

程序**直接读**这些,不通过服务调用。

| 偏移 | 大小 | 内容 |
|---|---|---|
| `0010h` | 字 | 设备字(见第二节) |
| `0013h` | 字 | 常规内存 KiB 数 |
| `0017h` | 字节 | 键盘标志,见下 |
| `0018h` | 字节 | 第二组键盘标志 |
| `0019h` | 字节 | BIOS 用来算 Alt 小键盘序列的 ASCII |
| `001Ah` | 字 | 键盘缓冲区**头**:指向下一个**要被读出**的字符 |
| `001Ch` | 字 | 键盘缓冲区**尾**:指向下一个**空闲(将被写入)**的位置 |
| `001Eh` | 32 字节 | 键盘环形缓冲区本体(16 个字,**实际只能存 15 个**) |
| `0049h` | 字节 | 当前视频模式 |
| `004Ah` | 字 | 每行列数 |
| `004Ch` | 字 | **视频页的字节长度**:80×25 文本模式是 `0x1000`(4096) |
| `0050h`–`005Fh` | 8 个字 | 八个页各自的光标位置 |
| `0060h` | 字 | 光标形状:**高字节 `0061h` 是起始扫描线,低字节 `0060h` 是结束扫描线**——也就是这个字就是 `AH=01h` 收到的那个 `CX`(`CH` 起始、`CL` 结束)。扫描线从 0 数;**结束线高于起始线就是不画光标** |
| `0062h` | 字节 | 活动页 |
| `006Bh` | 字节 | POST 时最后一次意外中断的向量号 |
| `006Ch` | 双字 | 自午夜以来的滴答计数 |
| `0070h` | 字节 | 时钟回绕(午夜)标志 |
| `0080h` | 字 | 键盘缓冲区的起始偏移(`001Eh`)——**很多机器不支持** |
| `0082h` | 字 | 键盘缓冲区的结束偏移(`003Eh`)——同上 |
| `0084h` | 字节 | **行数减一** —— 【源码】2026-10-01 补。VGA BIOS 用它而不是常量:`read_byte(BIOSMEM_NB_ROWS)+1`(vgabios)/ `GET_BDA(video_rows) + 1`(SeaBIOS)。`vgatables.h` 里叫 `BIOSMEM_NB_ROWS` |
| `0087h` | 字节 | **视频控制字节,bit 7 = "上次设置模式时要求不清屏"** —— 【源码】同上。`00h` 的 `AL` bit 7 就是被记在这里(`BIOSMEM_VIDEO_CTL`),而 **`0Fh` 返回的 `AL` 是"模式 \| 这一位"**,所以程序能从 `0Fh` 把那个请求读回来 |

### `0040:0017` 的位

**低四位是"此刻按着"的键,高四位是"锁住"的开关。**

| 位 | 含义 |
|---|---|
| 0 | **右** Shift 按下 |
| 1 | **左** Shift 按下 |
| 2 | Ctrl 按下 |
| 3 | Alt 按下 |
| 4 | Scroll Lock 生效 |
| 5 | Num Lock 生效 |
| 6 | Caps Lock 生效 |
| 7 | Insert 生效 |

> 注意 0/1 的左右顺序:**0 是右 Shift,1 是左 Shift** —— 这一对最容易记反,而记反之后"两个 Shift 是否都算"这种判断会错一半。

### `004Ch` 为什么是 4096 而不是 4000

80 × 25 × 2 = **4000** 字节,而那个字段是 **4096**。差别是它记的是**页的步长**(向上取到 4 KiB 边界),不是内容的长度。40 列模式下 40 × 25 × 2 = 2000,而字段是 2048 —— 也是 2 的幂,不是内容长度。**这条推理加上外部资料是一致的。**

但要注意资料明确指出的:**这个字段在不同硬件上并不一致**(80×50 模式有些机器给 8000、有些给 8256;Hercules 也不一样),所以有资料建议**干脆忽略它**,改用列数乘行数算。以扇区级模拟的立场:**按 4096 写,但要知道它不是一个可以依赖的字段**。

**来源:** [The Art of Assembly (键盘缓冲区与端点)](https://www.cin.ufpe.br/~clac/infra_de_software/Art%20of%20Assembly.pdf)、[DOSEMU 邮件列表(80×25 → 40:4C=0x1000)](https://sourceforge.net/p/dosemu/mailman/message/32298654/)、[Is the current video buffer segment address recorded in memory? — Stack Overflow](https://stackoverflow.com/posts/65414795/revisions)。

写在这里,因为它们**必须有人做决定**,而"没人注意到有分歧"是最坏的结果。

| 位置 | 分歧 | 目前的处置 |
|---|---|---|
| `INT 10h AH=0Eh` 上滚时新行的属性 | **vgabios 取"底行那一格"的属性**(动态);**SeaBIOS 用固定 `0x07`** | **确实是分歧,已查实(2026-10-01)**。中间一度被误记为"两份一致"——错在按参数名 `use_attr` 推断了被调函数的语义,而那个标志在 `vgafb_write_char` 与 `vgafb_clear_chars` 里含义不同。见第一节**注二**。本机跟 vgabios |
| `INT 10h AH=0Eh` 的页 | Ralf Brown 说 `BH`,vgabios 的注释说那份清单错了、应当是活动页 | **用活动页** |
| `INT 16h AH=02h` | 标志字节在 `AL` 还是 `AH` | 用 `AL`(详细资料一致,维基表格是孤例) |
| `0040:004Ch` | 4096 还是 4000 | 用 4096(是页步长,不是内容长度),但记为不可依赖 |
| `INT 13h` 的驱动器不可用 | 任务书坑 7 说 `0Ch`;§4 确认过的码表里**根本没有 `0Ch`**,而 `01h` 的定义是"功能号**或参数**无效" | **定为 `01h`**(2026-10-01)。驱动器号是一个**参数**,而 `0Ch` 讲的是**介质**(类型找不到 / 道不被支持),不是驱动器存在与否。任务书那条 `0Ch` 是**没有出处的** |
| `INT 13h AH=04h` | 硬盘上是否与内存比较 | **定为"不比较"**(2026-10-01,任务 D)。只判驱动器与扇区地址,然后报成功;报告里写明它**没有真的校验**。理由:这台机器没有控制器,介质是宿主内存里的一块数组,"永远报成功"在这里与事实一致,而"可能报假失败"会破坏本来能跑的程序 |
| `INT 13h` 的 `AL = 0` | 是否表示 18 扇区 | **定为拒绝**(2026-10-01,任务 D):`CF=1`、`AH=01h`,不搬任何扇区。§4 给的取值域是 1–128 且明说那个 18 没有出处;另外两条路都**静默**(搬 0 个扇区却报成功,或者按一个编出来的数搬 18 个扇区去踩调用方的缓冲区) |

## 九、这份文件**没有**覆盖的

- **原件。** 一条都没有。全部是二手转述。
- **真机 IBM BIOS 的行为。** 2026-10-01 的源码级查证查的是**两份开源 BIOS**(`qemu/vgabios` 与 `coreboot/seabios`)——它们是 PC 兼容机的实现,**不是 IBM 的固件**。所以"两份一致"不等于"真机如此";而两份不一致的地方(上滚属性、`TAB`、越界矩形),真机的答案**仍然不知道**。见第一节注一到注四。
- **`INT 10h` 的图形模式功能**(`04h`–`06h`、`0Bh`–`0Dh`、`10h` 以后的所有 VGA 功能)。M7 才需要。
- **`INT 14h`/`17h`/`15h`**(串口、打印机、系统服务)。M4 不实现。
- **`INT 21h` 与整个 DOS 服务层。** M5。
- **8259 / 8253 / 8042 的端口编程。** 程序用 `out 21h` 屏蔽 IRQ 是常见做法,而 M4 的 `IN`/`OUT` 是吞掉端口的 —— **这是一处真实的兼容缺口**,记在这里而不是让它消失。
- **键盘扫描码表**(Set 1 与 Set 2 的对照)。这是任务 C 自己要写并且要注明依据的东西,**不在这份文件的范围内**,因为它是一张几百行的表,而且它属于实现而不是接口。
