## 二、第一段:语料

### 入口约定(沿用 M3,不重新发明)

`org 0x100` 的 flat 二进制;`CS:IP = 0:0x100`;`DS`/`ES`/`SS` = 0;`SP = 0xFFFE`;`FLAGS = 0xF002`。

> **一处要写进报告的偏离:** 真 DOS 给程序的是 **IF=1**(中断开着)。这条约定给的是 **IF=0**。
> M4 沿用 M3 的约定,因为改它会连 M3 的语料一起改。**后果是:任何需要中断的程序第一条指令必须是 `sti`。** 这不是小事,写进 `docs/tasks/M4-README.md` 那一节旁边,并且**在语料的每一个需要它的文件顶上注明**。

**结束用 `cli; hlt`**(见 M4-README 的 M4-6)。只写 `hlt` 而 IF=1 的话,运行循环会把它当成"等中断",程序就不会停。

### 每个程序顶上写清楚:它证明什么、期望看到什么

七个程序,一个都不能少——**每一个都在证明一条接口决定**:

| 文件 | 做什么 | 证明的是 |
|---|---|---|
| `hello.asm` | `INT 10h AH=0Eh` 打一行字 | 陷阱 → 服务 → 显存 → 端口这条**主路径**通了。这是**验收程序本身** |
| `direct.asm` | **不用任何 BIOS**,直接往 `0xB8000` 写字符和属性 | M4-8:**显存就是普通内存**。这条和行为 1 是两回事,而且只有它能在将来有人"顺手加上重定向"时报红 |
| `cursor.asm` | `02h` 定位 → `09h` 写 → `03h` 读回来;换页再写一次 | 页、位置、属性三者的一致;以及 `09h` **不动光标** |
| `scroll.asm` | 填满整屏再 `06h` 滚一行 | 窗口矩形和上滚的填入属性;以及 `0Eh` 到屏底时的自动上滚 |
| `timer.asm` | `sti` → 等若干个 `INT 1Ch` → `cli; hlt`,把计数印出来 | **中断投递**、`STI` 的影子、`INT 08h` → `INT 1Ch` 的链。**这是三条 M3 欠账里的一条半** |
| `key.asm` | `INT 16h AH=00h` 阻塞读,把读到的字符回显 | **`vm86_service_retry`**:没有键的时候真的在等,而不是拿着垃圾继续跑 |
| `disk.asm` | `INT 13h AH=02h` 读一个扇区,校验内容,印 OK 或 FAIL | 磁盘路径 + **成功/失败两条分支都走到** |

**`direct.asm` 和 `hello.asm` 的结果必须一样。** 如果不一样,说明有人把显存做成了两份状态——那正是 M4-8 要避免的。

### 宿主套件:`dos/tests/test_bios_programs.c`

汇编的构建规则**已经加在 `dos/Makefile` 里了**(`corpus/bios/*.asm` → `corpus/bios/*.c` → 链接进 `test_bios_programs`)。你只需要把文件放对位置、并且提供一个 `corpus/bios/replay.{c,h}`(或者不用——随便,只要 `test_bios_programs` 编得出来)。

**不要改 `dos/Makefile`。** 如果那套规则不够用,在报告里说,由协调方改。

### `disk.asm` 需要的镜像

## 三、第二段:接进 FunnyOS

现在 `user/vm/vm.c` 做的事是:手动构造两个 guest,跑完,比对终态。M4 之后它要做的是:**装固件 → 装四个服务 → 跑一个 .COM → 把屏幕渲染出来。**

```
vm_selftest() / vm_main()
  1. vm86_mem_attach + vm86_mem_clear         (16 MiB 的 .guestram,不动)
  2. vm86_reset(&cpu, &mem)
  3. vm86_install_firmware(&cpu)              ← 新
  4. vm86_register_service(0x10, bios10_service, &video)
     vm86_register_service(0x1A, bios1a_service, &clock)
     vm86_register_service(0x08, bios1a_irq,     &clock)
     vm86_register_service(0x13, bios13_service, &disk)
     (键盘见下)
  5. 把 .COM 放进 guest 内存 0x100,设好段和 SP
  6. 循环:
        stop = vm86_run(&cpu, SLICE);
        vm86_display_present(&display, bios10_active_page(&cpu, &video),
                             bios10_cursor_cell(&cpu, &video));
        bios1a_advance(&clock, 经过的毫秒) → 该响几下就 vm86_raise(0x08)
        轮询键盘 → bios16_key_arrived() + vm86_raise(0x09)
        if (stop != VM86_STOP_STEPS) break;
  7. 断言
```

**`SLICE` 存在的原因就是第 6 步里那几行**:宿主必须定期拿回控制权,否则用户看不见屏幕刷新、键盘也进不来。**切片多大是个权衡**(小 = 响应好、开销大),选一个并写进报告。

### 显示后端

`vm86_display.present(ctx, cells, cursor)` 里 `cells` 是 4000 字节的字符/属性对。把它写到 FunnyOS 的控制台上。

**注意这不是"打印一行字"**:`cells` 是**一整屏**,每次调用都可能整屏都不一样。你可以每次整屏重画,也可以记下上一次的副本做差分(**如果做差分,要有一个用例证明它和整屏重画的结果一样**——差分的 bug 长得很像"屏幕偶尔不更新")。

光标怎么画由你定;`VM86_DISPLAY_NO_CURSOR` 表示不画。

### 键盘(先查清楚再决定做不做)

FunnyOS 的内核有 PS/2 键盘驱动,M2 的 Shell 用它做行编辑。**但是**:

- **内核把键盘交给了谁?** 如果 `SYS_READ` 之类是"读一整行",那它读不到单个扫描码,也就喂不进 `bios16_key_arrived()`。
- **PS/2 扫描码集**和 BIOS 期望的扫描码**不是同一套**(Set 1 / Set 2 的差别)。

**先去看 `libu` 里有什么、内核给了什么系统调用,然后决定:**

- **有得用** → 接上,并且写清楚中间那次转换在哪里;
- **没有** → **不要为了它去改内核**(那会牵动 `g_current`/`process_run` 那条 M4 之后才动的线)。在报告里写清楚:**缺的是哪个系统调用、它应该长什么样**,然后让 `key.asm` 只在宿主套件里跑。

**M4 的验收标准只要求输出**(见 M4-README 第一节),所以这条路走不通**不影响验收**,但它是 M5 之前必须补上的一块,写进报告。

### 时钟

FunnyOS 有标定过的 LAPIC 定时器(100 Hz)。把它接到 `bios1a_advance(&clock, ms)` 上,让 guest 的 `INT 1Ah` 读到的时间**和墙上时间对得上**。

**这一条要有一个断言**:guest 跑完之后,它数到的滴答数和宿主实际经过的时间(按 18.2 Hz 换算)**在容差之内**。不然"时间服务存在"只是"有个函数被调用过"。

### `make test-vm` 的断言

验收:**`hello.asm` 在 FunnyOS 里跑,屏幕上出现那行字,而且断言看得到。**

`tools/run-vm-test.sh` 现在是断言串口输出的。**整条链要能通到串口**:显示后端把字画到控制台 → 控制台镜像到串口 → 脚本抓到。**先确认这条链存在**;不存在的话,在报告里说清楚,并且**让断言落在能落的地方**(最差也能断言"解释器报出了期望的终态"),**不要**把断言写成"退出码是 0"。

## 四、坑

1. **`cli; hlt` 结束,不是 `hlt`。** 见第二节。
2. **同一份 guest 内存要在两个地方用**:解释器写,显示后端读。`vm86_mem_attach` 挂的是 `g_guest_ram`,显示后端拿到的指针也必须是**同一个**。两份拷贝 = 屏幕永远停在开机状态。
3. **`.guestram` 是 NOLOAD 段**(见 `user/link.ld` 和 `vm.c` 顶部那段注释)。**别把它改成 `.bss`** —— 16 MB 会变成 96 MB 的生成源码,而且是在构建时炸掉。
4. **别让 `vm86_run` 无限跑。** 切片 + 一个**总步数上限**:一个跑飞的 guest(比如 `key.asm` 在没人按键时)必须能被判成"没结束",而不是让测试挂在那里。**上限要用"没结束"这个结果报出来,不是报成异常**——M3 的 `vm_selftest` 里已经有这个形状,照着做。
5. **`INT 10h` 的服务是被 `vm86_host_trap` 调的,不是被你自己调的。** 第二段里你不要再手动调用服务函数;要测服务就调服务,要测**集成**就让 guest 去 `INT`。
6. **`user/vm/vm.c` 现在那份"两个硬编码 guest + 比对终态"的自检,M4 之后还是要能跑。** 它是 `make test-vm` 在 M3 上唯一证明"解释器真的在 FunnyOS 里跑起来了"的东西。**别删掉它**;可以让它退到"BIOS 程序跑不通时的后备",但**先跟协调方说**。
