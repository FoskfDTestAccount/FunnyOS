**你负责:** `dos/bios/bios13.{c,h}`、`dos/tests/test_bios13.c`、`tools/mkfloppy.py`

## 一、你要交的东西

| 文件 | 内容 |
|---|---|
| `dos/bios/bios13.{c,h}` | `INT 13h` 服务 + 一个扁平的块设备 |
| `dos/tests/test_bios13.c` | 你的套件 |
| `tools/mkfloppy.py` | 造一个镜像文件 |

**M4 只做扇区级读写,不做文件系统。** `INT 13h` 不懂 FAT,**不要顺手实现它**——那是 M5,而且它会以"看起来能用"的方式掩盖这一层的问题。

### 块设备的接口

由你在 `bios13.h` 里定义,但必须满足:

- **一块线性字节数组 + 几何参数**,而不是"文件"。宿主可以是 FunnyOS 里的一个内存数组,也可以是测试里的一小块 malloc,也可以是将来映射到文件——**这一层不该知道它背后是什么**。
- 状态结构体**由调用方拥有**。
- 写入要**落到那块数组上**。M4 不做写保护、不做缓存。

## 二、命令码

| AH | 功能 |
|---|---|
| `00h` | 复位磁盘系统。**别真的做什么**——我们没有控制器。但要**报成功** |
| `01h` | 取上次操作的状态,放回 AH。**上次的状态要记住**,包括成功时的 0 |
| `02h` | 读扇区 |
| `03h` | 写扇区 |
| `04h` | 校验扇区 |
| `08h` | 取驱动器参数 |
| `15h` | 取磁盘类型(**可选**,见坑 6) |

`02h`/`03h`/`04h` 的三个参数寄存器:

| 寄存器 | 含义 |
|---|---|
| `AL` | 扇区数(0 表示 18,是真机上的一个历史怪癖——**要不要实现由你决定并写明**) |
| `CH` | 柱面号,**低八位** |
| `CL` | **低六位是扇区号(从 1 开始)**,高两位是柱面号的第九、第十位 |
| `DH` | 磁头号 |
| `DL` | 驱动器号(`00h` 软盘 A,`80h` 第一块硬盘) |
| `ES:BX` | 数据缓冲区 |

## 三、几何

M4 只需要 1.44 MB 软盘这一种:**80 柱面 × 2 磁头 × 18 扇区 × 512 字节 = 1 474 560 字节**。

线性扇区号:

```
lba = ((cylinder * heads) + head) * sectors_per_track + (sector - 1)
```

**注意 `sector - 1`。** 扇区号从 1 开始是这一层最容易忘的一件事,而且忘了之后**第 0 扇区读不到**、第 1 扇区读出来是第 2 扇区的内容——症状是"启动扇区是空的",会让人去查启动扇区而不是查这里。

---

## 四、状态怎么报:**这条最容易做错**

**`INT 13h` 用进位标志报错,不是用 AH。**

- 成功:`CF = 0`,`AH = 0`。
- 失败:`CF = 1`,`AH` = 状态码。

只用 AH 判断的程序是错的;**只设 AH 而不设 CF 的实现也是错的**,而且错得更隐蔽:调用方看到 CF=0 就当成功,拿着一个没被填过的缓冲区继续跑。

状态码至少要有:

| 码 | 含义 | 什么时候给 |
|---|---|---|
| `00h` | 成功 | |
| `01h` | 非法功能号 | 未实现的 AH |
| `02h` | 找不到地址标记 | 一般用不到 |
| `04h` | 扇区没找到 | **越过镜像末尾** |
| `09h` | DMA 跨 64 KiB 边界 | 见坑 4 |
| `0Ch` | 驱动器不可用 | 驱动器号不是 `00h`/`80h` |

**未实现的 AH 要报 `01h` 并且置 CF**,不能悄悄地什么都不做——程序据此判断"这台机器有没有这个功能",静默成功会让它以为有。

## 五、坑

1. **`CL` 的高两位。** 1.44 MB 软盘只有 80 个柱面,所以那两位**永远是 0**——这正是 bug 能藏很多年的原因。**把它们解出来**(而不是把 `CL` 直接当扇区号),并且**用一个柱面号 ≥ 256 的用例**把这条钉住,哪怕我们的镜像只有 80 柱面:那条用例测的是**解码**,不是磁盘。
2. **`AL = 0` 表示 18 扇区。** 只在真软盘驱动上成立。**决定要不要实现它,并写清楚**——不实现的话,一个用 `AL=0` 的程序会读 0 个扇区然后以为成功了。
3. **读写不能越过镜像末尾。** 一组扇区里**任何一个**越界,整次操作失败(`AH=04h`,CF=1),而且**缓冲区的内容不要改**。半成功的读比失败更糟:调用方拿到的是上一次的残留数据。
4. **`ES:BX` 跨 64 KiB 边界。** 真软盘驱动会拒绝(`AH=09h`),因为 DMA 做不到。判断方法是看 `(ES*16 + BX)` 和 `+ 扇区数*512` 是否跨过 64 KiB 边界。**这条容易漏,而且漏了不会立刻出问题**——缓冲区小的时候永远碰不到。
5. **`08h` 返回的是"最大扇区号",不是扇区数。** 真 BIOS 在 `CL` 的**低六位**返回的是每磁道**最大扇区号**(也就是 18),`DH` 是最大磁头号(1),`CH` 是最大柱面号的低八位,`CL` 高两位是它的高位。**这三个"最大"都是"最后一个的下标",不是"个数"**——写"个数"会让一个按返回值算容量的程序正好小一格。
6. **`15h`(取磁盘类型)。** 需要就做,但**它是在 `AH=08h` 之外判断"这是不是软盘"的另一条路**,返回的东西必须和 `08h` 自洽。不做就报 `01h`,别报 `00h`。
7. **驱动器号 `80h`。** 我们没有硬盘。报 `0Ch`(驱动器不可用),**不要**当成软盘处理——一个去读 `C:` 的程序拿到 A: 的内容会做出很奇怪的事。
8. **`04h`(校验)。** 读一遍、比较一下自己还是直接成功,由你决定并写明。选"什么都不做但报成功"的话,在报告里说清楚它**没有真的校验**。
9. **写入要真的改变镜像。** 有一个容易犯的错:读的路径对了,写的路径只改了缓冲区没写数组——而"读回来对"的用例(读 → 写 → 读)**碰不到它**,因为第二次读的还是原来那块。**写路径的用例必须是"写 → 重新挂载/换一个缓冲区读"**。

## 六、`tools/mkfloppy.py`

一个 Python 脚本,**不依赖任何外部库**:

```
mkfloppy.py <输出文件> [--size-bytes N] [--put <偏移> <输入文件>]
```

- 默认造一个 **1 474 560 字节**的全零镜像。
- `--put` 把一个文件放到指定的线性字节偏移(用来塞一段测试数据,或者以后塞一个启动扇区)。
- 越界要**报错退出**(非零返回码),不要截断。

**为什么要有它:** 验收程序要读的扇区得**先有人放进去**。让宿主在测试里手工构造 1474560 个字节的数组,既慢又看不出意图。这个脚本是"镜像长什么样"这件事的**唯一**来源。

## 七、测试要求

至少覆盖:

- **扇区号是从 1 开始的**:写第 1 扇区,确认它落在**偏移 0**,而不是偏移 512。
- **LBA 的两条接缝**:`(C=0,H=0,S=18)` 的下一个扇区是 `(0,1,1)`;`(0,1,18)` 的下一个是 `(1,0,1)`。**这两条要单独写**,它们是唯一能区分"公式写对了"和"碰巧对了"的地方。
- **柱面号的第九、第十位**:用一个 `CH` 高位不为 0 的 `CL` 做解码断言(见坑 1)。
- **越界读**:报 `AH=04h`、CF=1,**而且缓冲区一个字节没动**(先填上已知值再读)。
- **写 → 换缓冲区读**(见坑 9)。
- **`AL=0` 的行为**,就是你决定的那一个。
- **CF 和 AH 每次都成对核对**:成功的用例也要断言 `CF=0` **和** `AH=0`。
- **`01h` 取回上次的状态**:一次失败之后,`01h` 拿到的是那个错误码,不是 0。
- **未实现的 AH**:CF=1、`AH=01h`。
- **`08h` 返回值里"最大扇区号"和"扇区数"的差别**(见坑 5)。

**每条用例都要证明它能失败**:写完把实现故意改错,确认用例报红,再还原。
