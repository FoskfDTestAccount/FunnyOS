**"没查出问题"是一个结论,不是"没做事"。** 下面每一条都写明了验的是什么、

## 二、D 的模块是什么,以及这次审查的范围

扇区级块设备:`struct bios13_disk` 是调用方拥有的一块线性字节数组加几何参数,
服务按 CHS 地址读写它。七个功能号做了六个,**15h 故意不做**。

审查覆盖:七个功能号的正常与失败路径、地址解码的两个编码位、三处接缝、
状态码配对、失败时的不变量、64 KiB 边界、以及"没有磁盘"的机器。
**不覆盖**:经过陷阱的端到端调用(那是 E 的验收语料)、格式化/长读写等未实现的功能号
(它们只报 `01h`,第三节确认了这一点)。

## 三、协调方点名的六项,逐项结果

| 点名的东西 | 怎么验的 | 结果 |
|---|---|---|
| **接缝:第 18 扇区之后跨磁头** | 在 `(0,0,18)` 写 `0x11`、`(0,1,1)` 写 `0x22`,一次读 2 个扇区,断言两个缓冲区各拿到各的;另外断言 `lba(0,0,18)==17`、`lba(0,1,1)==18` | **对**。两个地址落在相邻的 LBA 17/18,一次读跨过去 |
| **接缝:最后一个磁头之后跨柱面** | 同上,`(0,1,18)` 与 `(1,0,1)` → LBA 35/36 | **对** |
| **`CL` 高两位的柱面解码(柱面 ≥ 256)** | 两条:** decode 函数**直接喂 `(0x2C,0x41)→300`、`(0x00,0x81)→256`、`(0x00,0x82)→512`(两个高位分别单独钉住);**走服务**——把盘的几何改成 1024 柱面/1 磁头/1 扇区,在柱面 256、300、512 各写一个扇区,断言落在偏移 256/300/512 × 512 | **对**。而且第二条证明服务**确实用了解码器**,不只是解码器自己对 |
| **`CF` / `AH` 成对** | 关键在**先把两个都置成错的值**:CF 置 1 之后做一次成功调用,断言 CF 变 0(否则"本来就对"的实现也能过);CF 清 0 之后做一次失败调用,断言 CF 变 1。成功路径断言 `CF=0 且 AH=0`,八种失败各断言 `CF=1 且 AH=码` | **对**,每条路径都成对 |
| **失败时缓冲区一个字节不动** | 两种失败(越界与 DMA 跨页)各把 2 KiB 缓冲区填成 `0xEE`,调用后**逐字节**比对;写路径另外断言整块镜像没变 | **对**。八种拒绝理由全部先判完再搬 |
| **`ES:BX` 跨 64 KiB** | `2000:FE00` 加 1 个扇区**正好停在页尾 → 允许**;同处加 2 个 → 拒绝 `09h`;`2000:FF00` 加 1 个 → 拒绝 `09h` | **对**。边界两侧都钉住了,`>` 写成 `>=` 会被抓住 |
| **读→写→换缓冲区读** | 在 `(1,1,5)`(LBA 58)写 `0x77`,**再直接查镜像的那个偏移**,然后读进一个先填了 `0x99` 的**另一个**缓冲区 | **对**。换缓冲区是关键:读回同一个缓冲区的话,"写什么都没做"的实现也会通过 |

**这一条里没有"看起来对"的判断。** 每一项都是失败会报红的断言,而且第七节证明了
它们真的会报红。

## 五、**唯一的发现:`08h` 的 `BL` —— 三处说法互相矛盾**

| 出处 | 说的是什么 |
|---|---|
| `docs/dos-refs.md` 第四节 | `BL` = 驱动器类型,`04h` = 1.44M,并且**明确写着"已实现"** —— 正因为如此它没被列进那一节"本机还没做的两件事"里 |
| `bios13.c` | **从来不写 `BL`** |
| `docs/tasks/M4-D-report.md` 第 5.7 节 | **有意不写**:那张表在这个仓库里没有出处,"编一个数比留原值更坏" |

**实测确认了中间那条**(不是从代码看出来的,是跑出来的):把 `BL` 置成 `0xAB` 再调
`08h`,调用后 `BL` 还是 `0xAB`。用例名就是这条发现,见下。

**这三处里至少有一处是错的,而且这是文档级的错,不是实现级的:**
`dos-refs.md` 第四节现在把 `BL` 描述成已实现——那是给**下一个读它的人**看的,
而照着它写程序的人会读到一个没被写过的字节。

**要裁决的是"该不该写",不是"谁对":** 两种都有道理。

- 写 `04h`:规格有值(1.44M),这台机器的几何就是 1.44M(80×2×18×512 = 1 474 560),
  D 自己也说 `08h` 的 `DL` 就是照"这台机器的事实"写的。同一节里 `DL` 写了、`BL` 没写,
  这条不对称需要一个理由。
- 不写:那张表的**来源等级**确实只有二手,而"留原值"让程序读到它自己放进去的东西,
  "编一个"让它读到一个我们声称是真的常数。

**我的意见(不代替裁决):** `BL` 与 `ES:DI` 不是同一种东西。`ES:DI` 指向一张
**11 字节的表**,而表在 guest 内存里放哪儿是个接口决定(真机在 ROM 里,`IVT[1Eh]` 指向它)
——那是**做不到**,该留着。`BL` 只是一个字节,值是这台机器**自己的事实**,
和同一组出口里 `DL=1` 的来源等级完全一样。所以 `BL` 应该写 `04h`,
而 `dos-refs.md` 第四节"已实现"那句话**要么让它成真,要么改掉**。

**用例已经把它钉住了**:`08h and the drive-type byte` 断言 `BL` 保持调用者的值,
**用例名和注释里写着这三处出处**。裁决之后改哪边都行——改代码那边用例会变红,
那时读注释就知道该改的是用例;而如果没人动,这条不一致至少是**被记下来的**,
不是躺着的。

## 七、变异测试:21 个注入缺陷,21 个被杀;19 个用例全部至少红过一次

方法同本项目既有做法:把 `dos/` 复制到 WSL 的文件系统,**在副本里**逐条注入缺陷,
`make -B test-bios13_audit`,记哪些用例报红,再还原。**产品树一个字节没动。**

**为什么必须做:** 这份审查第一次跑就全绿。全绿要么是好消息,要么是这份审查不会失败
——这两者从输出上看一模一样。变异测试是把它们分开的唯一办法。

注入的缺陷分六类:

- **地址算术**:柱面丢掉高两位;`CL` 的移位量从 6 改成 4;扇区号不减一;
  传输偏移恒为 0。
- **判定**:驱动器不查(改成反向);`AL=0` 放行;扇区掩码少一位;几何不再是上限;
  镜像长度不再是上限;去掉 64 KiB 检查;让校验也吃缓冲区规则。
- **状态报告**:失败不置 `CF`;成功不清 `CF`;`01h` 覆盖它报告的东西;
  `00h` 复位不忘旧错误;未知功能号报成功。
- **写路径**:写不落镜像。
- **`08h`**:扇区最大值减一;**开始写 `BL`**(这条模拟"裁决为写 `04h`")。
- **无盘**:`ctx == NULL` 时照常报成功。

**两条方法论观察,值得留给下一份:**

1. **"被杀了,但没有任何用例具名"要单独报。** 有一条变异(去掉镜像长度检查)
   让套件**段错误**而不是报红——进程死了,stdout 是缓冲的,于是所有 `-- 用例名`
   都丢了。如果脚本只记"套件退非零 = 被杀",这条会看起来像一次干净的击杀。
   脚本现在把这种情况单独列出来。
2. **那条段错误本身是一个发现**(第八节)。

## 八、一个实现观察:镜像长度检查是**内存安全**的承重项

第七节里去掉镜像长度检查之后套件段错误,不是巧合。

`bios13_transfer()` 直接索引 `disk->image[offset + i]`,没有自己的边界判断——
它的正确性**完全依赖** `bios13_check()` 里那一句

```c
if ((uint64_t)request->lba * BIOS13_SECTOR_BYTES + request->bytes > disk->size)
    return BIOS13_STATUS_NOT_FOUND;
```

**那一句不只是"返回 `04h` 而不是读错地方",它是"不读到调用方的数组外面去"。**
现在它是对的(检查保证 `lba*512 + bytes ≤ size`,而传输只走 `bytes` 字节),
而且用了 64 位乘法,所以一个高柱面的多扇区请求不会绕回成"看起来够短"。

**写在这里是因为这层防护看起来像一条普通的参数检查。** 下一个动
`bios13_check()` 的人应该知道:删掉它不是少一个错误码,是让读越出调用方的缓冲区。

## 九、没覆盖到的、以及已知的假定

**这次审查没有覆盖的:**

- **经过陷阱的端到端路径**(guest 真的执行 `INT 13h`)。那是任务 E 的验收语料,
  和 M4-README 协调点一的安排一致。本套件直接调服务函数。
- **`04h` 校验到底该不该比较**:`dos-refs.md` §8 把它列为"由任务 D 决定",D 决定了
  (不比较)。审查确认了实现**与 D 的决定一致**,没有、也不该重新裁一遍。
- **`15h` / `AL=0` / 驱动器码这三个已经裁过的决定**:同上,确认实现与裁定一致。
- **`tools/mkfloppy.py`**:D 的工具,不在这份审查的范围内。

**已知的、代码里没有防护的假定**(都无害,但值得知道):

- **`disk->image == NULL` 而 `size != 0`** → 会在传输时崩。头文件只说了
  "NULL **context** 是没有磁盘的机器",没说 NULL **image**。调用方不会这么传,
  但这是一个没有断言也没有防御的输入。
- **病态几何**:`heads = 0` → 任何磁头都 `04h`(安全);但 `08h` 会 `heads - 1` 下溢成
  `0xFF` 报出去。`cylinders = 0` 同理,`08h` 报 `0xFFFF` 的柱面。这些几何不是这台机器
  会有的,测试盘的几何字段又是公开可写的,所以**一个把几何设成 0 的测试**会得到一个
  怪异的 `08h` 答案。没有崩溃,也没有断言。
- **几何的上限**:`cylinder` 是十位(0–1023),所以 `cylinders = 1025` 时 `08h` 报不出
  正确的最大柱面。CHS 本身就表达不了,不是缺陷。

**D 已经记录、我没有重复的缺口**(`dos-refs.md` §4 里有):`08h` 的 `ES:DI`
不指向软盘参数表、`IVT[1Eh]` 仍指向本机的桩。`ES:DI` 我不当发现——三处说法一致,
而且那是"做不到"不是"忘了"。

## 十、给下一个人的

1. **裁决 `BL`**(第五节)。这是这份审查唯一要别人签字的事。
2. **`bios13_check()` 里那句镜像长度检查不要删**(第八节)。
3. **`08h` 和 `02h` 的编解码必须一直写在同一套排布上**(§4 明说了这个目的),
   第九节的往返用例是钉住这条的。
4. **接缝用例容易写成"同一个位置"。** 校验两处相邻地址的写法看起来像在问
   "这两个地址是不是一个地方"——不是,是"它们是不是**挨着**"。
   D 的报告第十一节也记了同一条,两个人独立踩到,值得写进下一份任务书。
5. **一份全绿的审查要先问"它会不会失败"。** 第七节那 21 个变异就是为了回答这个问题;
   没有它们,这份报告的"没查出问题"和"什么都没查"在输出上无法区分。
