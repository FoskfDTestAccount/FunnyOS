# M5 —— DOS 服务与 `.COM` 加载器

**这一版的位置**：M4 做完的是一台 IBM PC 兼容机的**固件**。M5 做的是它上面那层 **DOS**——PSP、环境块、`INT 21h`、`.COM` 加载器，以及一个 DOS 程序能读写的文件系统。

**验收标准：跑起第一个真实的 DOS 程序。**

这也是全项目的核心里程碑（路线图上标 ★★）。M0–M4 都在为它铺路；到这里，"用 FunnyOS 跑 DOS 程序"第一次成为可以指着看的事实。

---

## 一、起点：现在在哪

写计划之前把现状量了一遍。有几条和先前文档里的说法不一致，或者文档没提，先记在这里——**计划建在盘点之上，盘点错了后面全错**。

下面这张表记的是 **W1 动手之前**的状态，之后不再改动：每个工作包做完时，改动记在它自己那一节的"做完之后"里。这么分是因为两者会不一样，而一张跟着代码走的表会让"当时为什么这么排"变得无从读起。

| | 现状 |
|---|---|
| **进程模型** | **一个全局变量就是当前进程**。`g_current` 在 `kernel/proc/process.c` 里被 **15 处**碰到（DESIGN 说的"五处"是最要命的那五处）。`process_run()` 进入时设它、返回前清它；TSS 的内核栈指针**设一次就不再指回来** |
| **Shell 启动 VM** | **做不到**。M3 就记下的遗留，DESIGN §7.2 点名它是"M4 之后的第一件事" |
| **VM 进程** | 今天是一个**自足的测试夹具**。`user/vm/vm.c` 对内核的全部交往是 `uprintf`（经 `libu` 走 `SYS_WRITE`）；它不读键盘、不开文件，而它的"屏幕"是一个私有结构，**给断言读的，不是画给人看的** |
| **文件系统** | 内核只有一块**只读** ramfs（`kernel/fs/ramfs.c`），目录项是编译进内核的字符串。没有可写路径，没有子目录语义，没有驱动器号 |
| **服务分层** | M4 把固件服务做在**解释器进程内部**（`vm86_register_service`），而不是 DESIGN D4 字面上说的"经由系统调用"。这条分歧 M5 必须先裁定，因为 `INT 21h` 会住在同一层 |
| **键盘** | 内核交出的是**译好的键码**；`INT 09h` 要 set-1 扫描码。M4 记下的缺口 |

### 一条必须先做的架构裁定：`INT 21h` 住在哪一层

D4 说"guest 请求宿主服务时"是唯一跨特权级的地方。M4 实际做的是：**服务住在解释器进程里**，只有真正需要宿主资源时才回内核。

这两句不矛盾，但边界要写清楚，否则 `INT 21h` 会变成一个在两处各写一半的东西。裁定如下：

> **服务住在 VM 进程里；只有需要真实资源时才走系统调用。**

理由是这个划分本身有内容：`INT 21h AH=09h`（打印一个字符串）**不需要内核**——它写的是 guest 显存，而 guest 显存就在 VM 进程自己的地址空间里。而文件功能需要镜像资源，挂载时通过宿主接口取得；W5 最终把 FAT 解析留在 VM（见 W5 做完之后）。按这条线分，落到内核的那部分是**小而稳定**的（打开/读/写/关闭/查找，加上几个控制台原语），留在 VM 进程里的是**大而会长的**（几百个功能码的分发）。

反过来的划分（每个功能码都过一次系统调用）会让每一次 `AH=09h` 都付一次特权级切换——而 DOS 程序打印东西是高频操作，不是 D4 说的低频服务调用。D4 的"服务调用是低频的"这句对 BIOS 成立，对 `INT 21h` 不成立，这是这一版要更正的一条。

## 二、工作包

顺序不是按"哪块先做完"排的，是按**谁挡着谁**排的。

### W1 进程模型：可重入 + 启动子进程 ★先做

**为什么是它**：DESIGN §7.2 点名它是"M4 之后的第一件事"，而且它是**唯一一件越晚做越贵的事**——M5 后面每一块（`.COM` 加载器、`INT 21h`、文件）都会写在一个"当前进程是全局变量"的模型上，等到发现要改，改的就是全部。

**要做的**：

- `g_current` 从"进入时设、返回前清"改成**保存/恢复一对**。清成 `NULL` 是错的：子进程跑完时，外层的父进程仍然存在，而这行代码宣布它不存在。
- **TSS 内核栈指针**同样保存/恢复。
- 新增 `SYS_SPAWN`：父进程给出镜像与参数，内核建子进程、跑它、把**退出码**交回父进程。**先做阻塞式**——DOS 的 `INT 21h AH=4Bh`（EXEC）就是阻塞的，子程序结束才返回调用者，所以阻塞式既是最简单的也是语义正确的那一个。
- 子进程的地址空间、堆、文件表的生命周期（`process_destroy` 的时机）。

**验收怎么判**——三条断言，**第一条专门钉设计点名的那一个失败形状**：

1. 子进程运行**期间**来一个定时器中断，它必须落在**子进程**的内核栈上；子进程结束之后再来一个，必须落在**父进程**的栈上。这条挡的正是"M4 之后的第一件事"那句话里的后果：*外层进程的下一次中断落在已死的子进程栈上*。没有这一条，"可重入"就只是一句声明。
2. 退出码正确回到父进程（包括退出码为 0，因为 0 和"还没开始"必须分得开——`process_run` 里那段关于 `setjmp` 的注释就是这个教训）。
3. 子进程崩溃（写一块没映射的地址）只杀死子进程，父进程继续跑，并拿到一个表示崩溃的码。

**挡住**：所有下游。

#### W1 做完之后

已实现并验证。三处细节与计划不同，记在这里：

- **要保存的不是一样东西，是四样。** 计划里只写了 `g_current` 和 TSS 栈指针。实际动手时发现另外两样同样会被覆盖：**当前 PML4**（子进程退出时内核切回了内核页表，父进程恢复运行就会落在错误的地址空间上）和**向量寄存器**（进入子进程时 `fpu_restore` 会把父进程正在用的 XMM/x87 抹掉）。`process_run` 里那段"两个进程时，它们是两个程序各自保住自己算术与共享一套寄存器之间的差别"的注释，说的就是后一条。
- **`SYS_SPAWN` 收一个名字，不收"再开一个我"。** 内核只有一份内嵌镜像（`kernel/proc/image.c` 里一行），但接口是 `(const char *image, arg)`，因为**被查找的形状**才是以后贵的那部分；FAT 卷上的 `.COM` 接在同一个入口，调用方一行都不用改。
- **进程名从"借用指针"改成"自己拥有"。** `process_create` 原来把调用方给的指针存下来，而今天所有调用方传的都是字符串字面量，所以它一直是对的——直到我加的这个调用方传了栈上的缓冲区。

**验收怎么判，最后长成了什么**：内核在每次从 Ring 3 进来的定时器中断上检查那个帧落在哪个栈上，退出时报告三种结果（全对／有落错／**一个都没观测到**）。第三种单独成一种，因为"没有中断"会满足"没有落错"却什么都没检查。注入验证：拿掉 `tss_set_kernel_stack(previous_stack)` 那行，报 `FAIL (6 of 17 Ring 3 ticks landed off the running program's kernel stack)`。

**顺带查出来的**：FPU 自检并不像 `run-user-test.sh` 注释说的那样守护 `-mgeneral-regs-only` —— 它的循环每轮都问时钟，中断全落在系统调用里。33 次滴答，Ring 3 里 0 次。注释已按实情改写。

### W2 VM 进程与内核的通路

**为什么**：验收标准是"程序跑起来**并且看得见**"。今天那个 VM 进程画给谁看都不画。

**要做的**：

- **显示**：guest 文本显存 → FunnyOS 屏幕。这里有一个要做的决定：**VM 是独占屏幕**（像 DOS），还是借用一块再还回来。倾向后者——内核的 panic 输出必须随时能抢回屏幕，而"DOS 程序卡住时用户按不出任何东西"是 DOS 的毛病，不是要继承的。
- **键盘**：`SYS_GETKEY` 是阻塞的；`INT 16h AH=01h` 要的是"有键吗"，需要一条**非阻塞**的形式。
  **这条移到 W6 了**，理由记在下面：它加得出来，但今天没有东西能验证它。
- **时间**：`SYS_UPTIME_MS` 已有，够 `INT 1Ah` 用，不用加。

**验收怎么判**：一个 `.COM` 通过 `INT 10h` 打出的字出现在 FunnyOS 屏幕上——而且这次是 **VM 进程自己做的**，不是测试夹具里的断言。

**挡住**：验收标准本身。

#### W2 做完之后

显示那一半做完了，**键盘那一半没做，而且是故意没做**。三处与计划不同：

- **不是"借一块区域"，是"借整块屏幕"。** 计划里写的是"VM 是独占屏幕，还是借用一块再还回来；倾向后者"。落地的形状是后者的一个版本：**屏幕只有一个持有者，进程要么持有它、要么没有**，内核的日志在没人持有时画、被持有时不画但继续往自己的网格里写。所以 panic 随时能抢回屏幕（`panic()` 第一件事就是抢），而"DOS 程序卡住时用户按不出任何东西"这条毛病没有继承——程序死了，持有就结束。

  没有做成"区域内嵌一块"是因为**内嵌的那块会被日志滚过去**：控制台的日志是一整块会滚动的网格，留一个洞不让它滚，等于在这个文件里同时维护两种网格。整块借出把这个问题变成了"谁来画"而不是"画在哪"。

- **`screen_present` 直接从调用者的内存画，没有拷贝。** 传的是 guest 页在 guest 内存里的那个指针，一字节都没重排。这让"屏幕是 guest 内存的相片"变成两行代码的性质而不是一个要断言的东西。**但它是有前提的**：页还在调用者的内存里、调用者还活着。这个前提在"页可以被切走再切回来"的那天就不成立了——见 [M4-G](M4-G-mouse-tabs.md) 的 G3，那里明说了这一条会在什么时候失效、以及届时哪一句话要改。

- **验收长出了一个新的工具，而且是这一版唯一能看见屏幕的东西。** 串口日志能说的每一句话——guest 的页对、内核收到了、内核说它画在哪——**都和一个从没被写过的 framebuffer 相容**。所以 `tools/run-screen-test.sh` 走了一条别的测试走不了的路：让程序把页留在屏幕上等一个按键（`vm=screen`），用 QEMU monitor 截屏，然后由 `tools/check-screen-pixels.py` **逐扫描线**比对。

  那个检查器刻意**不假设调色板**：背景色取自一个已知是空白的格子、前景色取块里另一种颜色，两个颜色都是从**屏幕上读出来的**。代价是**调色板本身不被检查**（这一点写在脚本的文件头里）。它做的是：让程序持有屏幕、把页留在上面等按键、截屏，然后检查每一格是不是字体里那个字的形状、位置对不对、区块外有没有被动过、光标画在不在 guest 的光标格上。

**验收是怎么验的——注入，五个不同的错法，五种不同的诊断**：

| 注入的错法 | 检查器说的 |
|---|---|
| 每个字右移一格 | `400 scan line(s) outside the guest's page are not the console's background colour` |
| 丢掉属性字节、用控制台自己的颜色 | `the page is drawn in the console's own background colour -- the attribute byte was not used` |
| 什么都没画 | 当时是 `the whole page is one colour -- nothing was drawn on it`；W3 重写取色之后这句话变成了 `row N ... is one colour -- nothing was drawn there`。**两句话都对，但记在这里的那一句会和树里的对不上**，所以照 W3 那一节看现在的措辞 |
| 页根本没交给内核 | 断言先红：`NOTHING WAS PRESENTED` / `the kernel said where the page went` |
| **每个字左移一个像素**（留在格子里） | `cell 0,0 scan line 3 is not the font's glyph for 'M'` |

最后一条是关键：前三种都被别的检查先拦住了（移出矩形、把空格画出了墨），**只有形状比对**能看见"位置对、栅格对、但形状不对"。所以这一条单独注入过一次，否则"逐扫描线比对"这句话是没有证据的。

**键盘那一半为什么不在这里做**：计划把它记在 W2 名下（`SYS_GETKEY` 阻塞，`INT 16h AH=01h` 要非阻塞）。加一条非阻塞的读键系统调用是十行，但**它今天无法被验证**——guest 根本没有键盘来源（`run_corpus` 顶上那段注释记着这件事，W6 才是解它的地方）。一条加了却没有任何调用方、也测不了的接口，正是"套件绿在一个从没被测过的实现上"的另一种写法。**这一条移到 W6**：那里有真实的扫描码要过，非阻塞查询和它一起才验得了。

**挡住**：验收标准本身（显示这一半已经通了）。

### W3 `.COM` 加载器 + PSP + 环境块

**要做的**：256 字节 PSP（`INT 20h` 在 `0x00`、内存顶端在 `0x02`、`INT 22h/23h/24h` 三个向量、父 PSP、JFT、环境段、命令行尾在 `0x80`、两个默认 FCB 在 `0x5C`/`0x6C`）；环境块（`NAME=VALUE\0` 序列 + 结尾多一个 `\0` + 一个字计数 + 程序全路径）；进入时的寄存器约定（CS=DS=ES=SS=段，IP=`0x100`，SP=`0xFFFE`，栈顶压一个 0 字让 `ret` 落到 `INT 20h`）。

**验收怎么判**：一个手写的 `.COM` **读自己的 PSP** 并把字段打出来。关键在于**期望值从规范抄，不从加载器抄**——项目已经有这条规矩（"审查的期望值必须独立写出来"），而这里它是唯一能防住"加载器和测试共享同一个误解"的东西。

**挡住**：任何真实程序。

#### W3 做完之后

第一件产物不是代码，是**依据**。

计划里写「期望值从规范抄，不从加载器抄」，而**树里当时没有 DOS 层的规范可抄**：`docs/dos-refs.md` 第九节明明白白把「`INT 21h` 与整个 DOS 服务层」记成 M5 未覆盖。那份文件存在的理由就是「一个没有依据的服务号只能靠记忆写，而记忆错的地方每个人会一致地错」——PSP 的字段偏移正是这种事实里最典型的一种：装载器写到 `002Ch`，测试也去 `002Ch` 读，两边一起错，套件全绿。

所以先有了 [`dos-refs-dos.md`](../dos-refs-dos.md)：PSP 的完整偏移表、`.COM` 的进入约定、环境块的布局、命令行尾、两个默认 FCB，**每条都带来源**，来源互相矛盾或干脆没说的地方单列一节，本机的取值再单列一节。

四处计划里没写、动手时才定下来的：

- **`PSP:05h` 那五个字节写零，而不是填成 DOS 的样子。** 查到了它的构造规则（`9A F0 FE 1D F0` 是一个靠 1 MiB 回绕到达 `INT 30h` 的 CP/M 入口，`FEF0` 那个字**同时**是「程序段大小」），而本机没有 `INT 30h` 的处理程序——**填出来的字节会看起来完全正确却跳向虚空**。写零并写明理由，比写一串读起来像真的、效果是死路的字节好。这是「不实现也可以是正确的决定，但用一个假的理由去支持它不行」的那条规矩。
- **两个进入约定要并存，而且不是不一致。** `corpus/bios` 冻住的约定是 **IF 清零**（它自己的注释就说了真实 DOS 是置位的，那个偏离是为了 M5 加 PSP 时不移动 M3 的样本），而 DOS 装载器出来的程序 **IF 置位**。两条路各管各的样本，这个区别写进了依据文件和两边的代码。
- **内存顶端那一格把「640 KiB」这个常数从 `firmware.c` 提到了 `firmware.h`。** 一个 `.COM` 在 DOS 下拿到**到常规内存顶端为止**的全部空间，所以 `PSP:02h` 是一个和机器大小有关的数，而 `INT 12h` 与 `0040:0013h` 报的是同一个数。**一台自称 640 KiB 却把程序的内存说成到 1 MiB 为止的机器，是在两个程序会读的地方自相矛盾**——原来那个常数是 `firmware.c` 私有的，两份事实迟早会分开。
- **拒绝要报出是哪一个拒绝。** 计划里的装载器没有签名。落地的是一个枚举而不是 `bool`：「没启动起来」不是一个能据以行动的东西，而**一个只返回 false 的装载器会让套件断言「有东西被拒了」——那正是错的被拒时照样绿的写法**。五种拒绝各有各的测试，包括「拒绝时一个字节都没写」。

**套件在装载器的第一版里找出了一个真 bug**：没有参数时两个默认 FCB 的名字位被我写成了零，而 **DOS 留的是空格**。这正是依据文件第五节单独拎出来说的那条「看起来同样合理但不是 DOS 的行为」——写下来有用，是因为它是被套件而不是被眼睛抓住的。

**验证**：`dos/tests/test_dos.c` 14 个用例、212 条断言，**每一条期望值都从依据文件抄，`struct vm86_dos_psp` 一次都没被读过**。五个注入全部被抓住，诊断各不相同：

| 注入 | 检查器说的 |
|---|---|
| FCB 名字写成零而不是空格 | `FCB1 name: at 0x1005D expected 0x20, got 0x00` |
| 装载器替调用者补了一个前导空格 | `the tail length: at 0x10080 expected 0x08, got 0x09` |
| 进入时 IF 没置位 | `IF: IF should be set and is clear` |
| 栈上没压那个零字 | `the word a RET returns through: at 0x1FFFE expected 0x0000, got 0x1234` |
| JFT 指针写成线性地址而不是远指针 | `PSP:0036 JFT segment: at 0x10036 expected 0x1000, got 0x0001` |

**而且它在它将被使用的地方也跑起来了。** `vm=psp` 让 VM 进程用这个装载器装起 `psp.asm`，把屏幕留在上面，由 `run-screen-test.sh` 截屏判定——第一个**以 DOS 的方式装载**的程序出现在 FunnyOS 的屏幕上，22 行 PSP 字段逐格比对。

为此像素检查器从「第 0 行」推广到了「若干行」。**推广之后第一次注入就发现它的诊断会指错方向**：一个「只画第一行」的注入被报成「用了控制台自己的颜色」——因为背景色取自区块的**最后一行**，而那一行在注入下根本没被画过。两个不同的错法产生同一个测量、同一句消息，而消息说的是没发生的那个。改成从**报告说有文字的第一行**取色、并把「用了控制台的颜色」这条挪到字形比对**之后**，同一个注入现在报 `cell 1,0 scan line 0 is not the font's glyph for ' '`——直接指向绘制。

这条值得单独记：**注入的价值不只是证明断言会红，还包括证明它红的时候说的话是对的。** 一个会红但说错话的断言，比不红更费时间。

**挡住**：任何真实程序（现在它真的挡住了，而不是计划上挡住）。

### W4 `INT 21h` 核心

先做能跑通验收的最小集，再按真实程序的实际需求扩。建议的第一批：`30h`（版本）、`09h`/`02h`（输出）、`4Ch`/`00h`（终止）、`25h`/`35h`（取/设向量）、`1Ah`（DTA）、`4Eh`/`4Fh`（查找）、`3Dh`–`42h`（打开/关闭/读/写/定位）。

**验收怎么判**：每条功能码一个 `.COM`，外加**变异测试**（工具已在树里，186 个变异体，这一层要补上自己的）。

**做完之后（W4，2026-10-01 收尾）**：

- 十二个核心功能码和 INT20h 已落地；`int21.asm` 在宿主逐字节比对、
  QEMU 真机像素比对，带返回码 7 走通 `VM86_EXIT -> VM86_STOP_EXIT`。
  文件与输入调用没有提前写假后端，分别留给 W5/W6。
- 服务在 VM，输出共用 `bios10_tty()`；成功清 CF 是本机策略，
  未实现功能 AL=0/CF=1、AH 保持；具体来源/偏离在 DOS 依据文件。
- **构建系统修复属于验收结果的一部分**：内核/用户对象启用头文件依赖，
  默认目标固定为 all，宿主 suite 依赖头文件。此前新旧 CPU 布局混用使
  Ring 3 静默丢掉服务 flags，而宿主仍绿；flags 写回/拒绝计数器把此类
  故障显式化。注入工具现在用独立临时目录，避免并发共享工作树。
- 交接时缺少的第 17 条 flags 注入已完成：基线 17/17 命中正确诊断；
  W5/W6 后的树再次回归（结果见 W4–W6 完成记录）。未擅自提交/推送。

### W5 文件：FAT 镜像挂载

DESIGN D8 选了 **FAT 镜像优先**，理由是它把"磁盘"的复杂性封在一个文件里，且与真机行为最接近。

**这里有一个必须先定的架构问题，而 DESIGN 没有回答**：VM 是 Ring 3，碰不到磁盘。两条路：

- **(a)** 内核提供文件系统层，VM 通过系统调用读写（`SYS_OPEN`/`SYS_READ`/… 已经有了，但 ramfs 是只读的）；
- **(b)** 镜像整个作为内存交给 VM 进程，FAT 解析在 VM 进程里做。

倾向 **(a)**：FAT 解析放内核会让内核长出一块与 DOS 无关的东西，放 VM 进程则意味着每读一个扇区都要把整块镜像映射过去。而 (a) 还留着一个好处——**宿主路径映射**（D8 的另一条路）以后接在同一个接口上。

**验收怎么判**：一个 `.COM` 打开镜像里的一个文件、读它、把内容打出来。

**做完之后（W5）**：

- 架构最终选 **(b)**，推翻动工前倾向而非悄悄改计划：镜像只在挂载时
  用现有 SYS_OPEN/READ 从内核 ramfs 拿字节；**不是每个扇区映射整块镜像**。
  FAT12/FAT16 解析是 VM 内的纯字节数组后端，同份代码跑宿主 suite。
- 可挂载 BPB superfloppy；8.3 根目录/现有子目录、16 个独立句柄，
  `3Ch..42h`、`4Eh/4Fh` 接通。写会更新所有 FAT 副本，零字节写可改长度，
  EOF/负定位/访问模式/只读/满盘/坏链/guest 越界有明确返回。
- 原“不写 FAT”收窄为“不做持久化”：**会话私有镜像可写**，新运行重新
  挂载。否则计划里的 /40h 只能在一个假后端上验；不加块设备驱动、不刷宿主文件。
- `FILES.COM` 从镜像加载后打开 HELLO.TXT、读并输出、定位、关闭、创建、
  写入、读回、查找 DTA、FindNext 耗尽和删除，再以零退出码结束。
  Shell 新命令 `DOS <8.3.COM> [args]` 不再只跑内嵌语料。
- 独立镜像检查使用 mtools；手写 BPB fixture 不调用生成器；同一 FILES.COM
  经 DOSBox 输出/副作用对照。公开 DTA 43 字节不复用宿主结构体布局，
  搜索 continuation 属于 DTA，允许交错两个搜索。

### W6 键盘来源

内核交出译好的键码，`INT 09h` 要 set-1 扫描码。两个选择：内核**多给一个原始扫描码**的接口（干净，但要改内核的键盘驱动），或 VM 侧做一张**反查表**（不用改内核，但键码到扫描码不是双射，会丢信息）。倾向前者。

**从 W2 挪过来的**：`SYS_GETKEY` 是阻塞的，而 `INT 16h AH=01h`（"有键吗"）要一条非阻塞的形式。加它是十行，但**它今天没有调用方、也测不了**——guest 在 W6 之前根本没有键盘来源，于是"非阻塞读键能用"这句话会绿在一个从没被跑过的路径上。挪到这里，和真实的扫描码一起验。

**验收怎么判**：一个 `.COM` 通过 `INT 16h` 读到一次按键，并且**那次按键的扫描码和字符都对**——只对字符会漏掉整类 bug（方向键、功能键没有字符）。测试经 QEMU monitor 在键盘上按键（`run-input-test.sh` 已经在这么做），而且按下去的键要**挑一个扫描码和字符都不相同的**，否则两个字段错了也看不出来。

---

**做完之后（W6）**：

- 选择内核原始扫描码接口，明确启用 8042 set-1 translation；独占流
  `SYS_KBD_ACQUIRE/POLL/RELEASE` 交出包括前缀与按下/释放的每个字节。
  流空非阻塞返回，满队列明确报溢出；进程销毁也释放资源。
- VM 在 slice 之间送 BIOS latch，再 raise INT09，不反查字符，也不向
  Shell 队列重复投递。`SYS_POLLKEY` 在验收页交回控制台后有实际调用方。
- DOS /01h、/06h、/07h、/08h、/0Ah、/0Bh 已实现，含扩展键两字节、
  回显/不回显、状态查询、退格、CR/容量和 Ctrl-C 的 guest INT23 路径。
- **公共陷阱层的嵌套帧问题被真实键盘路径揭出**：一个 last-SP 不能描述
  外层阻塞服务与内层 IRQ。INT/IRET 现在维护 SS:SP 帧身份栈；重试
  保留原帧，不重做 INT。单独测试等待时一帧、返回后无泄漏、flags 无拒绝。
- `KEYS.COM` 同一字节在宿主/QEMU 两个固件路径验证 1E61h、3042h、
  4800h、3B00h，外加 DOS 行编辑。截图看 framebuffer，释放键看非阻塞
  译码接口，Shell 回归看控制台键盘重新可用，不仅是“guest 打了 PASS”。

## 三、验证：没有交叉审查之后拿什么替代

**这一节是这一版最该读的一节。**

M4 的结论不是靠 21 个套件得出的，是靠**每个模块由一个没写它的人审**——那十七条发现里有四条是作者自己的套件完全看不见的。而这一轮没有第二个人。承认这一点之后，替代品按强度排：

1. **可执行的外部权威——DOSBox 对照。** 把同一个 `.COM` 在 DOSBox 里跑一遍，比较可观测行为（屏幕、退出码、文件副作用）。这把"我认为对"换成"两个独立实现一致"，而且**它不依赖我的判断、也不依赖我对规范的记忆**。这是这一轮最该新建的基础设施。
   - 要克制：比较的东西选**可观测且稳定**的（文本屏幕、退出码、文件内容），不要比时序、不要比内存里的中间状态。
   - 它有自己的盲区：DOSBox 也不对的地方，两边会一起错。
2. **变异测试。** 工具已经在树里，机械，不关心谁写的代码。给 `INT 21h` 每条功能码补变异体。
3. **期望值从规范抄，不从实现抄。** PSP 字段偏移、`INT 21h` 的返回约定，都从文档抄进测试，不是从我的常量抄。
4. **先写期望、后写代码。** 每一片功能码，先把 `.COM` 和它该打印什么（从规范）写下来，再写实现。它不能替代独立审查，但它把"实现和测试一起错"的概率降下来。

**一个诚实的减法**：上面四条加起来**仍然不是**交叉审查。交叉审查的价值在于审查者**没有和作者共享同一个误解**；而这四条——包括 DOSBox 对照——共享的正是**我选的测试用例**。我挑的用例覆盖不到的地方，就是这一版的盲区。这一节的长度会体现在 M5 的"没有证明什么"里。

## 四、风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| **兼容性长尾** | 高 | 这是 DESIGN §8 登记的头号风险。缓解就是 M5 本身：**尽早引入真实程序**，别等做完再试 |
| **`INT 21h` 范围蔓延** | 高 | 先做最小集跑通验收，之后每一条功能码都由**某个真实程序真的用到**来驱动，不按清单堆 |
| **没有独立审查** | 中高 | 见第三节。DOSBox 对照是主要补偿，但它不覆盖"我没想到要测的" |
| **W1 做错方向** | 中 | W1 的验收第一条就是钉那个失败形状的；如果那条断言没法让它红，说明没测到东西 |
