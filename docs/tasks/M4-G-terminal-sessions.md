# M4-G 后续 —— 用户可创建的多标签终端会话

> **实现更新：** 第一版已经接入普通启动路径：用户新建/关闭、独立 FunnyCOM、
> 会话输入/输出、协作式挂起/恢复、DOS 衔接。下面保留原目标与工作分解，
> 其中“当前尚未实现”描述的是计划制定时的状态，不是现有开发树。
> 实际验收与限制以 [`M4-G-terminal-completion.md`](M4-G-terminal-completion.md) 为准；
> 第一版仍不是通用抢占式后台多任务。

## 0. 用户目标与本轮状态（2026-10-01）

用户已反馈鼠标可以正常使用，并明确下一步方向：**先做用户能自行创建标签页的终端，
让多个命令行会话共存，而不是急着做窗口式 GUI。** 用户提供的终端截图用于表达
“标签、新建入口与独立命令行页面”的交互目标，不要求复制外观或引入图形桌面。

这份文件是**后续实现与验收计划，不是功能完成报告**。当前开发树有 PS/2 鼠标、
指针覆盖、内核页面快照与标签切换，但还没有用户创建/关闭终端或多个独立 Shell。
[`M4-G-preview.md`](M4-G-preview.md) 描述的 Log/Program/父子页仍是底层验收夹具。
G1–G4 的通过不能被当成“多标签终端已经完成”。

## 1. 三种对象必须区分

| 对象 | 责任 | 生命周期 |
|---|---|---|
| 显示页（screen page） | 字符/属性快照、光标、重绘与指针覆盖 | 是终端或程序的显示资源，不等于 Shell |
| 终端会话（terminal session） | 文本输出、当前输入行、输入队列、焦点、Shell 与前台程序关系 | 用户新建；退出/关闭时回收 |
| 进程（process） | 私有地址空间、内核栈、执行上下文、文件资源与故障隔离 | 由会话启动与关联，可阻塞或恢复 |

**标签对应会话，不应永久绑定一个正在显示的程序。** 同一会话先显示 Shell，
运行 DOS 程序时显示其文本页，程序退出后恢复该会话的 Shell；不能每启动一次
程序就把它当成用户新建的终端。内核日志是独立诊断输出，不冒充用户会话。

## 2. 第一版对用户的承诺

- 普通启动进入 `Terminal 1` 的 FunnyCOM，不依赖 `selftest=desktop`。
- 标签栏提供 `[+]`；点击它或使用 `Ctrl+Shift+T` 创建一个新的 Shell 会话。
- 点击标签或按 `Alt+1..9` 切换；编号指用户终端的可见顺序，内核日志不挤占编号。
- 提供关闭入口、`Ctrl+Shift+W` 与会话内 `EXIT`。未运行程序的会话可直接关闭；
  有前台程序时先给出确认/明确拒绝，不能悄悄丢掉工作，也不能仅删除标签而留下进程。
- 每个会话至少有自己的文本内容、光标、未提交输入行与退格位置。
  `CLS`、命令回显与 Shell 输出只影响所属会话。
- 第一版明确一个可测试的会话上限；上限处失败必须给出反馈，并完全回滚资源。
  关闭一个会话后应能再次新建；槽位复用不能带出旧内容或旧输入。
- 关闭当前页后选择一个仍存在的相邻会话。关闭最后一个会话时创建新的空会话；
  若内存不足，保留可见诊断与可恢复入口，不能黑屏或进入无反馈状态。
- 从输入/输出层保证会话隔离，不仅仅把多套屏幕画出来。

这些快捷键与生命周期是**拟实施的接口**，当前 ISO 尚不支持。

### 第一版范围与非目标

这是文本终端，即使字符最终由 framebuffer 画成像素，也不意味着在做图形桌面。
这一轮不做可拖动窗口、桌面图标、任务栏、控件库、窗口合成器或 USB HID 驱动。

**多个会话可恢复运行是本轮必需，所有后台程序并行推进不是可默认声称的结果。**
第一阶段至少支持一个 Shell 等待输入时切到另一个 Shell 输入并执行命令。
对于正在执行 DOS 程序/长命令时的切换，在上下文机制完成前必须明确限制，
不能因为能切换画面就声称另一个 Shell 已经可以运行。
持续后台计算、任意 CPU 密集程序的抢占和终止作为单独验收目标；没有验证就不声称支持。

## 3. 已核实的实现缺口

以下来自当前代码路径，不是外部产品的假设：

1. `kernel/proc/syscall.c` 的 `SYS_WRITE` 通过 `kputc()` 写公共控制台，
   `SYS_READ(stdin)` 调用公共 `console_read_line()`。
2. `kernel/console/console.c` 的行编辑只有一次阻塞调用内的局部状态；
   `kernel/console/kbd.c` 的翻译后按键队列是全局的，原始扫描码也只有一个 owner。
3. `user/funnycom/main.c` 只有一个 Shell 循环、一份 `line`/`argv`，
   正常模式没有独立终端会话对象。
4. `kernel/proc/process.c` 的 `process_run()` 已能保存/恢复嵌套父子调用上下文，
   但退出是 unwind/longjmp；它没有任意选择一个已挂起 Shell 并继续执行的能力。
   `SYS_SPAWN` 等到子程序结束才返回，不能拿它循环新建多个可交替工作的终端。
5. `kernel/console/screen.c` 目前按 owner 管理固定 25 行的程序页，
   标签宽度是固定 20 列；这不等于按屏幕可用空间布局的终端标签栏。

因此实现不能只是加 `TAB NEW` 命令，复制共享命令行缓冲，或再调用一次阻塞 spawn。

## 4. 实施顺序与完成门槛

### T1：终端会话对象与按会话路由的输入/输出

**先做本项。** 保留 screen 的 RAM 权威快照、指针重绘与 Log 诊断能力，
新增会话身份，分离 active/visible terminal 与当前运行进程。

- 用户态进程关联终端身份；`stdout/stderr/stdin/clear` 路由到所属会话。
- 内核 `kprintf()` 与串口日志保留独立诊断路径，不能写进当前活跃终端冒充用户输出。
- 行编辑状态、按键队列、光标与字符缓冲按会话隔离。
  原始按键仍由焦点会话的前台持有者接收，切页快捷键不能注入 guest。
- Shell 页使用屏幕可用字符区域，25 行 guest 页保持自己的布局约定；
  标签栏占用的行数与坐标换算只有一个权威来源，不写死 1024×768。
- 初期只承诺有限屏幕行缓冲与滚动，不提前声称无限 scrollback 或历史命令编辑。

**验收：** 对 A/B 写不同内容，切换后保留；对 B 清屏不动 A；
A 的半行输入与光标经过 B 的输入、回显、退格后仍正确；内核日志不污染 A/B。

### T2：可挂起/恢复的执行与等待机制

T1 后再接本项，**没有它就不能验收多个独立 Shell**。

- 建立可恢复的进程上下文与状态（运行、可运行、等待输入、等待子程序、退出）。
- 等待 stdin 的 Shell 挂起而不是占住唯一的全局读行调用；
  焦点变化能使另一个会话的 Shell 获得输入与执行机会。
- 切换必须完整维护当前进程、PML4、TSS `rsp0`、通用寄存器和 x87/SSE 状态。
  拥有阻塞 syscall 的进程还需保留/恢复内核栈，不能只存用户态 RIP/RSP。
- 保持已有阻塞父子语义；等孩子的父 Shell、当前可运行 Shell 与显示焦点是不同状态。
- 输入 ISR 只记录事件；不在键盘/鼠标 ISR 内分配进程、释放当前内核栈或直接 longjmp。
- 最小调度先以等待/让出等安全点实现并验证；如果要承诺任意长命令的即时切换或
  CPU 密集后台运行，再独立完成 timer 抢占与 syscall 重入验证，不能用轮询假装已支持。

**验收：** A 阻塞读行时，B 真正执行 `ECHO`/`DIR`；再切回 A 续写同一行。
多次切换后检查 Ring 3 中断栈归属、地址空间、FPU 与资源；不能仅比对页面快照。

### T3：用户新建/关闭标签和 Shell 生命周期

T1/T2 的不变量成立后再做用户入口。

- 普通启动路径创建首个终端并启动 FunnyCOM；`[+]`/快捷键创建其他会话。
- 标签标题、激活高亮、关闭按钮及命中区域共用布局计算；
  小分辨率/较多标签时保证可选中，不能画出了第 8 页却没有可点击入口。
- 关闭按 session → 所属进程/前台程序 → 输入 → 页/内存的明确顺序回收。
  从被关闭进程自己的栈转走后再释放资源，不能直接删掉正在执行的栈。
- 新建失败处理与最后一页策略必须可验证；`EXIT` 只结束所在会话，
  不是原来的“唯一 Shell 结束，内核从此 idle”。

**验收：** 正常启动中新建三个终端，鼠标/键盘切换、关闭当前/非当前页、
`EXIT`、最后一页、新建上限、关闭后复用与分配失败路径均有测试。

### T4：DOS 前台程序与所属会话衔接

- DOS 程序的 guest 文本屏幕属于启动它的会话；程序持有期间 Shell 在同一会话等待。
- 程序退出/故障后恢复该会话的 Shell 与正确输入所有者，不重建其他会话。
- 不为了产生“看起来像多终端”的标签，把每个 guest 页当成新 Shell。
- 两个同时存活的 DOS 上下文不得共享单份 VM/guest 内存；
  私有 FAT 镜像保持原有会话内写入语义，未实现共享持久化不作承诺。
- 若第一阶段仍不支持 DOS 运行中唤醒其他 Shell，应明确反馈该限制；
  此状态只能算阶段性版本，不能称最终多终端验收通过。

**验收：** 在 A 启动会等待键盘的 DOS 程序，切到 B 执行命令再返回 A 继续；
结束 A 的 DOS 程序后 A/B 的 Shell 与输入完整，重复运行后没有悬挂页或资源泄漏。

## 5. 回归与对用户的交付

- 宿主：会话生命周期、输出/输入/行编辑隔离、布局与资源失败测试；ASan/UBSan。
- QEMU BIOS/UEFI：**普通启动路径**的新建/执行/切换/关闭，分别检查串口行为与实际页面像素。
- 保留现有 G1–G4 指针/快照、W1 嵌套上下文以及 W5/W6 的 DOS 资源/键盘回归。
- VirtualBox（I/O APIC 开启 + PS/2 Mouse）：新建与关闭入口、鼠标/键盘焦点与切换实测。
  VMware 当前只有用户对现有鼠标的反馈，新终端功能必须另行测试。
- 每阶段更新功能矩阵与限制，测试成功后再导出 ISO。
  现有 `funyos-m4g-preview.iso` 不因这份计划而变成多终端版本。

**最终验收句子：用户无需进入 selftest，即可创建多个独立命令行会话，
各自保留输出和未提交输入；能在不同会话执行命令、运行并返回 DOS 程序，
并安全地关闭会话，而不是只能在固定的 Log/Program 画面之间切换。**
