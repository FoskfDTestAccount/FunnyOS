# M4 任务书:实模式环境与 BIOS

这份目录里的每一份文件都是一个**独立任务**,交给一个独立的执行者。这份 README 是 M4 的总纲:开始之前先读完,然后只看你自己那一份。

> M3 的总纲在 `README.md`,它的第六节(哪颗芯片)、第八节(不在范围内的操作码)以及"手册没写不等于硅片不做"那条规矩**继续有效**,本文件不重复,但每一条都还在生效。**先去读那一份的第六节再回来。**

---

## 一、M4 要做什么

FunnyOS 跑的是一台**自己实现的 IBM PC 兼容机**。M3 让这台机器的 CPU 是对的:它能执行手工汇编的二进制,寄存器和标志位状态正确。但一台 CPU 不是一台电脑——**没有任何程序能在上面跑完**,因为它没法输出一个字符。

M4 补上的是**固件**:中断向量表、中断模型、四个 BIOS 服务(10h 显示、13h 磁盘、16h 键盘、1Ah 时间),以及那块程序会直接去写的显存。

**验收标准:能跑一个自己写的、通过 BIOS 输出的 `.COM` 程序。** 具体地说,一个 `org 0x100` 的 flat 二进制,通过 `INT 10h` 打出字符,在 FunnyOS 的屏幕上真的出现。

### 和 M3 的根本差别

M3 的每一条期望值都能追到**一颗芯片**(8086)。M4 的期望值追不到芯片——**BIOS 不是芯片**,它是 IBM 在 1981 年定下的软件接口,后来被所有人复制。

这件事有一个直接后果,必须写在最前面:

> **仓库里没有 IBM PC 技术参考手册,也没有 Ralf Brown 的中断列表。** 和 M3 缺 8086 手册是同一个缺口,而且**更危险**:M3 里两个人的期望值还可能因为推导路径不同而分歧;M4 里,一个记错的服务号会被**每一个**用它的人一致地记错,所有测试都会绿,而且绿得很有自信。
>
> 所以:**每一条期望值都要注明它是从哪来的**(某个约定俗成的服务号、某份二手资料、还是"我们选的")。**"我记得是这样"要写成"我记得是这样"**,不要写成"手册规定"。原因见 `mark-inferred-vs-checked-claims` 那条:带理由的错误比没理由的错更难发现。

四个头文件。**你只能读,不能改**;缺什么就停下来写进报告。

| 文件 | 内容 | 状态 |
|---|---|---|
| `dos/include/vm86/host.h` | 宿主陷阱、服务注册、IVT、中断投递、运行循环 | **冻结,本轮新增** |
| `dos/include/vm86/firmware.h` | 中断向量号、BIOS 数据区偏移、显示约定 | **冻结,本轮新增** |

`host.h` 顶部的注释就是这份文档的另一半——**陷阱为什么是 `FE 38`、桩为什么用 IRET 收尾、异常为什么按 IVT 有没有被改写来决定投不投递**,理由都在那里。先读它。

`cpu.h` 新增的三个字段(在 `halted` 下面):

| 字段 | 是什么 | 谁写 |
|---|---|---|
| `intr_pending[32]` | 待投递的硬件中断位图,一向量一位 | `host.h` 的 `vm86_raise()` / `vm86_clear_pending()` |
| `intr_shadow` | 还要过几条指令边界才允许识别中断 | `STI` 和任何写 SS 的指令置 1;**运行循环**递减 |
| `insn_ip` | 当前指令**第一个前缀之前**的 IP | 运行循环在消费前缀前记下;**串操作**用它回卷 |

## 三、本轮由协调方做出的决定

这些是接口级的决定,由冻结接口的人做完,**执行者按它做,不要另起一套**。每一条都写了理由,以及理由里哪些是查过的、哪些是选的。

### M4-1 宿主陷阱的编码是 `FE 38`

桩是四个字节:`FE 38 <向量> CF`,从 `0xF000:0000` 起,一向量四个字节,整个表 1 KiB。IVT[v] 指向 `F000:(v*4)`。

**为什么是 `FE /7`:** 它必须是一个**汇编器产不出来**的编码,否则程序迟早会无意中产出它。`FE` 是字节宽度的 INC/DEC 组,只有 `/0` 和 `/1` 有定义,`/7` 在 8086、186、以及之后任何一颗芯片上都不是指令,`inc`/`dec` 也没有 reg=7 的字节形式。mod 和 r/m 都是 0,所以它不带位移,后面那个字节没有歧义。

**为什么不用别的:**

- `F1`(LOCK)和 `D6`(SALC)在 8086 硅片上是**真实指令**,而且本仓库的 `test_verify.c` 和 `test_smoke.c` 已经把这两个字节钉成"未认领 → 向量 6";征用它们等于对那颗芯片说谎。
- `0F` 在 8086 上是 POP CS,而且是留给 286 两字节转义的。同一份测试也钉着它。
- `FF /7` 不行:`vm.c` 的验收用例 `bad-opcode` 用的就是 `FF 38`。

`FE /7` 是唯一一个**征用后不破坏任何既有断言**的编码(查过了:整套测试里没有任何用例碰过它)。

**桩为什么用 IRET 收尾、而不是由宿主模拟返回:** 栈上的中断帧是 guest 的 `INT` 压的(或者 TSR 链接过来之前压的),唯一知道怎么正确弹开它的代码是**guest 自己的 IRET**。宿主服务只管做事,做完就返回,让解释器接着执行那条 `CF`。

### M4-2 服务是函数,注册表是全局的

```c
typedef void (*vm86_service_fn)(struct vm86_cpu *cpu, void *ctx);
```

服务从 `cpu` 的寄存器里取参数、把结果写回去;`ctx` 是注册者给的东西(显示状态、键盘队列、磁盘镜像)。`void` 返回值是**有意的**:M4 里没有任何东西需要"结束程序"(见 M4-11)。进程级而不是每机器一份,理由写在 `host.h` 里。

### M4-3 `INT n` 不做任何特判

它读 IVT、压帧、跳过去——**和 M3 一模一样**。落到桩上就是宿主服务,被 TSR 改写了就是 TSR 的服务。**TSR 链接因此自然成立**,不需要为它写任何代码。

### M4-4 硬件中断投递就是执行一条 `INT n`

`vm86_interrupt()` 是唯一一份压帧+跳转的实现,由三条路径共用:`INT n` 指令、运行循环投递硬件中断、运行循环投递异常。**它们只在"什么时候发生"上不同,不在"做什么"上不同**,写两份就必然在某一处不再相等。

### M4-5 异常只在 guest 挂钩了那个向量时才投递

`vm86_step()` 返回 `VM86_FAULT` 时,运行循环查 `vm86_vector_is_stub()`:

- **向量仍指向我们的桩** → guest 没有为它装处理程序 → **停下并报告**(这就是 M3 的行为,`make test` 里的旧用例一条都不改)。
- **向量已被改写** → 投递给 guest 的处理程序。

这就是 D6 说的"IVT 改写检测",只是**用比较代替了对 0x0000-0x03FF 的写钩子**——同一个答案,少一套机器。

### M4-6 `HLT` 会等待

`HLT` 不是"结束"。真机上它是"等一个中断"。所以运行循环看到它时:

- **有挂起中断且 IF=1** → 当作被唤醒,清 `halted`,投递,继续跑。
- **否则** → 返回 `VM86_STOP_HALT`,由宿主决定(轮询设备、投递、再进来)。

**`cli; hlt` 是终结**,因为 IF=0 的 HLT 在真机上不会被可屏蔽中断唤醒。M4 的验收程序就靠这一点结束。

### M4-7 M3 的三笔欠账在这里还

1. **`REP` 可中断。** 真机在每次迭代之间识别中断。`vm86_str_repeat()` 每轮之间检查 `vm86_interruptible()`;要中断就**把 IP 回卷到 `cpu->insn_ip`**(第一个前缀之前)并返回 `VM86_CONTINUE`,让运行循环去投递。**回卷必须带上前缀**——回卷到操作码之后会静默地把 `rep movsb` 变成 `movsb`。
2. **`STI` 延迟一条指令**(是**识别**延迟,不是 IF 延迟;`STI` 立即置 IF)。
3. **写 SS 之后一条指令**(`mov ss, r` 和 `pop ss` 都算)。

2 和 3 是同一个机制:`intr_shadow = 1`,运行循环在每条指令边界上递减并跳过投递。

### M4-8 显存不做重定向

DESIGN §3.4 写的是"对 0xA0000–0xBFFFF 的写入被转发到宿主显示子系统"。**M4 不这么做。**

0xB8000 就是 guest 内存里的一块普通 RAM,宿主**从那里渲染**。代价是图形模式(M7)必须回来做重定向;换来的是**直接写 0xB8000 的程序读回来能看到自己写的东西**——这是程序真的会做的事,而重定向方案里它会读到别的东西。

这条是**对设计的偏离,记在这里和 DESIGN 里**,因为它读起来像是"忘了做"。

### M4-9 BIOS 数据区要维护

程序**直接读** `0040:xxxx`,不是通过服务调用。一个 `INT 1Ah` 答得对、但 `0040:006C` 里的计数是 0 的机器,会让一部分程序以没人猜得到的原因失灵。

偏移量全在 `firmware.h` 里,**谁的服务谁写**:模式字归视频,计数和键盘标志归键盘/时钟,引导时的固定字段归机器复位。**字段的归属不要交叉写**,两个写者就是两份会分歧的事实。

### M4-10 ROM 区仍然是平坦 RAM

`0xC0000–0xFFFFF` 在真机上是 ROM:读不到的东西返回 0xFF,写被丢弃。**M4 里它是普通 RAM**(读作 0)。`mem.c` 现在就是这样,本里程碑不改。

这同时是**桩能放在 `0xF0000` 的前提**——真 ROM 里写不进桩。代价是:一个去校验 ROM 签名(`0xFFFFE` 处的 `55AA`)的程序会发现没有 ROM。这一条记为已知简化,不是疏忽。

### M4-11 程序终止(`INT 20h` / `INT 21h/4Ch`)不在 M4

它需要 DOS 服务存在,也就是 M5。**M4 的程序以 `cli; hlt` 结束。**

对应的接口后果:`vm86_service_fn` 返回 `void`,**没有**"我要结束程序"的说法。等 M5 需要它时,`enum vm86_result` 会多一个枚举值,**`-Wswitch` 会把每一个必须做决定的消费方列出来**——这正是那个枚举当初被设计成这样的原因。

## 四、硬性规则

### 1. 只改你自己的文件

**文件归属表在第七节。** 不属于你的文件一律不动,包括头文件、别人的模块、`dos/Makefile`、顶层 `Makefile`。

理由和 M3 一样,而且这轮更严重:五个人共用 `cpu.h` 和 `mem.c`,改一处就是改所有人的编译单元。

### 2. 需要接口里没有的东西时——停下来报告

缺什么、为什么现有的不够、你打算怎么绕过。**不要自己加。**

### 3. 不要写第二份共享实现

`vm86_interrupt()`、`vm86_push16()`、`vm86_pop16()`、`vm86_rel` 系列、`vm86_str_repeat()`——直接用。**两份实现的后果不是多了一点代码,是它们必然在某个边界上不一致**,而那个边界会在 M5 跑真实 DOS 程序时出现。

### 4. 每个服务、每条命令码都要有测试

没有测试的命令码等于没写。

### 5. 编译必须零警告

`dos/Makefile` 开着 `-Werror`。新增的源文件**不需要**改 Makefile:`CORE_C` 现在通配 `intr/*.c` 和 `bios/*.c`,新文件自动进来。

### 6. 每个用例都要证明它能失败

这是 M3 那条规矩,继续有效:写完之后**故意把实现改错**,确认用例真的报红。M3 三处独立的变异活动里,第一轮各自都暴露过**永远不会红的用例**——那些用例比没有更糟,因为它们占着位置还让人以为覆盖到了。

## 五、怎么构建和测试

宿主测试(**不跑 QEMU**):

```bash
cd dos
make list        # 有哪些套件
make test        # 全部
make test-bios10 # 只跑你自己的
```

**M4 的测试必须能在没有 FunnyOS 的情况下跑完。** 服务是纯函数:给它们一个 CPU、一块内存、一个假的设备(`ctx`),它们就能工作。`dos/tests/harness.h` 里的约定继续有效,尤其是**每段程序的末尾必须有 `HLT`**(而且 M4 里要 `CLI` 之后再 `HLT`,否则运行循环会把它当成"等中断"——见 M4-6)。

FunnyOS 侧(验收):

```bash
make test-vm     # 把解释器跑进 Ring 3,断言屏幕输出
```

**一、A 必须先交出可用的骨架,其他人才测得通端到端。**

**二、显示后端(B)和 FunnyOS 的屏幕(E)之间只有一层。**
B 定义 `dos/bios/bios10.h` 里的后端接口,并在**没有 FunnyOS 的时候**用一个假后端测试。E 把 FunnyOS 的控制台接到同一个接口上。**B 负责定义,并且要在报告里写清楚它期望后端能做什么。**

**三、键盘的来源(C)和 FunnyOS 的键盘(E)之间同理。**
C 定义队列的接口,宿主往里投扫描码。**注意:FooOS 的键盘驱动投的是 PS/2 扫描码,而 BIOS 的 `INT 16h` 要交的是 ASCII + 扫描码**——这中间有一次转换,**明确写在谁那里**。

**四、磁盘(D)和 M5 的 FAT 之间。**
M4 的 `INT 13h` 只做**扇区级**读写,不懂文件系统。D 顺带交一个能造出镜像文件的工具,但**不要实现 FAT**——那是 M5。

## 八、不在本次范围内

- **`INT 21h` 及任何 DOS 服务。** M5。
- **FAT / 文件系统 / `.COM` 加载器。** M5。M4 的程序还是编译进镜像的字节数组。
- **`INT 20h` / `INT 21h/4Ch` 程序终止。** 见 M4-11。
- **图形模式(`INT 10h` 的 04h-06h、0Ch-0Dh 等)、VGA 模式 13h、VESA。** M7。
- **`INT 14h` 串口、`INT 17h` 打印机、`INT 15h` 系统服务。** 没有设备要驱动。**注册表里没有它们,调用会落到桩上、什么也不做然后 IRET**——这是**故意**的,不是没做。
- **8087 浮点。** M7。
- **把 `0xC0000-0xFFFFF` 做成真正的 ROM 洞。** 见 M4-10。
- **进程模型的重入**(让 Shell 能启动 VM)。**这是 M4 之后的第一件事**,不在本轮。
