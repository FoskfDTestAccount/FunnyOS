## 二、坑

### 1. MOV 段寄存器有硬性限制(而且违反它是**未定义行为**)

- **`8C`(MOV r/m16, Sreg)**:任何段寄存器都可以读出,写到任何 r/m16。
- **`8E`(MOV Sreg, r/m16)`**:**`reg` 字段为 1(`CS`)的编码是非法的**。CPU 不允许 `mov cs, ax`——那是 `jmp`/`call` 的活。

非法编码的行为在手册里是"未定义"。你有三个选择:忽略、当作无效指令触发向量 6、或者按字面执行。**选一个,写下来,并写测试。** 我的建议是触发无效指令异常——它最接近"这不是一条指令",而且能让错误尽早暴露。

**还有一条容易漏的:`8E` 会延迟一条指令生效。** 真实硬件上,`mov ss, ax` / `mov sp, ...` 这个组合靠它工作——段寄存器在下一条指令执行完之后才真正更新,这样紧跟着的那条指令读 SS 还能读到旧值。手册明确说了这一点。

**本实现不做延迟**,因为我们的 `vm86_set_seg` 是立即生效的,而延迟需要在 CPU 状态里加一个"待生效段"字段——那是对冻结接口的改动。所以:在注释里写明这个偏差,并在报告里提出来。这不是你能在 `ops_mov.c` 里解决的问题。

### 2. XCHG 的内存形式会加 LOCK,但这里无所谓

`86`/`87` 访问内存时硬件会隐式加锁。这台机器只有一个 CPU,所以没有可失败的地方。**接受并忽略**,但要知道这件事,因为它在多处理器模拟里会变成真问题。

### 3. A0-A3 没有 ModRM 字节

`mov al, [0x1234]` 的编码是 `A0 34 12`——**操作数就是那个 16 位地址**,没有 ModRM。

这意味着:

- 不能调用 `vm86_fetch_modrm()`
- 但**段超越前缀仍然生效**(段默认是 DS)
- 地址是**直接给出的偏移量**,不是线性地址——要和段基址相加

### 4. C6/C7 的 `reg` 字段必须是 0

组 11 只有一种操作(传送立即数),所以 `reg` 字段被规定为 0。编码里出现非 0 的 `reg` 是**未定义**。

和坑 1 一样:选一个行为(建议触发无效指令异常)、写下来、写测试。

### 5. POP r/m16 的读序

`8F` 先从栈上读 16 位、**然后** SP 加 2、**最后**写目标。

顺序很重要:`pop [sp]` 的编码合法,而它的结果取决于你是先加 SP 还是先算目标地址。手册的规则是——**有效地址在 SP 增加之前就算好了**。所以 `pop [sp]` 写的是旧 SP 指向的位置。

### 6. PUSH SP(已在 `50-5F` 里,但注释提到过)

8086 上 `push sp` 压的是**减完之后**的 SP;186 上压的是**减之前**的。现有实现对两者都用同一个 helper,也就是 8086 行为。这是对的,但如果你在测试里发现它,不要"修"它。

### 7. XLAT 的细节

`XLAT` 等于 `mov al, [bx + al]`,但:

- 段默认是 **DS**,可被段超越前缀改变
- 用的是 **BX**(不是 BP、不是 SI)
- **不动任何标志位**
