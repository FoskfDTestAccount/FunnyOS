## 二、`INT 16h`(键盘)

| AH | 功能 |
|---|---|
| `00h` | 读一个键。**没有键时不能装作有**——见第三节 |
| `01h` | 检查有没有键。**ZF=1 表示没有**;有的话,返回 AL=ASCII、AH=扫描码,而且**键留在队列里**(不取走) |
| `02h` | 取换挡状态,放回 **AL**(就是 `0040:0017` 那个字节)。**不返回扫描码**——见下面的勘误 |

队列的表示在 `firmware.h` 里:`0040:001E` 起 32 字节,头在 `0x1A`、尾在 `0x1C`,**偏移量是相对段首的**,范围 `0x1E..0x3E`。每项是**一个字**:ASCII 在低字节,扫描码在高字节。

> **勘误(2026-10-01,查证后改):`02h` 不返回扫描码。**
>
> 这份任务书原来写着"注意:AH 也要放扫描码"。**那是错的。** 查到的技术资料一致地说 `02h` 只把换挡状态字节放进 `AL`,不返回扫描码,也不返回 ASCII。(有一份维基表格写着 `AH` 是标志字节,而详细的资料一致说是 `AL` —— **两份来源在这里不一致,以"AL"为准并记下这个分歧**。)
>
> 这一处错了不会崩,但会让程序在"有没有按 Shift"上判断错,而症状是某个按键行为不对,很难追到 BIOS 调用上。
>
> **`00h`/`01h` 的返回到是对得上原来的写法**:`AH` = 扫描码、`AL` = ASCII,而且**没有 ASCII 的键(功能键、方向键)给 `AL = 0`**、扫描码在 `AH`。`01h` 还要把这两个也填上(如果队列里有东西)——它只是**不取走**。
>
> **依据是二手的** —— 网上查到的厂商 BIOS 手册与技术资料转述(仓库里没有原件)。拿到原件应当复核。

**头尾相等既是空也是满**(差一次回绕)——这是设计如此,不是可以修好的地方。一个"更聪明"的实现会和按规矩读它的程序对不上。

## 三、阻塞读:这是本任务里唯一要动脑子的地方

`AH=00h` 在真机上是**自旋等**,而且**开着中断等**——这样 `INT 09h` 才能进来把键放进队列。

我们的服务是同步的,模拟器是单线程的:**服务里不能自旋**,否则宿主永远拿不回控制权,键永远进不来。

答案是 `vm86_service_retry()`(`host.h` 里有详细说明):**把这条 `INT` 撤销并重来**——弹掉 INT 压的那个帧,把 IP 退回指令本身。于是:

1. guest 真的在"等",而且是浮在外面的等;
2. 运行循环的预算到点就返回,宿主拿到控制权;
3. 宿主把键喂给 `bios16_key_arrived()`、拉起 `INT 09h`;
4. 中断在**两次尝试之间**被投递,`INT 09h` 把键放进队列;
5. guest 重放那条 `INT 16h`,这次拿到键。

**每一步都要有测试**,尤其是第 4 步——"中断在两次重试之间被投递"是这条路径的全部价值。只测"队列里有键时读得到"是不够的,那测不到重试机制。

**只在真的一条键都没有的时候才重试。** 队列里有东西却重试,会变成一个永远读不出东西的死循环——而且这个死循环在步数预算用完之后表现为"程序卡住不动",不是报错。

## 四、18.2 Hz 从哪来:这是本任务里唯一要做的决定

`0040:006C` 那个双字数的是 **18.2 Hz 的滴答**,时间是 65536 / 1.193182 MHz ≈ 54.925 ms 一下。程序算"过了多久"就是拿它除以 18.2。

**还有一个查到的具体数字:一天是 `0x1800B0` 个滴答**(1 573 040,即 18.2065 × 86400 向下取整),而且**午夜时计数归零** —— `INT 1Ah` 的 `AL` 就是"自上次读以来过了午夜"的标志。所以计数不是简单地任它涨到 32 位回绕,`0x70` 那个标志和午夜归零是一件事的两面。

(还有一个查到的怪癖,值得写进注释:**真 BIOS 把这个标志"置位"而不是"累加"** —— 所以连续两个午夜之间如果没有任何人去读,第二个午夜会丢。这是真行为的缺陷,不是我们的 bug;按真机做,并在报告里说明。)

**宿主的时钟不是 18.2 Hz。** 所以某处必须做一次换算,而**放在哪儿是要决定的事**:

- 放在宿主 → 宿主得知道 18.2 这个常数,而且**每个宿主**(测试、FunnyOS)都要知道一遍;
- 放在 `bios1a.c` → 常数只有一份,宿主只说"过了多少毫秒"。

**建议后者**,也就是 `bios1a_advance(st, ms)` 累积毫秒、返回**这一次应该产生几个滴答**;宿主拿这个数字去 `vm86_raise(cpu, VM86_INT_TIMER)`。

**另一个决定:计数器谁来加。** 真机上 `0040:006C` 是**由 INT 08h 的处理程序**加的——所以一个挂钩了 INT 08h 又不链回去的程序,会让 BIOS 的计数**停住**。那不是 bug,那是真行为。所以按真机做:**计数在 `INT 08h` 的服务里加**(并且在那里处理 `0040:0070` 的回绕标志),`bios1a_advance()` 只负责算"该响几下"。

**把这两个决定和理由写进报告。** 这是本节里唯一没有唯一正确答案的地方。

## 五、`INT 08h` 和 `INT 1Ch`

`INT 08h` 的服务要做两件事:

1. 计数 +1(以及回绕时置 `0040:0070` 的 bit 0);
2. **调用 `INT 1Ch`**——也就是 `vm86_interrupt(cpu, VM86_INT_USER_TIMER)`。

第 2 条看着奇怪,其实是对的:`1Ch` 是留给用户定时器钩子的向量,BIOS 的 08h 处理程序**末尾会主动去调它**。而且这样写**链式顺理成章**:

- 服务调 `vm86_interrupt(cpu, 0x1C)` → 压帧、跳到 `IVT[1Ch]`;
- `IVT[1Ch]` 还是我们的桩 → 陷阱查表发现没有服务 → 什么都不做 → 那条 `CF` 把它弹回去;
- `IVT[1Ch]` 被程序改过 → 它的处理程序跑,`IRET` 之后**回到 08h 桩的那条 `CF`**;
- 那条 `CF` 再弹掉 08h 自己的帧,回到被中断的代码。

**这条路径要有一个用例**:把 `IVT[1Ch]` 改成一个 guest 处理程序(里面数一次某个内存地址),跑若干个滴答,确认它被调到了**而且次数对**。

**EOI 不归你管。** 8259 在宿主这边不存在——宿主负责"什么时候投递",服务只负责"投递到了之后做什么"。

## 六、`INT 1Ah`(时间)

| AH | 功能 |
|---|---|
| `00h` | 读滴答:CX 高十六位、DX 低十六位;AL = "自上次读以来过了午夜"标志(读的时候**自己清掉它**) |
| `01h` | 设滴答:CX:DX |
| `02h` | 读 RTC 时间。**需要 CMOS 时钟,我们没有**——见下 |
| `04h` | 读日期。同上 |

`02h`/`04h` 没有硬件可读,**注册成空服务还是干脆不算实现,由你决定**,但报告里要写清楚:**一个程序拿这几个功能去判断"这是不是一台 AT"**,你返回的东西会决定它走哪条路。**推荐:让它们落到桩上(没注册),也就是什么都不做**,并在报告里写明这样会让 `AH` 保持原值、程序据此判断"没有这个功能"。**不要返回一堆 0** —— 那看起来像"1980 年 1 月 1 日午夜",程序会当成真时间用。

## 七、BIOS 数据区

你负责这两个字段(**别的字段归别人**):

| 偏移 | 内容 |
|---|---|
| `0x0017` / `0x0018` | 换挡状态两个字节:`0x17` 是 Ins/ Caps/ Num/ Scroll 与 Ctrl/Alt,`0x18` 是另一组。(**具体每一位是什么,去查证;查不到就在报告里写明**——这个字节很多人是靠记忆写的,而记忆在这里经常是错的) |
| `0x001A` / `0x001C` | 队列头 / 尾 |
| `0x001E`–`0x003D` | 队列本体 |
| `0x006C` / `0x0070` | 滴答计数 / 回绕标志 |

## 八、坑

1. **`01h` 不能取走键。** 它是"看看有没有",取走的话下一次 `00h` 就丢了一个键——而程序通常是先 `01h` 确认再 `00h` 读。
2. **`00h`/`01h` 的返回值:** `AL` 是 ASCII,`AH` 是扫描码。返回时**不要动 CX/DX/SI/DI/BP/段寄存器**。
3. **`INT 09h` 是可以被替换的。** 所以"硬件上来了一个扫描码"和"它进了队列"是**两件事**——这就是 `bios16_state` 里要有"硬件寄存器"那个字段的原因。程序挂钩 INT 09h 做热键时,它会读走扫描码而不放进队列,那是它的权利。(**8259 在端口 60h 上的那一读我们要不要模拟,是个决定**——见下。)
4. **队列满。** 32 字节的环满了之后新键怎么办?真 BIOS **丢掉**并且响一声(把 `0040:0071` 的 bit 7 置位)。别让它覆盖头。
5. **扫描码的译码表**至少要覆盖:字母、数字、回车、退格、Tab、Esc、空格、方向键(扩展码 `0x48`-`0x50` 那一段,真 BIOS 会把扩展键的 ASCII 位置填 0 而扫描码放在 AH)、以及 Shift/Ctrl/Alt 自身的状态位。**这份表你要自己写,并且注明依据**——这是最容易"照着记忆写错"的一处。
6. **`0040:0017` 的更新时机**:换挡键**按下和松开都要**更新它,不是只在按下时。松开是扫描码带 `0x80` 位那种。
7. **`bios1a_advance` 的取整。** 54.925 ms 不是整数,毫秒累加会漂。用一个整数累加器(比如"已经攒了多少个 1/1000 滴答")而不是每次重新除,并写一个用例说明长时间之后的误差有界。

## 九、不做,但要写进报告

- **8259 的端口。** 程序用 `out 0x21` 屏蔽 IRQ 是常见做法(关键区里关掉定时器)。M4**不做**——现在的 `IN`/`OUT` 是把端口吞掉的。**这是一处真实的兼容缺口**,写进报告,别让它消失。
- **键盘控制器(8042)的命令。** 同上。
- **CMOS/RTC(`INT 1Ah` 02h/04h)。** 见第六节。

## 十、测试要求

**不要用真的键盘**:测试直接调 `bios16_key_arrived()` 和 `bios16_service()`,断言队列和寄存器。

至少覆盖:

- **`00h` 在空队列上重试**:断言 IP 被退回、**SP 复原**(帧真的弹掉了,没有泄漏)、而且**再来一次仍然可以读到**。
- **重试期间中断被投递**(第三节第 4 步)——这条单独写,它是整个机制的价值所在。
- **`01h` 不取走**,`01h` 之后 `00h` 还能拿到同一个键。
- **队列的回绕**:填到 `0x3E` 之后下一项绕回 `0x1E`。
- **队列满**时新键被丢掉、头不动。
- **`INT 09h` 的译码**:字母、回车、方向键(扩展)、以及一个换挡键的按下与松开。
- **滴答的速率**:`bios1a_advance(st, 1000)` 在若干次调用之后给出的滴答总数误差有界(用一个明确的数字钉住,别写"大约")。
- **`00h` 读滴答之后午夜标志被清掉**。
- **`INT 08h` → `INT 1Ch` 的链**(第五节)。
- **程序换掉 `IVT[1Ch]` 之后**,它拿到的是自己的处理程序;换回来之后又是"什么都不发生"。

**每条用例都要证明它能失败**:写完把实现故意改错,确认用例报红,再还原。
