# M4 任务 B:INT 10h 视频

**你负责:** `dos/bios/bios10.c`、`dos/bios/bios10.h`、`dos/tests/test_bios10.c`
**难度:** 中高。命令码多,而且**寄存器保持规则**错一条就会让程序以看不出原因的方式走错。

> 先读 `docs/tasks/M4-README.md`、`dos/include/vm86/firmware.h`、`dos/include/vm86/display.h`。

---

## 一、这个模块在系统里的位置

```
guest 程序 ──INT 10h──▶ 桩(FE 38 10 CF)──▶ 宿主陷阱 ──▶ bios10_service()
                                                              │
                                                    写 guest 内存 0xB8000
                                                    写 BIOS 数据区 0040:0049…
                                                              │
宿主(每隔一段)────────── vm86_display_present() ◀────────────┘
```

**关键在最后一行。** 显示**不是**由服务驱动的:程序也可以直接往 `0xB8000` 写(很多程序就是这么干的),那种写不经过任何服务。所以宿主按自己的节奏从 guest 内存里**读**那一页去渲染。

`vm86_display_present()` 只有一行(判空 + 调用),**你来定义它**,放在 `bios10.c` 里。

---

## 二、你必须导出的东西

`dos/bios/bios10.h` 里,除了 `bios10_service` 之外还要有三个访问器,因为**宿主需要它们才能渲染**:

```c
struct bios10_state;   /* 由调用方拥有:模式、活动页、光标位置与形状、当前属性 */

void        bios10_reset(struct bios10_state *st);
void        bios10_service(struct vm86_cpu *cpu, void *ctx);   /* ctx 是 bios10_state* */

/* 光标在第几个单元(row*80+col),不显示时返回 VM86_DISPLAY_NO_CURSOR。 */
uint16_t    bios10_cursor_cell(const struct vm86_cpu *cpu,
                               const struct bios10_state *st);

/* 活动页在 guest 内存里的地址:4000 字节,字符/属性交替。 */
const uint8_t *bios10_active_page(const struct vm86_cpu *cpu,
                                  const struct bios10_state *st);
```

`struct bios10_state` 的内部布局随你,但**必须是调用方拥有的一个结构体**,不是模块里的 `static`——测试要能同时开两个,FunnyOS 要能把它放在自己的进程里。

## 三、命令码

文本模式下要做的(AH 是功能号):

| AH | 名字 | 备注 |
|---|---|---|
| `00h` | 设置模式 | 只要支持文本模式(`03h` 八十列彩色、`02h` 八十列单色、`00h`/`01h` 四十列)。**收到图形模式怎么办要明确决定**——见坑 1 |
| `01h` | 设置光标形状 | CH 起始扫描线、CL 结束扫描线 |
| `02h` | 设置光标位置 | DH 行、DL 列、BH 页 |
| `03h` | 读光标位置 | 返回 DH/DL 位置、CX 形状。**返回时的寄存器约定见坑 5** |
| `05h` | 选择活动页 | AL 是页号 |
| `06h` / `07h` | 窗口上滚 / 下滚 | AL 行数、CH/CL 左上、DH/DL 右下、BH 填入属性 |
| `08h` | 读光标处的字符与属性 | 返回 AL 字符、AH 属性 |
| `09h` | 在光标处写字符+属性 | AL 字符、BH 页、BL 属性、CX 重复次数。**光标不动** |
| `0Ah` | 在光标处写字符 | 同上,但**保留原有属性** |
| `0Eh` | 电传输出 | AL 字符、BH 页。**这是验收路径用的那个**。BL 只在图形模式下有意义——见下面那条勘误 |
| `0Fh` | 取当前模式 | 返回 AL 模式、AH 列数、BH 活动页 |

**`0Eh` 是重点**(验收程序走的就是它),它的控制字符处理必须对:

- `0Dh`(CR):列归零,**行不动**。
- `0Ah`(LF):行下移一行,**列不动**;**已经在最底行时整屏上滚**。
- `08h`(BS):列减一,退到上一行行尾…… **这里要不要回绕由你决定并写清楚**(真 BIOS 在列已经是 0 时的行为值得你自己去查证,别按"应该"写)。
- `07h`(BEL):忽略。
- 其它可打印字符:写进当前页光标处(**属性见下面的勘误**),光标右移一格;到行尾**回绕到下一行行首**(是回绕,不是只在行尾停住)。

> **勘误(2026-10-01,查证后改):`0Eh` 在文本模式下不写属性字节。**
>
> 这份任务书原来写的是"属性用 BL"。**那是错的。** 文本模式下 `0Eh` 把字符写进目标单元,**保留那个单元上原有的属性字节**,`BL` 只在图形模式下作为前景色有意义。
>
> 这不只是细节:一个用 `0Eh` 在空白屏幕(属性已经是 0x07)上打字的程序,两种实现看起来一样;而一个先在整屏写满彩色属性、然后用 `0Eh` 在上面打字的程序,用 BL 的实现会把颜色擦掉,而真机不会。
>
> **依据是二手的** —— 网上查到的厂商 BIOS 手册与技术资料的转述,不是仓库里的原件(仓库里没有 IBM PC 技术参考手册)。所以这条记为"查证过,但依据是二手来源",拿到原件应当复核。
>
> 相关的两条同样来自这次查证:`BX`/`CX`/`DX` 与段寄存器**不受影响**(`SI`/`DI` 可能被改);到屏幕底部时是**内部转调 `06h`** 完成上滚——也就是说 `0Eh` 和 `06h` 的滚动语义必须一致,不要在两处各写一份。

**写完之后光标要真的动。** `09h`/`0Ah` 不动、`0Eh` 动——这是两条不同的规则,不要合并成一条。

## 四、BIOS 数据区

`firmware.h` 里有偏移量。**你负责写这几个字段**(别的字段归别人,不要动):

| 偏移 | 内容 |
|---|---|
| `0x0049` | 当前模式 |
| `0x004A` | 每行列数 |
| `0x004C` | 每页字节数 |
| `0x0050`–`0x005F` | 八个页的光标位置,每页一个字(行在高字节) |
| `0x0060` | 光标形状,一个字(起始在低字节) |
| `0x0062` | 活动页 |

**这些必须每次变动后立刻同步**——程序是**直接读**它们的,不是通过 `INT 10h` 问的。

## 五、坑

1. **收到不支持的(图形)模式怎么办?** 真 BIOS 会去切模式。你做不到。三个选项:静默忽略、保持文本模式但改掉 BDA 里的模式字、或者拒绝。**这是一个选择,不是事实**——选一个,写进注释和报告,并且**想清楚哪个的后果最小**:"改了模式字但显示没变"会让程序以为它在图形模式下去写显存。
2. **`AH` 的返回值。** 大多数功能返回时 **AH 保持等于功能号**(有些程序靠它判断 BIOS 版本)。有几个功能会改 AX。**逐个核对,不要"看起来不用管就不管"。**
3. **`AL` 的高位在 `00h` 里的含义。** `AL` 的 bit 7 置位时真 BIOS 表示"不要清屏"。这是一条真规则,不是传说——但**你要先确认它**,确认不了就在报告里写成"我们没实现,理由是……"。
4. **页偏移不是 4000。** 页面间距是 BDA `0x4C` 里那个值(真机上 80×25 文本是 4096),光标和地址都要按它算。用 4000 去算第 2 页会**恰好错在页边界附近**,而且第 0 页一切正常。
5. **`03h` 的返回。** DH/DL 是位置、CX 是形状、BH 保持页号。这里错一个寄存器,程序拿到的光标位置就是垃圾,而它通常只是拿去算个偏移,不会崩。
6. **`06h`/`07h` 的 `AL = 0`。** 真 BIOS 上是"清空整个窗口",不是"滚 0 行"。滚 0 行是"什么都不做",两者差一整屏,而且只在 AL=0 时才分得出来。
7. **窗口的四个寄存器是 `CH/CL` 和 `DH/DL`**,不是 `CH/DL`。滚动的矩形由它们给出,不是整屏。
8. **`0Eh` 到屏幕底部要上滚整页**(不是清屏,是上滚一行),滚动的填入属性是……**这里真 BIOS 的取值你要查证**;查不到就选一个并说明。
9. **别自己实现一遍 `vm86_display_present` 之外的显示机制。** 显存就是 guest 内存,不要试图维护第二份"影子屏幕"——两份状态必然分歧,而分歧的那天表现为"程序读回来的和屏幕上的不一样"。

## 六、测试要求

`dos/tests/test_bios10.c`。**不要用真的屏幕**:`vm86_display` 传一个假的,把 `present` 收到的 `cells` 和 `cursor` 记下来,断言它。这是唯一能让"字符出现了"变成断言而不是"某个人看了一眼"的办法。

至少覆盖:

- **`0Eh` 打一行字**,然后用假后端断言:第 0 行第 0..n 个单元是期望的字符和属性,光标的 `cursor` 正好在第 n+1 格。
- **`0Eh` 到行尾回绕**,以及**在最后一行触发上滚**(断言整屏内容整体上移,最后一行是空的,不是上一行的残留)。
- **`0Dh`/`0Ah` 分开处理**:`0Ah` 之后列**不变**,`0Dh` 之后行**不变**。
- **`09h`/`0Ah` 不动光标**,而 `0Eh` 动。
- **`09h` 带重复次数**。
- **`02h`/`03h` 往返**:设一个非零页、设一个位置、读回来,三者都对。
- **`06h` 的 `AL=0` 清窗口**,和 `AL=1` 只滚一行,两者不同。
- **`05h` 换页之后 `09h` 写的是新页**,旧页不变。
- **BDA 同步**:每次操作之后**直接读 `0040:0049`/`0x50`/`0x62`** 去核对,不要再调 `INT 10h` 读——那测的是另一条路。
- **未知的 AH**:确认它的行为就是你决定的那个,并且**寄存器没有被意外改掉**。

**每条用例都要证明它能失败**:写完把实现故意改错,确认用例报红,再还原。
