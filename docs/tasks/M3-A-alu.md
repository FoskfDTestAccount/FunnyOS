## 二、通用结构

组编码(`80-83`、`F6/F7`、`FE`)都是同一个形状:**ModRM 的 `reg` 字段是操作码扩展位**。所以一个函数处理整个组:

```c
static enum vm86_result op_group1(struct vm86_cpu *cpu, uint8_t opcode)
{
    uint8_t width = (opcode & 1) ? 16 : 8;   /* 80/82 是字节,81/83 是字 */
    struct vm86_modrm mr;
    vm86_fetch_modrm(cpu, &mr, width);

    switch (mr.reg) {          /* 操作扩展位 */
    case 0: /* ADD */ ...
    case 7: /* CMP */ ...
    }
}
```

注意 `0x82`——它是 `0x80` 的**未公开别名**,编码完全相同。真实程序里会出现(某些汇编器会生成它)。两个操作码指向同一个函数即可。

## 三、坑

### 1. 移位的标志位规则与直觉不符

这是整个任务里最容易错的部分,而且错了不会崩,只会让某个循环多转一圈。

| 指令 | CF | OF(仅当计数为 1 时有定义) |
|---|---|---|
| SHL/SAL | 最后移出的那位 | `CF XOR 结果的最高位` |
| SHR | 最后移出的那位 | 操作数的**原始**最高位 |
| SAR | 最后移出的那位 | **恒为 0** |
| ROL | 循环移出的那位 | `结果的最高位 XOR CF` |
| ROR | 循环移出的那位 | 结果的**次高位** XOR 最高位 |
| RCL | 循环移出的那位 | 同 ROL |
| RCR | 循环移出的那位 | 同 ROR |

**计数为 0 时一个标志位都不动。** 这在硬件上不是一个特例分支——它就是"没有发生任何事"。但它会让 `shl ax, cl` 在 CL=0 时表现出和 CL=1 完全不同的行为,而编译器生成的代码确实会有 CL=0 的时候。

**计数大于 1 时 OF 未定义。** 手册不承诺任何值,测试里用 `ignore` 参数跳过它,实现里不要试图"算对"。

### 2. 移位计数在 8086 上**不**截断

这是 8086 与 186 的真实差异,而我们会同时声称支持两者:

- **8086**:`shl ax, cl` 用 CL 的**完整值**(0-255)。CL=20 就是移 20 次,结果是 0。
- **186+**:计数被**截断到 5 位**(16 位操作数其实是 4 位)。CL=20 变成移 4 次。

**本实现按 8086 行为**(不截断),因为 DESIGN 说这台机器是 8086。但请在代码注释里写明这个选择——这是有人会来改的那类决定,而改的人需要知道你当初为什么这么选。

### 3. DIV 有两个出错条件,都触发向量 0

不只是除零:

- 除数是 0 → 向量 0
- **商放不下**(16 位除法中商 > 0xFFFF,8 位除法中商 > 0xFF)→ **也是向量 0**

第二个条件很容易漏。`div bx` 在 DX=0xFFFF、AX=0xFFFF、BX=1 时不是得到一个截断的商,而是触发除法错误。真实 DOS 程序靠这个来检测溢出。

设置 `cpu->fault = VM86_VECTOR_DIVIDE_ERROR` 并返回 `VM86_FAULT`。

### 4. MUL/IMUL/DIV/IDIV 的标志位

- **MUL/IMUL**:CF 和 OF 表示"结果的高半部分非零(或非符号扩展)"。其余标志位**未定义**。
- **DIV/IDIV**:所有标志位**未定义**。不要清零,也不要保留——手册不承诺。
- **IMUL 是符号乘法**,结果在 DX:AX 里(不是 AX)。符号扩展是**对结果**做的,不是对操作数。

### 5. NEG 不是"取反"

`NEG x` 等于 `0 - x`,并且:

- 操作数为 0 时 **CF = 0**(不是 1)
- 否则 CF = 1
- 操作数为 0x80/0x8000 时 **OF = 1**(取负结果还是它自己)

### 6. NOT 不动任何标志位

一个标志位都不动。`NOT` 和 `NEG` 挨着放在组 3 里,而它们的标志位行为完全相反。

### 7. DAA/DAS/AAA/AAS 的规则必须查手册

这四条是 BCD 调整,规则是**条件式的、带隐式依赖的**:

- `DAA`/`DAS` 读 **AF 和 CF**,按一张四行的表决定加/减 6(或 60),然后再设 CF。
- `AAA`/`AAS` 读 **AF**,决定是否加/减 6,并且**只改 AL 的高四位和 AF/CF**,其余保留。

凭记忆写这四条几乎必然出错。查《8086 Family User's Manual》第 3 章各自那页的表格,照着写。**每一条都要有至少三个测试用例**:不需要调整的、需要调整低位的、需要调整高位的。

### 8. AAM/AAD 带一个立即数操作数

编码是两字节(如 `D4 0A`),那个立即数是**进制**。手册说不是 10 的行为未定义,但真实程序里 `D4 0A` 就是除以 10。

- `AAM`:AL 除以立即数,商 → AH,余数 → AL
- `AAD`:AL = AL + AH × 立即数,然后 AH = 0

两个都根据 AL 的结果设 SF/ZF/PF。

### 9. CBW/CWD

- `CBW`:AL 的符号位扩展到 AH(`0x80` → AX = `0xFF80`)
- `CWD`:AX 的符号位扩展到整个 DX

两者都**不动任何标志位**。

### 10. `FE` 的寄存器形式是合法的,而且**没有替代编码**

写这条是因为**第一版任务书在这里写错了**,而且错得很有说服力:表里写的是"INC/DEC **内存**字节",于是实现把它当成了 memory-only,让 `mod==3` 报非法指令。

**`FE C0` 就是 `inc al`。** 寄存器形式完全合法、有文档。

**为什么这个错特别贵:** `40`-`47` 那组一字节短形式是给 **16 位寄存器**的(`inc ax` … `inc di`)。**字节寄存器没有短形式。** 所以 `inc bl` 只能是 `FE C3`,`dec dl` 只能是 `FE CA`——**每个 DOS 程序里的每一次字节寄存器自增自减都走这条编码**。拒绝它,真实程序在第一次 `inc bl` 时就死。

真正未定义的只有 `reg` 字段的 `/2`-`/7`,那些报非法是对的。

**由这条推广出的一个检查动作:在你"拒绝"一个编码之前,先问一句——它是真的未定义,还是只是不常见、或者存在更短的等价形式?** **存在短形式,不等于长形式非法。** `40` 存在,不代表 `FE C0` 不合法。

### 11. 理由里出现"外部世界的事实断言"时,标注你是查过还是推的

上一条之所以差点被当成一个经过权衡的决定放过去,是因为它的理由读起来很完整:"`inc al` 有一字节编码""汇编器不会发这个"。**两条都是关于外部世界的事实断言,而两条都是错的。**

所以:凡是理由里出现这类句子——"汇编器会/不会发这个""手册是这么写的""真实程序用不到"——**在报告里标明你是查证过还是推测的**。推测不是错,把推测写得像查过才是。
