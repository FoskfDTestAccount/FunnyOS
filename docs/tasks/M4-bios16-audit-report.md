## 〇、结论

**这两个模块的核心是对的**,包括 C 自己标出来的那个最不显然的决定(阻塞重试不设影子)。逐条验证见第二节。

**一条真缺陷,一条注释算术错:**

| # | 是什么 | 严重度 |
|---|---|---|
| 1 | **`0040:0071` 是 Ctrl-Break 标志,不是溢出标志** —— 任务书写错了,C 照做了 | **中**:会污染一个程序真的会轮询的字段 |
| 2 | **`BIOS1A_TICKS_PER_DAY` 的推导站不住**:常数对,理由错 | 低:但读者会"修"那个常数 |

**另外一条机制上的观察**(不是这两个模块的错):整条 `08h → 1Ch` 链在 `IF=0` 下运行,因为我们的固件处理程序不像真 BIOS 那样自己 `STI`。

## 一、需要处理的

### 1(中)。`0040:0071` 是 Ctrl-Break 标志

> **【已修】** 协调方裁定"去掉写入",`bios16.c` 现在不碰这个字节;偏移进了 `firmware.h`(`VM86_BDA_CTRL_BREAK`),旁边写着这段经过。本套件的用例已从"钉住缺陷"翻成"钉住正确行为"(`an overflow touches nothing`,断言 `0x00`)。
>
> **下面保留原始分析,因为值得记下来的是它怎么发生的,而不是它修了没有。**

**两份独立来源:**

- Ralf Brown 的内存表:`MEM 0040h:0071h - Ctrl-Break FLAG`,"bit 7 is set when Ctrl-Break has been pressed",交叉引用 `INT 1B`。
- 关于缓冲区满:真 BIOS **响一声、不推进尾指针、直接返回**,也就是**丢掉那次击键**;**不置任何标志**。

**代码为什么写它:** `docs/tasks/M4-C-kbd-time.md:163` 写着:

> "4. **队列满。** 32 字节的环满了之后新键怎么办?真 BIOS **丢掉**并且响一声(把 `0040:0071` 的 bit 7 置位)。别让它覆盖头。"

**那半句是错的。** 而 `dos-refs.md` 通篇没有 `0040:0071`,所以这条唯一的"权威"就是任务书的那句话。

**最值得记下来的一层:** `bios16.c` 自己的注释**注意到了**这个偏移不在 `firmware.h` 的图里、也不在任务书列的"本模块拥有的字段"里 —— 然后**选择相信坑清单,而不是相信归属规则**。而归属规则("不属于你的字段别写")正是能抓住这一条的规则。这是一个**规则和便条冲突时便条赢了**的例子,而这个项目为这个形状已经付过代价。

**后果不是表面的:** 轮询 `40:71` bit 7 来判断用户有没有按 Ctrl-Break,是这件事的**通常做法**(FreeDOS 的 `break.c` 就是 `CB_FLG = *(UBYTE FAR*)MK_FP(0,0x471)`)。现在的实现让**每一次读键落后**都表现为"用户按了 break",而把那个位当"停下你正在做的事"的程序就真的会停。

**建议:** 不写。`kb_push` 丢弃最新键、不推进尾指针的那部分**是对的**,保留;把写 `0040:0071` 的三行去掉。如果确实想要一个"溢出发生过"的可见信号 —— **真机上没有**,所以老实说没有。

**用例:** `KNOWN DEFECT: an overflow touches the Ctrl-Break flag`(前两条断言证明普通入队和"装满"都不碰那个字节,第三条钉住溢出的现在行为 `0x80`;修好之后改成 `0x00`)。变异"把 `BIOS16_BDA_OVERFLOW` 改一个字节"能被它抓住,说明这条用例真的钉在 `0x0071` 上。

### 2(低)。`BIOS1A_TICKS_PER_DAY` 的推导错,常数对

`bios1a.h` 说这个常数是"eighteen and a bit ticks a second, times 86400, **rounded down**, the same rounding the firmware does"。算一遍:

```
1193182 / 65536 * 86400 = 1573042.68   ->  1573042 = 0x1800B2
```

而常数是 `0x1800B0` = **1573040**,差**两个 tick**。

**常数是对的,理由错的。** `0x1800B0` 是 IBM 固件用的值,它短两个 tick 是因为 **BIOS 的时钟本来就短** —— 真机的午夜比真实的 24 小时早到约 2.7 个 tick。这是那份常数的性质,不是这里算错了。

**为什么值得改:** 危险在于读者会信哪一半。一个核了算术、发现它推不出那个常数的人,会去"修"**常数**,于是这台机器在"午夜是什么时候"上与每一个按真机写的程序分歧 —— 而 `dos-refs.md` 第六节列的就是 `0x1800B0`。

**用例:** `the BIOS day is shorter than a real day` —— 同时钉住"一天毫秒数 = `0x1800B2`"和"固件的天 = `0x1800B0`",并断言前者大于后者,把一个注释里的算术错变成一条能红的断言。

## 二、C 的决定,逐条验证

### 1. `00h` 的阻塞重试**不设** `intr_shadow` —— **决定正确**

C 的理由是:重试是**从头重新进入服务**的,自己起影子会让机器永远投递不出东西。我独立推了一遍,成立,而且成立的方式比那句话说的一步更多:

- 重试回卷到的是**桩**(不是 INT),桩只有一条指令(`FE 38`,一条陷阱)。所以重试循环里**唯一**被执行的指令就是那条桩,而它每轮都把影子重新起起来 —— 于是每个边界上看到的都是"影子非零",投递永远被跳过。
- **这条推理依赖一个不显然的事实:** 回卷目标是桩。如果哪天有人把 retry 改成回卷到 INT(旧版 `host.h` 的措辞曾经就是这么描述的),循环里就会多出压帧,这个结论要重新推。

**"运行循环返回本身提供的延迟够不够"** —— 够,而且比够更多:INT 清 `IF`,重试把它打开并**返回**;运行循环在下一个指令边界上就能投递,而那个边界是重试本来就跨过的。硬件加给 `STI` 的那条"下一条指令"延迟在这里是多余的,因为返回本身已经跨过了一个边界。

**用例 `a blocking read is satisfied while it waits` 是全树唯一一条在真正的 `vm86_run` 上跑完阻塞读的用例。** INT 16h → 向量表 → 桩 → 陷阱 → 服务决定答不了 → `vm86_service_retry` → 运行循环花掉一个边界 → 投递 IRQ1 → 键盘处理程序填缓冲区 → 客人重新执行 INT 并拿到键。C 的两个套件都带**自己那份 `vm86_run` 复制品**(写于真循环存在之前,`test_bios16.c` 的注释自己说了),所以那条路此前没有被跑过。

**变异"重试时起影子" → 这条用例红,而且不会挂**:预算兜住了它(这点重要,一个"证明它会挂"的用例会真的挂)。

### 2. `02h` 只答 AL —— 勘误落对了,而且**没有别处顺手把它当 00h 处理**

- 代码 `cpu->al = kb_read_flags(cpu); return;`,只写 AL,`AH` 保持功能号 ✓
- 你特别问的"有没有别的地方顺手把它当成 `00h` 处理了":我逐个读了 `bios16_service` 的三个分支和 `key_translate`。**没有** —— `00h`/`01h` 都写 AX,`02h` 只写 AL。`key_translate` 的返回值只经 `kb_push` 进环,与 02h 无关 ✓
- 用例 `02h answers in AL and leaves AH alone`;变异"02h 顺手清 AH" → 红

### 3. 左右 Shift 的位序 —— **实现是对的,但两个套件都不区分它们**

- `dos-refs.md` 第七节:bit 0 = **右** Shift,bit 1 = **左** Shift,并点名这是最容易记反的一对
- 实现:`keymap[0x2A(左)] = BIOS16_HOLD_LEFT_SHIFT = 0x02`,`keymap[0x36(右)] = BIOS16_HOLD_RIGHT_SHIFT = 0x01` ✓ **对的**
- **但 `grep LEFT_SHIFT|RIGHT_SHIFT tests/test_bios16.c` 没有任何结果。** 两个套件都只测"Shift 按下了没有",而掩住两个位的结果一样 —— 所以**把这一对写反,两个套件全绿**。这正是你让我按"作者自己的套件区分不出来"这个标准找的东西
- 用例 `right and left shift are different bits`:右 Shift → `0x01`;再按左 → `0x03`;松开右 → 还剩 `0x02`;松开左 → `0x00`。变异"交换两个宏" → 红

### 4. 队列满的丢弃 —— **丢弃策略对,写标志那半错**(见一.1)

- 丢**最新**键、不覆盖头 ✓ 可恢复的选择:打字的人可以再按一次,而覆盖最新会破坏一个程序**即将读到**的数据
- 环 16 个字装 **15** 个(头 == 尾既是空也是满,最后一个槽用来区分两者)✓ 与 `dos-refs.md` 一致
- 响铃:这台机器没有喇叭,代码注释也这么说了 ✓ 无事可做
- 用例 `the ring holds fifteen and drops the newest`(通过**服务**读回来数,不是看指针)、`the pointers stay inside the ring`(40 次推/取,每个指针都在 `0x1E..0x3D` 且为偶)

### 5. `INT 08h → INT 1Ch` 的帧顺序 —— **对**

- `bios1a_irq` 从自己的处理程序内部调 `vm86_interrupt(1Ch)`,1Ch 的帧压在 08h 的帧**上面**,两个 IRET 按相反顺序弹回 ✓
- **值得说的是这个错不会在计数上显出来**:帧顺序写反的实现在**计数器上完全正确**,而机器的栈每 tick 下沉 6 字节 —— 直到某次中断把栈推进别的东西里。所以用例测的是**栈平衡**(计数器 +5 **且** `SP` 回到原处),不是计数
- 变异"不调 1Ch" → 红

### 6. 滴答速率与午夜 —— **对**

- 18.2065 Hz ✓ 一秒 18 tick ✓ 一小时 65543(`0x10007`)✓
 
  顺带:C 的分数 `596591/32768000` **是精确的**(= `1193182/65536000`,分子分母同除以 2),不是近似。可惜我的第一版用例断言选得太弱,区分不出"每次调用截断"和"余额带走" —— 50 ms 一次调用是 0.91 个 tick,截断就是 0。改成 55 次 50 ms 的切片(2.75 秒 → 50 ticks)才真的能失败。**这是我又一次被自己的弱断言绊到。**
- 午夜:计数真的归零,标志**置位而非累加** ✓ 真机怪癖按真机做 ✓(原型:两次午夜之间没人读,第二个午夜不留痕迹)
- 回绕条件是 `>=` 且**正确**:最后一个可见值是 `0x1800AF`,再一个 tick 得到 `0x1800B0` → 归零 + 置标志。用 `>` 会让程序看见一瞬间的 `0x1800B0` —— 变异能抓住
- 用例:速率、一天、回绕点、两个午夜一个标志

## 三、我确认没问题的其余部分

- **扫描码在高半、字符在低半**(`keymap` → `kb_push`,服务 → AL/AH)✓
- **未实现的 AH**(`10h` 以上的增强键盘调用)一个寄存器都不写 —— 程序用它探测机型时拿到的是"没有",而不是假答案 ✓
- **`01h` 在空队列上不动 AX**(C 的选择)。理由合理:一个忽略 ZF、直接读 AX 的程序会去处理"扫描码 0、字符 0"这个键盘产生不出来的键;不动寄存器至少让它处理它自己原来的值 ✓
- **锁键的读-改-写**不会和低四位互相擦除:按住 Shift 时 Caps Lock 仍在 ✓
- **Insert 同时是锁位和击键**(唯一一个两者都做的键)✓ 且 break 码不翻回去 ✓
- **`bios16_init` 把头尾都设成 `0x1E`** —— 空环不是零,零会让第一次击键写进设备字 ✓
- **`bios1a` 的 `02h`/`04h` 落到 `default` 什么也不做**,不返回零(回零会被当成 1980-01-01)✓
- **`00h` 返回**旧的**午夜标志并清掉它**,顺序正确(标志描述的是即将交出去的那个计数)✓

## 四、不是一个缺陷,但值得写下来

**整条 `INT 08h → INT 1Ch` 链都在 `IF=0` 下运行。**

真机的定时器 ISR 一开始就 `STI`,所以 1Ch 的钩子(以及钩子里的一切)是**可被键盘中断抢占**的。这里不是:IRQ0 的投递清掉 `IF`,`bios1a_irq` 不再打开它,`vm86_interrupt(1Ch)` 又在 `IF=0` 的基础上压帧 —— 于是键盘中断要等整个 tick 处理完才轮到。

- **不丢东西**(pending 位还在;`vm86_raise` 的 OR 让它还是一次),影响是**延迟**不是丢失。
- **这不是 `bios16`/`bios1a` 的错**,是所有固件服务模块的共同简化:真 BIOS 的处理程序自己 `STI`,我们的不。
- 记在这里是因为 M5 的 DOS tick 处理程序可能有一天依赖"处理程序里可以被抢占",而那会在一个和键盘毫无关系的地方表现出来。

**另一条:C 的两个套件各自带了一份 `vm86_run` 的复制品。** 那不是产品里的第二份实现(是测试夹具,注释也说明了),但它意味着**跑这两个套件的是没有被测过的那份循环**。真正的循环现在存在了,把一个处理器相关的 bug 藏在夹具里是可能的 —— 我在这次审查里就把阻塞读搬到真循环上跑了一遍,结果是好的。M5 之前值得把两份夹具换掉。

## 六、没覆盖的

- **Alt + 小键盘输入数字**(`Alt` 序列进入 `0040:0019`):注释说没实现,我没测它"确实没实现"。
- **复合键的 break 行为**是否与真机逐位相同:没核。
