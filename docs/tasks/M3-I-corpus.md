## 一、为什么要做这件事

现在 `dos/tests/` 里有六个套件、近三百个用例,测的全是**操作码**:给一条指令、一组初始寄存器,比对结果。这是对的,但它漏掉了一整类错误 —— **指令之间的相互作用**。

举几个只有连起来跑才会暴露的例子:

- `adc`/`sbb` 依赖上一条指令留下的 CF。单条测 `adc` 时 CF 是你直接设的;真程序里它是算出来的,而"算出来的 CF"和"设出来的 CF"在实现里可能不是同一条路径。
- `rep movsb` 的 `CX=0`、以及 `CX` 在最后一次也减。单条测 `movsb` 看不见。
- 段前缀跨指令、前缀与 `rep` 的组合(`F3` 同时是 `rep` 和段前缀 `DS` 的编码 —— 到底怎么解析,只有真跑一段才知道)。
- 一个循环里 `SHL` 后接 `JNZ`,移位计数为 0 时标志位不动 —— 循环会多转一圈,而单条测出来一切正常。

而且还有一层更重要的:**M3 的验收标准是"能执行手工汇编的二进制,寄存器与标志位状态正确"。** 那句里的主语是**二进制**,不是操作码。所以验收需要一个"二进制 → 跑 → 状态"的路径,现在没有。

这份样本集就是那条路径,而且它是**桥**:`dos/` 现在只在宿主进程里跑得通,接了内核之后要在 guest 里跑。同一个样本集、同一份期望状态,两边都要能用。**这就是为什么任务要求回放器是一个可复用的函数,而不是一个只会在宿主上跑的 `main`。**

## 二、冻结的约定:guest 镜像怎么加载、怎么进入

这一节是我定的接口,**照它做**。它现在服务于样本集,但 M5 的 `.COM` 加载器要用同一套,所以现在定对,以后不用改。

| 项 | 值 |
|---|---|
| 镜像格式 | 平坦二进制(`nasm -f bin`,源码里 `org 0x100`) |
| 加载到 guest 线性地址 | `0x100` |
| 入口 `CS:IP` | `0x0000:0x0100` |
| `DS` / `ES` / `SS` | 全部 `0x0000` |
| `SP` | `0xFFFE` |
| 初始 `FLAGS` | `0x0002` |
| guest 内存 | 至少 1 MB,`vm86_mem_attach()` 接到一块调用方拥有的缓冲 |

**为什么从 `0x100` 开始而不是 `0x0000`,哪怕现在没有 PSP:** `.COM` 的约定是 PSP 占 `0x0000`–`0x00FF`、程序从 `0x100` 开始。M5 会补上 PSP,到那时**这个数一个都不要改**。现在图省事从 0 开始,将来就要动所有样本的期望状态,而动过的东西就不再是"验证过的东西"了。

**为什么初始 `FLAGS` 是 `0x0002` 而不是 `0`:** 8086 的 bit 1 恒读为 1(`VM86_FLAG_ALWAYS_SET`)。设成 0 的话,上电状态下 `FLAGS` 的低位就是错的,而样本集第一次读它就会以最隐蔽的方式失败。

**没有 PSP 这件事要写进报告**,因为它是这套约定和真实 `.COM` 之间唯一的差。样本里不要出现任何依赖 `DS:0` 的代码。

## 三、你要做什么

### 3.1 样本(汇编源码)

`dos/corpus/` 下写一批 `.asm`,每个是一段能独立跑完、然后**停机**的小程序。用 `nasm -f bin` 汇编。**必须有覆盖**:

- **标志位链**:`adc` / `sbb` 的进位链,至少三段
- **循环**:一个用 `SHL`/`JNZ` 的真循环,**含一次计数为 0 的迭代**(验证第三节第 3 条)
- **串操作**:`rep movsb`、`repne scasb` 找字符、`CX=0` 的情况
- **段覆盖前缀**:同一个样本里对同一处内存先按 `DS` 读、再按 `ES` 读,证明 `DI` 的 ES 侧不可覆盖
- **80186 扩展**:`pusha`/`popa`、`enter`/`leave`、多操作数 `imul`、立即数移位
- **"哪颗芯片"那几处**(README 第六节的对照表):`push sp` 压的是**减之前**还是**之后**的 SP;带段覆盖前缀的 `lea` 结果是纯偏移还是含段基址;`mov` 到段寄存器之后 `seg_base[]` 什么时候更新。**每条都要单独一个样本**,因为这几处正是任务书自己错过的地方,它们值得被一个独立于实现的人写一遍。
- **必须 fault 的样本**:一条 `FF /7`(非法组 3 编码),期望是 `VM86_FAULT` 且 `cpu->fault` 是非法指令向量,**不是**被当成别的指令跑过去

### 3.2 期望状态清单

每个样本声明它的期望终态:

- 全部通用寄存器 (`AX BX CX DX SI DI BP SP`)
- 全部段寄存器 + (`CS`,`IP`) + `FLAGS`
- 可选:一段 guest 内存的期望字节

**`FLAGS` 的比较必须带一个"忽略掩码"。** 很多指令的某些标志位是**未定义**的 —— `MUL`/`IMUL` 除 CF/OF 外全部未定义,移位计数大于 1 时 OF 未定义,`DIV` 全部未定义。任务书 A 的坑 4 已经确立了这条规则。掩码写错的方向是不安全的:**掩码太宽会让真 bug 通过**。所以每个样本的掩码要有理由,不能整表复制一个常量。

**fault 样本的期望终态形状不同**:期望的是 `VM86_FAULT` + `cpu->fault` 的值,而不是寄存器。清单里要能表达这两种。

### 3.3 回放器

一个**可复用**的函数,形状大致是:

```c
/* 把 image 按第二节的约定装进 mem,跑到停机或 fault,
   和 expected 比对,把差异报给 sink。返回通过与否。 */
bool vm86_corpus_replay(struct vm86_mem *mem, const struct corpus_case *c,
                        vm86_corpus_report report, void *ctx);
```

**约束和任务 H 一样:不调用 `printf`、不 malloc、输出走一个 sink。** 理由也一样 —— 同一份代码将来要在 guest 里跑。

`dos/tests/test_corpus.c` 是宿主侧的驱动:对每个样本调 `nasm` 生成二进制、attach 一块内存、调 `vm86_corpus_replay()`、把失败汇总。宿主侧可以用 `printf` 做 sink,那是在**驱动**里,不在回放器里。

## 四、坑

### 1. "停机"是什么,先定下来再写样本

8086 的 `HLT` 在真实硬件上等中断。这里没有中断投递(那是 M4)。所以"跑完"需要一条明确的约定。两个候选:

- 样本最后一条是 `hlt`,回放器把 `cpu->halted` 当作终点
- 样本结尾是一条"特殊"指令,或者干脆靠**指令条数上限**兜底

**选一个,写进每个样本,并且写进报告。** 无论选哪个,**回放器都必须有指令条数上限** —— 一个写错的样本(比如死循环)不能让整个测试套件挂住。上限触发的报告要和"状态不匹配"明确区分开,否则一个死循环会伪装成一次断言失败,而你会去查那个根本不存在的错误。

### 2. 生成二进制会引入对 `nasm` 的依赖

`dos/Makefile` 现在的套件是纯 C。加进来的 `nasm -f bin` 让它多一个外部依赖。**顶层构建本来就要 `nasm`**(内核有 `.asm`),所以这不是新问题,但要在 `dos/Makefile` 里**显式检查 `nasm` 存在**,并在缺失时报一句能看懂的话 —— 否则失败信息会是"找不到某个 `.com`",离原因很远。

### 3. `rep` 与"计数为 0"——这是本任务最值钱的用例

`rep movsb` 在 `CX=0` 时,整条指令**一条都不执行**,`IP` 只前进过前缀和操作码,`SI`/`DI`/`CX` 全部不动。单条测 `movsb` 永远看不到这个,因为那个测试是自己决定要不要进循环的。

所以样本里要有一个 `CX=0` 的 `rep movsb`,并且**它前后各有一条会改标志位的指令** —— 用来证明 `rep` 在零次时连标志位都没碰。这个样本是任务 H 第二节第 1 条(`IP` 到底动没动)的独立佐证。

### 4. 段覆盖与 `DI` 的 ES 侧

`movsb` 的 `SI` 侧走 `DS`(可被前缀覆盖),`DI` 侧永远走 `ES`。**给 `rep movsb` 加一个 `es:` 前缀不会改变它的行为** —— 那正是要验证的。写一个样本:源和目标故意放在不同的段里,加前缀,结果必须和不加时一样。

### 5. 你的期望值是独立写出来的

**最重要的一条。** 这个任务的整个价值在于"有一个独立于实现的第二方说了算"。如果你先去看 `ops_alu.c` 怎么算再写期望值,那这份样本集只是把实现抄了一遍,它能证明的东西归零。

所以:**先按手册写期望值,写完再看实现。** 对不上的地方**先怀疑自己**,查完手册还不对,**报上来,不要改期望值去迁就实现** —— 那个不一致本身可能就是 F 在找的东西,也可能是你发现的。两种情况都要留痕。

这条同时适用于 README 第六节那几处"哪颗芯片":**按 README 的 8086 列写**,不要按你记得的 286/386 行为写。

## 五、完成标准

1. `cd dos && make test` 全绿,`-Werror` 下零警告
2. `make test-corpus` 会**真的执行**(用 `make -n` 或故意让一条断言失败来证明,别只看退出码)
3. 每个样本都有:源码、期望终态、以及**它为什么需要这个掩码**的一句话
4. 第三节 3.1 列出的每一类都至少有一个样本,包括**必须 fault 的那一个**
5. 回放器里不出现 `printf` / `malloc` / `stdio.h`(4.1 的指令条数上限可以用一个常量,不需要动态内存)
6. 报告里写:
   - 你选的"停机"约定是什么
   - 每个样本的期望值是**怎么来的**(查了手册的哪一页、还是推导的)—— 按任务书 A 坑 11 的要求,推测要标成推测
   - **有没有哪个样本,你先写的期望和实现不一致?** 有的话,最后是谁对,为什么。这一条不要写成"没有"就过去;真的没有也要说清楚你是怎么避免"看着实现写期望"的。
