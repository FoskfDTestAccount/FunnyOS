## 二、核心问题:REP 前缀

前缀通过 `cpu->prefix.repeat` 到达你手里,只有两个可能的值:

```c
0xF3   REP,或 REPE
0xF2   REPNE
```

**`F3` 同时表示 REP 和 REPE,是同一个字节。** 它到底是什么意思由指令决定:

| 指令 | 有 REP 前缀时 |
|---|---|
| MOVS / STOS / LODS | 重复 CX 次,然后 CX = 0 |
| CMPS / SCAS | 重复,但**同时**在 ZF 不再满足时提前停止 |
| 以上任何一条,`F2` 前缀 | 只有 CMPS/SCAS 有意义:ZF **变**为满足时停止 |

**写成一个函数的后果**:`repe cmpsb` 会一直比到缓冲区末尾,而不是在第一个不同处停下——而"在第一个不同处停下"正是程序用它来做的事(比较字符串)。于是返回值是"恰好全等"或"扫完了",永远不是"第 N 个字节不同"。

### 终止条件的细节

- **`F2` 用在 MOVS 上是未定义的。** 手册不承诺。选一个行为(建议当作 `F3`)、写下来、写测试。
- **停止条件是"ZF 不再满足"**,`F2` 是"ZF 满足"。不要写反。
- **CX 的递减发生在每次迭代之后**,包括最后一次。循环结束时 CX 一定是 0(除非因为 ZF 提前退出,那时 CX 是剩余次数)。

### `rep` 与 CX = 0

**检查必须在第一次迭代之前。** CX=0 的 REP 执行**零次**,不是一次,不是死循环。

一个"至少执行一次"的实现(比如 `do { } while (--cx)`)在这里会溢出——CX 从 0 减到 0xFFFF,然后搬运 65535 次。这是最经典的 REP bug。

## 三、方向标志

- **DF = 0**:向前,SI 和 DI **递增**
- **DF = 1**:向后,SI 和 DI **递减**

两者都合法,两者都被用。`std` / `cld` 是 M3 任务 D 的(D 归属 `F8-FD`),但你要读 `cpu->flags & VM86_DF`。

**递增量是元素宽度**,不是字节:字操作是 ±2,字节操作是 ±1。

写反的后果是:对**对称**的缓冲区看起来完全正常(回文、全零、全相同),然后在真实数据上错。所以测试里必须有一个**非对称**的用例,并且两个方向都要测。

## 四、段规则不是统一的

这是最容易搞错、也最难调试的部分。

| 指令 | 读自 | 写往 |
|---|---|---|
| MOVS | **DS**:SI(可被前缀改变) | **ES**:DI(**不可**被前缀改变) |
| CMPS | **DS**:SI(可被改变) | 只读,不写 |
| LODS | **DS**:SI(可被改变) | — |
| STOS | — | **ES**:DI(**不可**被改变) |
| SCAS | — | 只读,不写 |

三条结论:

1. **SI 永远是 DS 侧的指针,DI 永远是 ES 侧的指针。** 不管操作数是"源"还是"目的"。
2. **写永远经过 ES,而 ES 不能被段超越前缀覆盖。** 也就是说 `es: movsb` 是可能的(它改变的是 DS 侧),但没有办法让 MOVS 写到 DS 去。
3. **`SCAS` 拿 AL/AX 和 `ES:[DI]` 比;`CMPS` 拿 `DS:[SI]` 和 `ES:[DI]` 比。** 两边都用 DI 的是 SCAS。

要做这一点,你需要 `vm86_effective_seg(cpu, VM86_DS)` 来拿"被前缀改过之后的 DS",而 ES 直接用 `vm86_get_seg(cpu, VM86_ES)` —— **不要**对它用 `vm86_effective_seg`,那会让 `es:` 前缀错误地作用到写操作上。

## 五、哪些设置标志位

| 指令 | 标志位 |
|---|---|
| MOVS / STOS / LODS | **不动任何标志位** |
| CMPS / SCAS | 像 `CMP` 一样设置全部算术标志位 |

CMPS 和 SCAS 本质上就是 CMP,只是操作数来自内存。**不要重新实现标志位计算**——用 `vm86_alu(cpu, VM86_ALU_CMP, width, dst, src)`。它已经处理好了借位和溢出。

这也是为什么 `repe cmpsb` 能工作:每次比较都更新 ZF,而循环条件读的就是 ZF。

## 六、一个已知的实现取舍

真实的 8086 上,一条带 REP 的串操作**可以被中断打断**(每次迭代之间会检查中断)。这意味着一次 `rep movsw` 搬一兆字节不会阻塞中断。

**本实现不做这件事**,整个 REP 循环在一次 `vm86_step()` 调用里跑完。原因是没有中断模型(那是 M4),而现在加一个"可中断的长指令"机制,会在 M4 把它重写掉。

**但这个偏差要写进代码注释和报告里**,因为 M4 必须解决它:否则一个搬运大缓冲区的 DOS 程序会让定时器和键盘失灵几百毫秒。这是真实的 DOS 程序会遇到的(任何读大文件的操作)。
