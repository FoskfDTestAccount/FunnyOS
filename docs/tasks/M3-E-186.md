## 一、你为什么要做这个

DESIGN.md 把 80186 的扩展放在**"必须做"**那一档,理由不是"完整性好",而是:

> 到 1980 年代后期,大量 DOS 软件在编译时就把 186 或更高当作最低配置——因为那是编译器瞄准的下限。用 `PUSHA` 的程序不是稀奇的古董。

所以这些是普通指令,不是展品。

| 操作码 | 指令 |
|---|---|
| `60` | PUSHA |
| `61` | POPA |
| `62` | BOUND |
| `68` | PUSH imm16 |
| `69` | IMUL r16, r/m16, imm16 |
| `6A` | PUSH imm8 |
| `6B` | IMUL r16, r/m16, imm8 |
| `6C` `6D` | INSB INSW |
| `6E` `6F` | OUTSB OUTSW |
| `C8` `C9` | ENTER LEAVE |

**`C0`/`C1`(立即数移位)不在这里。** 虽然它们也是 186 加的,但它们是移位,helper 在 `ops_alu.c`,归任务 A。如果你在这里也认领它们,`vm86_ops_build()` 会在启动时报冲突——这是好事,但不如一开始就别写。

## 二、坑

### 1. PUSHA 压的 SP 是**最开始的**那个

`PUSHA` 的压栈顺序是:

```
AX  CX  DX  BX  SP  BP  SI  DI
```

**注意这个顺序和汇编里写的顺序不一样**——它是寄存器编码顺序。

而且:**压进去的 SP 是第一条 push 之前的值**,不是压到一半时的值。

一个"顺手用 `vm86_push16(cpu, cpu->sp)`"的实现会得到错误的值,因为那时 SP 已经被前面四次压栈改过了。正确的做法是**先把原始 SP 存下来**。

注意别和 `PUSH SP` 混淆:8086 上 `PUSH SP` 压的是减完之后的值(见 `ops_mov.c` 的注释),而 186 的 `PUSHA` 压的是**减之前**的值。**这两条规则不一样**,因为它们来自不同的指令、不同的年代。不要试图统一它们。

压进去错值的后果:除非程序真的用了那个被保存的 SP,否则完全看不出来。很多程序确实不用——所以这个 bug 会活很久。

### 2. POPA 读到的 SP 要**丢掉**

`POPA` 按同样的顺序弹出八个寄存器,但**读到的 SP 值必须被忽略**:

```c
cpu->di = vm86_pop16(cpu);
cpu->si = vm86_pop16(cpu);
cpu->bp = vm86_pop16(cpu);
(void)vm86_pop16(cpu);      /* SP: 读出来就扔,不要写回 cpu->sp */
cpu->bx = vm86_pop16(cpu);
cpu->dx = vm86_pop16(cpu);
cpu->cx = vm86_pop16(cpu);
cpu->ax = vm86_pop16(cpu);
```

一个"对称实现"会在最后写回 SP,于是把栈指针破坏掉。这是**非常壮观**的失败方式,而且会在 PUSHA/POPA 配对使用的地方立刻暴露——所以它反而比坑 1 容易发现。

### 3. ENTER 的嵌套层级不能只实现 0

`ENTER imm16, imm8`:第一个操作数是**局部变量字节数**,第二个是**嵌套层级**。

层级几乎总是 0,而 0 的情况简单到让人想"就实现 0 吧"。**不要**:

- 层级 0 和层级 1 的行为不同
- 真实编译器会生成 0
- 会生成非 0 的那个程序,得到的是**损坏的栈帧**而不是明显错误

嵌套的循环是八行,而替代方案是八行猜测。查手册(A-1 或 ENTER 条目下有伪代码),照着写。

`LEAVE` 是 `ENTER` 的逆,三件事:`SP ← BP`,然后 `pop BP`。

### 4. BOUND 是这里唯一会触发异常的

`BOUND r16, m16&16`:

- 从内存读**两个字**:下界和上界
- 和寄存器里的值做**有符号**比较
- 超出范围 → **向量 5**(`VM86_VECTOR_BOUND`,在 `ops.h` 里)
- 在范围内 → 什么都不做

三个细节:**有符号比较**(不是无符号)、**下界在前**(内存里低地址那个字是下界)、**两个界都含在范围内**。

### 5. 多操作数 IMUL 和一操作数 IMUL:语义不同,但 CF/OF 是**同一条规则**

| 形式 | 结果 | CF/OF |
|---|---|---|
| `IMUL r/m16`(在任务 A 的 `F6/F7` 里) | **DX:AX** 32 位积 | 结果放不下 16 位则置 1 |
| `IMUL r16, r/m16, imm16`(这里) | **r16** 16 位截断积 | **同上,同一条规则** |

**两个形式的结果不同,但 CF/OF 表达的是同一件事**:乘积能否用**有符号 16 位**表示。既然表达的是同一件事,两处的实现就不能不一致——否则 `imul bx` 和 `imul bx, 3` 会对同一个乘积给出不同的标志位。

**关键是"有符号"这三个字。** 不要说成、更不要实现成"高半部分非零",那对负数乘积是错的:

```
-2 × 3 = -6   →  DX:AX = FFFF:FFFA
                 高半部分是 0xFFFF,非零 —— 但它是低半部分的符号扩展
                 结果放得下,CF/OF 必须是 0
```

参考实现是任务 A 的 `op_group3()` 里的 `case 5`。**不要自己另写一套**——两个形式必须落在同一条规则上,而两份独立实现不会保持一致。

### 6. PUSH imm8 的立即数要符号扩展

`6A 05` 压的是 `0x0005`,但 `6A FB` 压的是 **`0xFFFB`**,不是 `0x00FB`。

用 `vm86_sign_extend8()`(在 `decode.h` 里)。

### 7. INS/OUTS 是串指令,而且可以带 REP

`6C`/`6D` 从端口读进 `ES:DI`,`6E`/`6F` 从 `DS:SI` 写到端口。端口号在 **DX**。

它们和任务 C 的串指令**共享同一套 REP 逻辑和方向标志规则**:

- `DF` 决定 SI/DI 递增还是递减(±1 或 ±2)
- `REP` 前缀让它们重复 CX 次,CX=0 时执行零次
- `INS` 用 **ES:DI**(写),`OUTS` 用 **DS:SI**(读)

**REP 循环已经交付,不要自己写。** `ops.h` 里有 `vm86_str_repeat()`,直接调用:

```c
static void outsb_body(struct vm86_cpu *cpu, uint8_t bits, int16_t delta,
                       enum vm86_seg source)
{
    /* read DS-side memory at source:si, write it to the port in DX,
       then advance si by delta */
}

static enum vm86_result op_outs(struct vm86_cpu *cpu, uint8_t opcode)
{
    return vm86_str_repeat(cpu, (opcode & 1) ? 16 : 8, outsb_body, false);
}
```

四个要点:

- **`conditional` 传 `false`** —— INS/OUTS 没有比较,REP 就是纯计数。传 `false` 时 `F2` 自动等价于 `F3`,不需要你分支。
- **`source`** 是循环替你算好的 DS 侧段(段超越已应用)。`OUTS` 用它读;`INS` 没有 DS 侧操作数,`(void)source;` 即可。
- **`delta` 已经带符号**,`si = (uint16_t)(si + delta)` 就行 —— 不要自己再去判 `DF`。
- **不要读 `cpu->prefix`,不要动 `CX`** —— 这两件事由循环负责。

`ops.h` 里那段注释是完整契约(包括"被 ZF 提前打断时 CX 里剩下什么"),读它。**契约缺了什么就报告,不要绕过去自己写一份** —— 这个函数存在的全部理由就是防止有第二份。

顺带:**端口还没有实现**(M4 才有设备)。和任务 D 的 `IN`/`OUT` 用同一套决定——见那份任务书第三节。
