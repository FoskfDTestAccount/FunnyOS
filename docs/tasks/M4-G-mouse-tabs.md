# M4-G —— PS/2 鼠标与多标签终端页面

**这份文档要回答的是**：这两件事怎么塞进 M4。M4 已经以 `v0.4.0-m4` 发布过了，所以它不是那批工作的一部分，而是**一个追加包**：做完按 `v0.4.1-m4` 发。

**为什么是 M4**。M4 的句子是"一台 IBM PC 兼容机"。它做齐了固件（`INT 10h/13h/16h/1Ah`），键盘是真设备、真中断。**鼠标是缺的那一个设备**——PS/2 鼠标和键盘共用同一个 8042 控制器，只是另一个端口、另一条 IRQ，所以它是同一类东西，不是新的一类。而多标签终端是**第一件真的用到指针的 FunnyOS 自己的界面**。

两者因此是一包：鼠标让标签页可点，标签页让鼠标有用。

---

## 一、起点

| | 现状 |
|---|---|
| **键盘** | `kernel/console/kbd.c`：8042 的**端口 1**，IRQ **1**，经 IO APIC 路由；解码 set-1 扫描码；有环形队列、有 `kbd_selftest` |
| **鼠标** | 什么都没有。8042 的端口 **2**（AUX）从未被使能过 |
| **屏幕** | `kernel/console/fb.c` 一块字符网格；`screen.c`（W2 新增）一个持有者、一块屏幕。**没有"页"的概念** |
| **指针** | 没有。`fb.c` 的文件头写着一条硬约束：**绝不从 `g_addr` 读**（WC 内存，读一次是一次未缓存事务，这是它曾经打印一行要六十秒的原因） |
| **测试手段** | `run-input-test.sh` 已经会**经 QEMU monitor 在键盘上打字**并断言。鼠标用同一条路（`mouse_move` / `mouse_button`） |

## 二、工作包

顺序按**谁挡着谁**排。G1 先做，因为它是唯一一个**不依赖显示就有一个干净、独立的验证**的。

### G1 鼠标设备：8042 端口 2 + IRQ 12 + 报文解码

**要做的**：

- 使能 AUX 端口。8042 的命令字节（读 `0x20` / 写 `0x60`）里有"使能 AUX 中断"和"关闭 AUX 时钟"两位，先设对；再向鼠标发 `0xF4`（开始上报）。
- **难点不在时序，在复用**：这一个控制器有两个端口、**一个输出缓冲**。状态寄存器 0x64 的 bit 5 说明"这颗字节来自 AUX 还是键盘"。字节不排空就会丢，而丢一个字节会把整个报文流错位——这正是 `kbd.c` 里"处理程序排空而不是读一个字节"那条注释说的同一件事，只是现在有两个来源。
- 报文解码：标准 3 字节报文。**byte 0 的 bit 3 必须是 1**，不是就说明这不是报文头，丢掉重新同步。X/Y 是 9 位有符号（符号位在 byte 0 的 bit 4/bit 5）。
- **Y 轴是反的**：线上 Y 增大是"往上"，屏幕坐标往下增大。这条写在这儿是因为它是**最容易写错又最容易被当成"鼠标坏了"**的一条。
- 事件队列，形状照抄 `kbd_poll()`。
- IRQ 12 经 IO APIC，路由方式和 IRQ 1 一样。

**验收怎么判**：经 QEMU monitor 发 `mouse_move dx dy` 和 `mouse_button 1`，内核把**累计位移和按键状态**打进串口，测试断言那几个数。位移**互不相同且非零**（`dx=7, dy=-3` 之类），否则"没坏"和"根本没测到"分不开——这条规矩项目里已经有了。

**挡住**：G2 和 G4。

### G2 屏幕上的指针

**要做的**：指针画在**两个表面之上**——控制台的日志、或者一个 guest 的页。移动它要把离开的格子按**权威缓冲**重画，而不是把底下的像素存下来再贴回去。

**为什么不是存底色**：`fb.c` 的硬约束是"绝不从 `g_addr` 读"。存下来就得先读回来，一次移动读 16×16 个未缓存像素，正是这个文件存在的理由的反面。所以指针必须是**覆盖式的**：谁在画，画完最后画指针；指针移动时，离开和进入的格子由那层的权威数据重画。

这要求 `fb.c` 多一个能力：**按权威网格重画一块矩形**。W2 加的 `fb_draw_page` 已经是这个形状了（对 guest 页而言），控制台自己的网格需要一份对等的。

**难点是一致性**：指针覆盖在两层之上，于是**两条绘制路径最后都得调用同一个"把指针画回去"**。这是"同一个事实两个写者"的老毛病，要在设计上堵死：重画的入口只有一个。

**验收怎么判**：截图。指针在某处、移动后不在原处；再加一条**结构性断言**——指针覆盖的那块像素必须和底层网格推出来的不一样，否则"画了指针"和"什么都没画"分不开。

### G3 控制台的多标签页

**这是这一包里最大的一块，因为它动的是"所有东西都从这里打印出去"的东西。**

**要做的**：

- **控制台的网格从 `char` 变 16 位**（字符 + 属性）。这是让"日志页"和"guest 页"变成**同一种东西**的前提，也是 G3 唯一一个会碰到全部打印路径的改动。属性渲染的调色板已经在 W2 里落进 `fb.c` 了。
- **页表**：`struct screen_page { used, name[], cells[] }`。日志是第 0 页，永远存在。被持有的页进入这张表。
- **标签栏**：一行，列出现有的页，高亮当前页。**只在有多于一页时出现**——这条规则让今天只有日志页的启动画面一个像素都不变，也让 `docs/screenshot-*.png` 那一批不用重拍。标签栏出现时可用行数少一行，所以行数必须**只有一个地方算**。
- **切换**：键盘（`Alt+1..9`，`kbd.h` 的键码层已经有 `ctrl`/`alt`；控制台在交给行编辑之前先看这些键）和指针（点标签栏）。
- **按住不放的规矩**：切换**不能把按键喂给正在持有屏幕的程序**。这不是细节，是 G4 里那个"切走了正在跑的 DOS 程序、它却收到了你按的 Alt+2"的 bug。

**这里有一件必须现在写下来的事，因为它改变了 W2 的一个性质**：

> W2 的 `screen_present` 是**直接从调用者的内存画**的，没有拷贝。这在"只有一页、且正在被显示、且 presenter 还活着"时是对的。**一旦一页可以被切走再切回来，它就不对了**——切回来的时候要重画，而那时调用者的内存可能已经属于别人。
>
> 所以 G3 必须让内核**在 present 时把页拷进自己的缓冲**。4000 字节一次，而 VM 只在页变化时才 present，代价可以接受。
>
> 而代价是**一句话要改**：W2 的"屏幕是 guest 内存的相片是**结构性的**"（因为传的就是那个指针）会变成"内核持有副本，画的是副本"。后者是**更弱的**断言，需要它自己的验证。W2 的验证方式（`check-screen-pixels.py` 逐扫描线比对）本来就是从截图读的，不依赖这一点，所以这个改动不会削弱 W2 已有的验证——但**W2 的文档里那句"结构性的"要跟着改**。

**验收怎么判**：内核每切换一次打一行串口；`run-screen-test.sh` 扩展成**切一次、截一次图**，每次的截图都要通过同一套像素检查。加上一条"标签栏只在多于一页时出现"的断言（单页启动的截图与旧版逐字节相同）。

### G4 指针点标签

**要做的**：标签栏出现时，点击落在标签栏上就切换；点到别处就交给当前的持有者（如果它要鼠标）。命中判定是**第一个**需要"屏幕坐标 → 单元格"的地方，而单元格尺寸**不能写死**——`check-screen-pixels.py` 就是这么算的（`fb 宽 / 网格列数`），这里用同一套。

**挡住**：没有，但它是这一包的意义所在。

## 三、不做的

- **`INT 33h`（DOS 鼠标驱动）**。那是**驱动，不是固件**：真机上它是 `MOUSE.COM` 提供的。所以它属于 M5/M6，和 `INT 21h` 同一层。M4-G 给的是**宿主**的一只鼠标；让 guest 能用上，还要 8042 的**寄存器级 guest 模型**和 VM 进程里的 `INT 33h` 服务，那是 M6 的事，且依赖 W5/W6 的设备层。
- **滚轮、第四第五键**。IntelliMouse 是 4 字节报文的扩展协议，要在使能序列里额外协商。先只做 3 字节。
- **图形模式下的指针**。现在没有图形模式。

## 四、风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| **8042 的 AUX 使能序列在各家用不同** | 中 | QEMU 实现的是标准序列。项目已经在 VMware 上栽过一次（`Makefile` 里那段关于 El Torito 的注释），所以**要在 QEMU 之外至少试一次真机或 VMware**，并把结果写下来 |
| **一个输出缓冲、两个来源** | 中高 | 排空逻辑要**一起**处理两个端口，否则丢一个字节就会让报文流永久错位——而症状是"鼠标偶尔乱跳"，这是最难查的那一类 |
| **G3 动的是全部打印路径** | 高 | 它是这一包唯一一个会碰到一切的东西。要分两步：先把网格改 16 位（这一步不改任何行为，日志页的属性就是今天的那对颜色），再加页表 |
| **指针与两层的重画一致性** | 中高 | 重画入口只留一个，见 G2 |
| **标签栏改变可用行数** | 中 | 只在多于一页时出现；行数只有一个地方算 |

## 五、和 M5 的关系

G1、G2 与 M5 无关，可以随时做。

**G3 与 M5 有耦合**，就一处：它要求 `screen_present` 改成拷贝。改动本身小（一次 `memcpy`），但**它出现的位置是 M5 正在用的那条链路**，所以要么在 M5 的显示部分稳定之后做，要么现在就把那句话写对。**倾向后者**——W2 的文档里"结构性的"那句现在就该改成"只要页还在调用者的内存里就是这样"，免得 G3 的时候才发现有一句话是旧的。

（这正是那条老规矩：**过期的说法会在最坏的时刻说话**。）
