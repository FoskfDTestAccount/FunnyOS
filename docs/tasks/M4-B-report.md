## 一、实现了哪些命令码

全部在 `dos/bios/bios10.c`,由 `bios10_service(cpu, ctx)` 一个入口按 `AH` 分发。

| AH | 名字 | 状态 |
|---|---|---|
| `00h` | 设置模式 | 文本模式 `00h`/`01h`(40×25)、`02h`/`03h`(80×25);`AL` bit 7 = 不清屏;**图形模式整个忽略** |
| `01h` | 设置光标形状 | CH 起始 / CL 结束扫描线,同步 `0040:0060` |
| `02h` | 设置光标位置 | DH 行 / DL 列 / BH 页 |
| `03h` | 读光标位置与形状 | 返回 DH/DL、CH/CL;BH 与 AH 保持 |
| `05h` | 选择活动页 | AL 页号;超范围丢弃 |
| `06h` | 窗口上滚 | AL 行数(0 = 清窗口)、BH 填入属性、CH/CL 左上、DH/DL 右下 |
| `07h` | 窗口下滚 | 同 `06h`,方向相反 |
| `08h` | 读光标处字符与属性 | **AL 字符 / AH 属性**(两个都改 AX) |
| `09h` | 写字符**与属性** | AL 字符、BH 页、BL 属性、CX 次数;**光标不动** |
| `0Ah` | 写字符(**保留属性**) | 同上但保留原属性;**光标不动** |
| `0Eh` | 电传输出 | AL 字符;**光标前进**;控制字符按真机处理 |
| `0Fh` | 取当前模式 | **AL 模式 / AH 列数 / BH 活动页**(三个都是结果) |

另外导出:任务书第二节要的三个访问器 `bios10_reset()` / `bios10_cursor_cell()` / `bios10_active_page()`,以及**由我在 `bios10.c` 里定义的 `vm86_display_present()`**(`display.h` 声明,实现只有"判空 + 调用"一行)。

`struct bios10_state` 是**调用方拥有**的完整类型(定义在 `bios10.h`),不是模块里的 `static`;测试里同时开了两个也没问题。

## 二、`0Eh` 的三条关键规则,以及它们分别来自哪

### 1. 文本模式下**不写属性字节**,`BL` 不被读

**【查证 + 二手,两处源码一致】** 两份独立实现的源码都是这个行为:

- **vgabios(QEMU)** — `biosfn_write_teletype(car, page, attr, flag)`,`0Eh` 以 `NO_ATTR` 调用;文本模式下只有 `if (flag == WITH_ATTR)` 才写 `address+1`,所以**属性字节原样不动**。
- **SeaBIOS** — `handle_100e` 构造 `struct carattr ca = {regs->al, regs->bl, 0}`,第三位 `use_attr = 0`;`vgafb_write_char()` 在 `use_attr == 0` 时**只写字符那一个字节**。
- **【二手】** UMBC CMSC 211 讲义把这个功能标题写成 *"Display Character using **Present Attribute**"*,入口表里**根本没有 `BL`**。

"不能用 `0Eh` 打彩色字,要上 `09h`" 是这个行为的通俗说法,和上面一致。

**这条和任务书原稿冲突,任务书是对的、原稿是错的** —— 协调方已在 `main@98140cd` 勘误,详见第四节。**我的实现从一开始(收到勘误之前)就是这个行为**:我在读任务书时就按项目规矩去查证了它,查完发现原稿写反了。

**后果不是装饰性的:** 一个先在整屏用 `09h` 铺了彩色属性、再用 `0Eh` 在上面打字的程序,按 `BL` 实现会把那些颜色擦掉——而**只在一个空白屏(属性本来就是 `07h`)上打字的程序,两种实现看起来一模一样**。也就是说按原稿写的实现能通过任何一个人顺手写的测试。

### 2. 屏幕底部上滚,和 `06h` **共用同一份实现**

**【二手,dos-refs.md §1】** "`0Eh` 在屏幕底部时靠内部转调 `06h` 完成上滚"。

代码形状照这条办:`teletype_scroll()` **没有自己滚**,它算出填入属性以后转调 `scroll_window()`——也就是 `06h`/`07h` 用的那一个函数。这是 M4-README 第三节第 3 条"不要写第二份共享实现"的直接应用。

### 3. 滚动时的填入属性 —— **【我们选的】**

**两个能工作的实现在这里互相矛盾,而 Ralf Brown 没有裁定:**

| 实现 | 填入属性 |
|---|---|
| **vgabios(QEMU)** | 从光标落点**上一行的那个单元里读**属性 |
| **SeaBIOS** | 固定 `0x07` |

**我们跟 vgabios**:填入属性 = 光标移动后所在列、在**窗口最下一行**那个单元已有的属性。理由:它和 `0Eh` 本身"保留单元属性"的主题一致——用同一种颜色打字的屏幕,滚动出来的空行也是那种颜色。SeaBIOS 的做法也记在这里,因为这个选择随时可以翻。

**这一条是"我们选的",不是"手册规定"。** `dos-refs.md` 没有覆盖它。

## 四、和任务书 / 参考文件不一致的两处

### 1. `0Eh` 的属性来源 —— 任务书原稿错,已勘误

原稿写"属性用 BL"。**我独立查证后实现的与之相反**(保留单元原属性),随后协调方在 `main@98140cd` 用 `docs/dos-refs.md` §1 勘误了同一条。

**两件事需要写清楚:**

- 我在收到勘误**之前**就已经按这个行为写完了 `bios10.c`——不是事后改的。
- 这一条**不能靠"两种实现都能过测试"糊过去**:它的可观测差别只在"屏幕上有非默认属性"时才出现,而这正是 `dos-refs.md` §1 点名的那种"错得很有自信"的形状。测试里 `0Eh keeps the attribute already in the cell` 就是专门照这个形状写的:先把单元涂成 `0x1E`,再把 `BL` 设成 `0x4F`,断言单元**保住了 `0x1E`**。

### 2. `0040:0060` 的字节序 —— 我们按 big-endian 写,**和任务书相反**

任务书表格里写"光标形状,一个字(**起始在低字节**)"。**我们写成"起始在高字节"**,也就是这个字就是 `CX` 本身(`CH` 起始、`CL` 结束)。

**依据:** Ralf Brown 的 `MEMORY.LST` 把 `0040:0060` 标为 **big-endian** 并注明"contains cursor start scan line and cursor end scan line"——`AH=01h` 从 `CH:CL` 取、`AH=03h` 原样放回 `CX`,`[0040:0060] = CX` 是最自然的实现,内存里低字节就是 `CL`(结束扫描线)。Norton 的表述("结束扫描线先存")与之一致。

**`dos-refs.md` §7 只写了"光标形状(起始扫描线 / 结束扫描线)",没有写这两个字节谁在低**——所以这一条既不在任务书的勘误里,也不在参考文件里,**是我自己查证后做的决定,提请复核**。

**后果:** 一个直接读 `0040:0060` 的程序会拿到**高低互换**的形状字。实践上:大多数程序通过 `03h` 读它(那样两者一致),但**直接读内存的那一类会错**。测试 `01h sets the shape and can hide the cursor` 把两个字节分别钉死(`0040:0061 == 0x20`、`0040:0060 == 0x00`),所以如果复核认为应当反过来,改这一处 + 改那条断言即可。

## 五、没实现的 AH,以及为什么

| 没实现 | 为什么 |
|---|---|
| `04h` `05h`(图形模式子集)、`0Bh`(调色板)、`0Ch`/`0Dh`(写/读像素)、`10h`–`1Ch`(VGA) | **M4-README 第八节划在范围外**,M7 做。M4 不做重定向(M4-8),没有图形帧缓冲可写。 |
| `04h` 在不少资料里是"读像素"、`05h` 是"选页"——**注意 `05h` 我实现了**(它是文本模式的选择活动页);`04h`/`06h`/`07h` 在这些资料里是图形模式子集 | 同上。`06h`/`07h` 我按**文本模式的窗口滚动**实现,这是它们在文本模式下的含义。 |
| `1Ah`/`1Bh`(读/写显示组合码,EGA/VGA 才需要) | M7。 |
| `12h`/`13h` 等"扩展" | 不是文本模式视频 BIOS 的功能。 |

**没有实现的 `AH` 会落到 `bios10_service()` 的 `default` 分支:什么都不做,一个寄存器也不改。**

这一点需要和"M4-README 第八节说的注册表里没有的服务"分清楚:

- **`INT 10h` 这个向量是注册了的**(E 接线时注册 `bios10_service`)。所以打到 `INT 10h` 的**任何** `AH` 都会进我的函数,包括我没实现的那些。
- 我的 `default` 分支**故意什么都不做**:软件探测某个 BIOS 扩展在不在,手法就是调一下看返回什么;一个"顺手写点什么"的桩会让程序相信有它其实没有的硬件。测试 `an unknown function changes nothing` 把 `AX`/`BX`/`CX`/`DX` 全部钉住。

### 关于"收到图形模式怎么办" —— 三个选项里选了什么

**选:什么都不做**(模式字、屏幕、BDA 全部不动)。

三个选项的后果:

| 选项 | 后果 |
|---|---|
| **静默忽略(选它)** | 程序留在它原来的文本模式里,输出好歹还去屏幕。 |
| 改 BDA 模式字、显示不动 | **最坏**。程序以为自己在模式 12h,把 `0xA0000` 当线性帧缓冲写,写到一片没有任何东西渲染的内存里。接下来一百次写都"看起来成功",故障在离原因很远的地方冒出来。 |
| 拒绝 | `INT 10h AH=00h` **没有错误返回通道**,拒绝不了。 |

测试 `00h refuses a graphics mode by doing nothing` 除了断言模式和列数没变,还**专门断言了屏幕内容没被清掉、`0040:0049` 里也没有记下 `13h`**。

## 六、宿主后端要做什么(E 按这一节接线)

### 调用形状

**显示不由服务驱动。** 程序可以直接往 `0xB8000` 写(很多程序就是这么干的),那种写不经过任何服务,所以宿主必须在**自己的节奏**上刷新:

```c
const uint8_t *cells  = bios10_active_page(cpu, &st);   /* 可能为 NULL */
uint16_t       cursor = bios10_cursor_cell(cpu, &st);   /* 可能是 VM86_DISPLAY_NO_CURSOR */
vm86_display_present(&display, cells, cursor);
```

`vm86_display_present(display, cells, cursor)` 在 `display`、`display->present`、`cells` **任一为 NULL 时都是 no-op**。无头测试直接传 `NULL` 就行,不用在每个调用点写判断。

### `cells` 是什么

活动页在 guest 内存里的地址。布局就是 `firmware.h` 写的那套:**字符在低字节、属性在高字节(字符/属性交替),从左到右、从上到下**。两边都不用转换。

### 宿主**必须**知道的两件事

1. **要读多少个单元:`st.columns * BIOS10_ROWS`(25)。**
   - 80 列 → 2000 个单元(4000 字节)
   - 40 列 → 1000 个单元(2000 字节)

   **不是一个常数**——40 列是这台机器支持的合法模式,`00h` 就能切过去。

2. **页与页之间不连续,不要假设 `cells + 4000` 是下一页。** 页的步长是 `st.page_bytes`(`0040:004C`):80 列是 **4096**、40 列是 **2048**。一个 80 列页的内容只有 4000 字节,后面 96 字节是填充。

   宿主不需要自己算这个——`bios10_active_page()` 已经把它算好了。**宿主唯一需要从 `st` 里读的字段就是 `columns`**(想显示当前模式/页号的话,再读 `mode` 和 `active_page`)。其余字段是 BIOS 自己的事。

### 指针的生命周期

`cells` 指向 **guest 内存**,在调用期间有效。宿主想留着它**必须拷贝**——guest 会继续写那块内存。

### 光标

`cursor` 是单元索引(`row * columns + col`),不是"要不要画"的布尔。`VM86_DISPLAY_NO_CURSOR` 表示**不画**,有两种来路:程序把光标关了(`CH & 0x20`,或者起始扫描线 > 结束扫描线——`MOV CH,20h` 那个经典写法),或者程序把光标设到了页外。宿主自己决定画成什么样子。

### ⚠️ 上电时必须清屏 —— E 特别注意这一条

**`bios10_reset()` 只重置状态结构,不碰 guest 内存。** 真正的清屏是**设置模式**做的(`INT 10h AH=00h`),这也是真机 POST 做的事。

**如果验收程序不先设模式就直接 `0Eh` 打字,屏幕属性就是内存里的原值**——测试内存是清零的,也就是 **`0x00`(黑底黑字),什么都看不见**。

我最初的实现里 `0Eh` 是"保留单元原属性"(见第二节),这个行为和"机器上电时屏幕被清成 `0x07`"是配套的:

- **验收程序应当先 `mov ax, 0003h; int 10h`**(真程序都这么干,它顺便清屏);
- 或者**宿主在上电路径上空跑一次模式设置**。

两条任选其一。**别只做 `bios10_reset()` 就开始跑程序。**

### 属性字节

低 4 位前景、bit 4–6 背景、bit 7 闪烁(或高亮背景)。宏在 `firmware.h`(`VM86_ATTR_*`)。

## 七、变异测试:每条用例都证明了它能红

12 个变异,逐个注入、`make -B` 强制重建、看哪些用例报红,然后还原。**全部被捕获。** 基线在注入前后都是绿的。

| 注入的错误 | 被哪些用例抓住 |
|---|---|
| `0Eh` 改成用 BL 当属性 | 4 条(含专门的 `0Eh keeps the attribute…`) |
| `0Eh` 不推进光标 | 6 条 |
| `0Eh` 写到 `BH` 的页而不是活动页 | `05h selects a page and 09h writes on it` |
| `0Eh` 的 BS 在列 0 回绕到上一行 | `0Eh backspace stops at column zero` |
| `0Ah` 顺手把列也归零 | `0Eh line feed and carriage return move different things` |
| `06h` 的 `AL=0` 当成"滚 0 行" | `06h with AL=0 clears the window` |
| 页步长改成 4000 | 3 条(含 `the active page is at the right address`) |
| `03h` 答的是另一页 | 2 条 |
| 不往 BDA 同步 | 3 条 |
| 未知 `AH` 顺手把 `AH` 清零 | `an unknown function changes nothing` |
| 图形模式改成"记下模式号" | `00h refuses a graphics mode by doing nothing` |
| `00h` 的 `AL` bit 7 失效(总是清屏) | `00h with bit 7 set keeps the screen` |

**一个假阴性来自 `-Werror`:** "`03h` 答的是另一页"的第一个写法让参数 `page` 变成未使用,`-Werror=unused-parameter` 直接编译失败——**编译失败不是"用例抓住了"**,换了一个仍然用到 `page` 的等价写法才真的跑起来并报红。这和 M3 那次记录的假阴性来源是同一个。

**过程中还修掉了两条自己写错的断言**(都是测试的错,不是实现的错):

- page 0 的光标已被前一个 `0Eh` 推进到第 1 列,我却断言 `09h` 写在原点;
- 在最后一行打字时,字符是**先写、后滚**,所以它"上移一行",我却断言它在最后一行。

另外删掉了一条**恒真断言**(`expect(f.cell[0][0], f.cell[0][0])`)——按 M4-README 第四节第 6 条,永不会红的用例比没有更糟。

## 八、任务书没写、我踩到的

1. **`0Eh` 在最后一行:字符先写进最后一格,然后才上滚。** 结果字符出现在**倒数第二行**的同一列,光标落在最后一行的行首。这是终端该有的行为,但和"整屏上移、最后一行是空的"的直觉描述不完全一样——测试按语句顺序钉住了它。

2. **`09h`/`0Ah` 走到屏幕底部是"停住",不是"滚动"。** 滚动是 `0Eh` 的行为。这是"两条不同规则"的第二半,任务书只写了"光标不动"那一半。

3. **`09h`/`0Ah` 在行尾会回绕到下一行。** 任务书没说。不实现回绕的话,一个用 `09h` 画满整屏的程序只有第一行是对的。

4. **`0Eh` 的 `09h`(TAB)任务书没列。** 不处理的替代方案是把它的字形打出来,那不是任何真固件做过的事。按 **【查证】** 的 vgabios 实现:写到下一个 8 的倍数为止。

5. **`02h` 允许把光标设到页外。** 真机不校验(它只是存进 BDA,而程序会读回来),所以我也照存。代价是 `bios10_cursor_cell()` 得为此返回 `NO_CURSOR`——**"程序把光标关了"和"程序把光标设到页外了"是两件事,共用同一个常量。**

6. **模式 3 其实只有 4 页可用**(4096 × 8 = 32 KiB > CGA 的 16 KiB 显存)。但 BDA 里就是八个光标字,所以状态里存八个;页 0–7 在**我们的内存模型里**都落在 `0xB8000`–`0xBFFFF` 之内(8 × 4096 = 32 KiB),不会溢到别的地方。这是有意的简化,不是疏漏。

7. **40 列模式的页步长是 2048 而不是 2000**,和 80 列的 4096 是同一个"向上取到 2 的幂"的道理。`dos-refs.md` §7 给了这个值。

8. **`06h`/`07h` 的矩形越界**(行/列超出屏幕、或右下角在左上角之前):**我们选的**是"什么都不做"。夹紧到屏幕内会让一个"滚第 10 到 40 行"的 bug 变成"滚第 10 到 24 行",把 bug 藏起来;什么都不做至少屏幕和程序要求的一致。

9. **`bios10_reset()` 不清屏**(没有内存指针,也不该有)。见第六节那条警告。

10. **测试跨目录 include.** `test_bios10.c` 用 `#include "../bios/bios10.h"`——`dos/Makefile` 的搜索路径只有 `include/` 和 libk,`"..."` 形式会先找本源文件所在目录,这是唯一不用改 Makefile 的写法(Makefile 不是这个任务能改的)。

## 九、我没做、但下游可能想要的

- **`05h` 换页时重编程 CRT 控制器**:真机要写 6845 的寄存器。这台机器没有 6845,状态里的 `active_page` 就是全部。
- **窗口**(`0Eh` 输出被限制在某个窗口内):`dos-refs` 的 Ralf Brown 摘录里提到过,但那是某些机器的行为,M4 的范围里没有可设窗口的入口。**没实现。**
- **`SI`/`DI` 被弄脏**:真机的 `0Eh` 可能改它们(**【二手】** dos-refs §1)。我们**一个都不改**——少弄脏一个寄存器不会让谁出错。

## 十、审查之后的补充(D 找到的覆盖洞,以及两处缺出处)

D 在审这一层时给了三条。**三条我都是先量再改的**,结果有一条和转述不一样。

### 1。`06h`/`07h` 窗口矩形:四个寄存器里有两个没被钉住 —— **确有其事**

D 报的是"`CL` 和 `DL` 恒为 0,所以窗口的左右两个寄存器完全没被钉住"。我自己构造了两个读法注入进去测:

| 注入的读法 | 补充前 | 补充后 |
|---|---|---|
| `(CH,CL)` 当 **(上,左) 互换** | **完全没被抓住** | 被新用例抓住 |
| 四角交叉成 `(CH,DL)-(DH,CL)` | **被 `06h with AL=0` 抓住** | 被两条抓住 |

**所以 D 那条转述过强了一格:两个注入里只有一个真的活下来。** 交叉那一条落在我原来的 `AL=0` 用例上——因为交叉之后 `left > right`,我的实现把非法矩形当"什么都不做",于是那条"窗口被清空了"的断言直接红。这不是运气:非法矩形"什么都不做"本身就是一个能被观测的决定。

补的用例 `06h uses all four corner registers`:窗口取 **行 1..3 × 列 2..4**,四条边外面各放一个标记。四个值互不相同,所以任何一种读法都会让至少一个标记动错。断言从 143 涨到 157。

### 2。`09h` 在屏底停住 —— **决定是对的,但我原来没写出处**

D 读了**我自己引的** vgabios 原文:文本模式下它**既不回绕也不停**,而是按线性地址一路 `+= 2` 写下去,也就是走出页面、走进显存里的下一份东西。我的"停住"与它**对程序可见的每一个单元都相同**,差别只在页面之外的内存——而那里它可能覆盖另一个页,我不能。

**已按"决定"改写注释并注明出处**(第八节第 2 条讲的就是这条规则,现在两边都写了出处)。

### 3。`00h` 的 `AL` bit 7 —— **规则是对的,缺的是那句出处**

我原来断言它是真规则,但没说是谁规定的。D 查了:**vgabios 的 set-video-mode 处理程序里就是 `noclearmem` 那段**,取 `AL` 的最高位决定跳不跳清屏。

**已补进注释。**

### 这三条合起来是一个形状

D 的第三条和协调方自己犯的一处是同一件事:**断言是对的,出处缺了**。一条正确的断言如果说不清为什么正确,下一个读它的人只有"信"和"不信"两个选择——而项目为这个形状已经付过好几次代价。我这次的教训具体一点:**在报告里写"我查证过 X"的时候,把查出 X 的那个地方写出来**(第几节、哪个函数、哪份清单),否则那句话和"我记得是这样"没有区别。

## 十一、D 的第二轮:三处改动(都先查源码再改)

D 的第二轮把 `dos-refs.md` 第一节真的拉下来 grep 了,在 `bios10` 上报了三处。**三处我都自己去读了源码才动**,因为"建议值会被直接照做",而这次要动的是**行为**。

### 1。`06h`/`07h` 的越界矩形:从"拒绝"改成"夹取"

**源码**(vgabios `biosfn_scroll`,我读了开头与循环体):

- 先判 `if (rul > rlr) return;` 和 `if (cul > clr) return;` —— **只有角交叉才原样返回**;
- 然后把**远角**夹进屏幕:`if (rlr >= nbrows) rlr = nbrows - 1;` / `if (clr >= nbcols) clr = nbcols - 1;`;
- 近角**不夹**;
- 逐行规则:`i + nlines > rlr`(或 nlines 为 0)的行填空行,否则从 `i + nlines` 搬过来。

**可达的后果**(D 给的,我认可):**40 列模式下 `DL = 79`**。一个按 80 列写的清屏窗口(行 0..24,列 0..79)在 40 列屏上,真机夹到 39 并清屏,我原来**什么都不做** —— 而那是**标准的清屏调用**,所以我的拒绝会让最需要它的一类程序失灵。

**已改成夹取**,并且**夹完之后再查一次角是否交叉**:`top = 30, bottom = 40` 这种输入夹完会变成交叉,不查的话高度会算成一个巨大的数,然后把**一行不属于窗口的行**擦掉。有专门用例钉住。

**顺带核实(这条没照抄转述):** vgabios 的逐行规则与我原来的 `lines >= height → 清窗口` **处处等价** —— 我给窗口高 h、行数 L,逐行条件 `i + L > rlr` 恰好把所有行都判成空行。所以那一支**不动**。我是读了循环体才敢这么说的。

### 2。`0Fh` 的 `AL` 要带上视频控制位

**源码**(vgabios `biosfn_get_video_mode`,逐条指令):

```
bh = [0040:0062]                ; 活动页
ah = [0040:0087] ; ah &= 0x80   ; 控制字节的 bit 7
al = [0040:0049] ; al |= ah     ; 模式,带上去
ah = [0040:004A]                ; 列数
```

确认:`AL = 模式 | (控制字节的 bit 7)`。一个用 `AL & 0x80` 问"屏幕上还有没有东西"的程序,在原来的实现下**永远拿不到那个信息**。

**已改**。状态里加了 `video_ctl` 字段,`00h` 记下 `AL` 的 bit 7,**`0Fh` 从状态取而不是从数据区取**:状态是这个模块相信的东西,一个在 `0040:0087` 上乱涂过的客人不该能让服务答出一个它自己不会去做的答案。

### 3。`0040:0084` 与 `0040:0087`

**RBIL 确认**:`0084` = "ROWS ON SCREEN MINUS ONE";`0087` = "VIDEO ... CONTROL",bit 7 = "do not clear RAM on mode set"。

`sync_bda` 现在写 `0084 = 24`(最后一行号)和 `0087 = video_ctl`。

**两个偏移不在 `firmware.h` 里**,所以按 `bios16` 对 `0040:0071` 的做法在 `bios10.c` 里就地定义并写明出处 —— **但和那一个有本质区别:这两个真的是视频服务的字段**,没有别人写,也没有别人有更强的声称。

### 4。留给下游的一个点(和第六节那条同类)

**在第一次 `INT 10h` 之前,`0040:0084` 是 0** —— 一台"0 行"的机器,而 `0x87` 是 0。A 的 `vm86_install_firmware` 写了视频字段(模式、列数、页步长、活动页、光标形状、八个光标位置),但**写不了这两个,因为它们不在冻结头文件里**。

我的服务一被调用就会把它们写对,所以窗口只在"程序在第一次 `INT 10h` 之前直接读数据区"时张开。**这和第 6 节那条("装完之后视频字段全是 0")是同一类缺口:谁在上电时种这些字节,需要有人认领。** `firmware.h` 冻着,所以我改不了 A 的文件;记在这里交回去。

### 5。变异

6 个全部被捕获:0Fh 退回裸模式、越界改回拒绝、夹取后不再查交叉、`0x84` 写成行数、模式设置不记控制位、`0x87` 从不写。断言从 157 涨到 **178**。
