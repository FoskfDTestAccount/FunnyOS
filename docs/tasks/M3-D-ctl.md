## 二、坑

### 1. 相对位移是相对于**已经前进过的** IP

```
E8 05 00     call +5
```

那条位移加到的,是**指完这条指令之后**的 IP——也就是说,取完位移之后 IP 已经指向下一条指令了。

```c
int16_t displacement = (int16_t)vm86_fetch16(cpu);
cpu->ip = (uint16_t)(cpu->ip + displacement);   /* 对 */
```

顺序不能反,也不能在取位移之前算。**这条每个模拟器都会写错一次**,而且错的方式很隐蔽:整体偏移 3 个字节,于是只调用错函数,不崩溃。

短跳(`EB`)同理,只是位移是 8 位**有符号**的。用 `vm86_sign_extend8()`——`dos/include/vm86/decode.h` 里有。

### 2. 条件跳转:一个表就够了

`70`-`7F` 的**低四位就是条件编号**:

```c
0  溢出(OF)          4  相等/零(ZF)       8  符号(SF)        12 小于(SF≠OF)
1  不溢出           5  不等/非零         9  非负            13 不小于
2  进位(CF)         6  低于/不进位        10 奇校验(PF)      14 小于等于
3  无进位           7  不低于/进位        11 偶校验          15 大于
```

写一张十六行的条件表,一个函数查表即可。写十六个函数会让"CF 和 ZF 写反了"这种错误有十六次机会发生。

**注意 `2`/`3` 和 `6`/`7` 是同一件事的两个名字**(CF 表示进位,也表示无符号的"低于")。别名不是错误,是 8086 真的把同一个标志位用两种语义命名。

### 3. INT 的入栈顺序和 IRET 的出栈顺序

**`INT n` 压栈的顺序是 FLAGS、CS、IP**(先压 FLAGS)。

**`IRET` 出栈的顺序是 IP、CS、FLAGS**(先弹 IP)。

顺序不一样不是笔误——栈是向下生长的,所以"先压的最后弹"。但这里是**先压 FLAGS 而先弹 IP**,正好是压栈顺序的反序。写反的后果是 IP 变成 FLAGS 的值,看起来像跳到了一个随机地址。

`INT n` 的目标地址来自 **IVT**:guest 内存的 `n * 4` 处,先是 IP(2 字节),然后是 CS(2 字节)。用 `vm86_mem_read16()` 读,注意是**线性地址**(0 段),不需要段基址。

`INT 3`(`CC`)是 `CD 03` 的**单字节形式**——不要给它加一个立即数字节。

### 4. STI 的效果延迟一条指令

真实硬件上,**`STI` 之后的那条指令执行完之前,中断不会被投递**。这不是 bug,是特性,而且是 `sti` / `hlt` 这个空闲循环能工作的原因:

```
sti
hlt        ; 如果 STI 立即生效,hlt 之前的窗口里中断到达就会被正确唤醒
```

如果 STI 立即生效,`sti` 和 `hlt` 之间到达的中断会被处理掉,然后 `hlt` **永远等下去**——因为那个中断已经用掉了。

**M3 没有中断投递**,所以这条现在观察不到。但它必须被建模:在 CPU 状态里加一个"下一条指令之后清除中断延迟"的标志。**这是对冻结接口的改动**——不要自己加,在报告里提出来。

Hmm,等等——读一下 `cpu.h`。如果里面没有这个字段,那这就是一份"需要接口变更"的报告项。**报告,不要自己改头文件。**

### 5. POPF 和 IRET 必须调用 `vm86_flags_normalise()`

这两个都**整体写入标志寄存器**。写完 之后必须调用:

```c
vm86_flags_normalise(cpu);
```

否则客户程序能把"恒为 1"的那些位(bit 1 和 12-15)写成 0——而真实 8086 上这做不到。有的程序正是靠 `pushf` / `pop ax` 检查那些位来判断 CPU 型号的,写错会让它走错代码路径。

### 6. FF 组 5 里有两个是你的,三个不是

`FF` 的八个子操作:

| reg | 操作 | 归属 |
|---|---|---|
| 0 | INC r/m16 | **调用 `vm86_alu_incdec()`** |
| 1 | DEC r/m16 | **调用 `vm86_alu_incdec()`** |
| 2 | CALL r/m16(近) | 你的 |
| 3 | CALL m16:16(远) | 你的 |
| 4 | JMP r/m16(近) | 你的 |
| 5 | JMP m16:16(远) | 你的 |
| 6 | PUSH r/m16 | 你的,用 `vm86_push16()` |
| 7 | (未定义) | 触发无效指令 |

**INC/DEC 必须调用 `ops_alu.c` 里的 `vm86_alu_incdec()`**,不要自己写。标志位必须和 `FE` 产生的完全一致,而两份实现不会保持一致。

顺带:**远 CALL 和远 JMP 的操作数在内存里是"先偏移、后段"**,而汇编里写作 `段:偏移`。这个反序是真实的,查一次反汇编再相信它。

### 7. RET 的栈调整

`RET imm16` 在弹出返回地址之后**还要再加 imm16 到 SP**。这是 `stdcall` 约定用的,忘了它会让调用者的栈逐渐偏移——而且要很多次调用之后才看得出来。

远 RET(`CA`/`CB`)弹的是 **IP、CS**,顺序是 IP 先。

### 8. LOOP 系列

四条都用 **CX 作为计数器,而且先减后判**:

- `LOOP`(E2):CX--,若 CX≠0 则跳转
- `LOOPE`/`LOOPZ`(E1):CX--,若 CX≠0 **且 ZF=1** 则跳转
- `LOOPNE`/`LOOPNZ`(E0):CX--,若 CX≠0 **且 ZF=0** 则跳转
- `JCXZ`(E3):**CX 不递减**,仅当 CX=0 时跳转

`JCXZ` 不碰 CX。另外三条都碰,而且**减到 0 之后不跳**——所以循环体执行 CX 次。

### 9. INTO 只在 OF=1 时才做事

`OF=0` 时 `INTO` 是**一条什么都不做的指令**,不是触发 int 4。和 `INT 4` 的编码效果一样但语义不同。

### 10. LAHF/SAHF 只碰低八位

- `LAHF`:AH ← FLAGS 的低字节(SF ZF 0 AF 0 PF 1 CF 的顺序)
- `SAHF`:FLAGS 的低字节 ← AH

**`SAHF` 之后也要 `vm86_flags_normalise()`** ——它写的是 FLAGS 的一部分,虽然理论上不该碰到高位,但便宜且安全。

### 11. CMC 只翻转 CF

一个标志位,别的什么都不碰。

## 三、I/O(E4-E7、EC-EF)——需要你做一个决定

`IN`/`OUT` 访问的是**端口**,而这台机器上还没有任何端口设备(那是 M4)。

所以:

- **不要触发无效指令异常。** 真实硬件上 `in al, 60h` 是合法指令,只是结果取决于设备。让它异常会让探测端口的程序直接死掉,而那种探测在真实 DOS 程序里很常见。
- **选一个一致的行为**,比如:所有 `IN` 返回 0xFF(浮空总线,和未映射内存一样),所有 `OUT` 被丢弃。
- 在注释和报告里**写明你选了什么**。

端口号在 `E4`/`E5`/`E6`/`E7` 里是**立即数一个字节**;在 `EC`/`ED`/`EE`/`EF` 里是 **DX**。不要混。

## 四、WAIT(9B)

8086 上 `WAIT` 是等协处理器。没有协处理器时它**什么都不做**。

实现成 NOP 即可,但加一行注释说明原因——否则下一个人会以为你忘了实现它。
