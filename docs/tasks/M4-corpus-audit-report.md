## 二、发现

### F1(过期文档,**会主动误导**)三处注释说 `disk.asm` 会打印 FAIL,而它今天过了

**事实:** `disk.asm` 里那条"NOTE ON THE FROZEN INTERFACE"、套件文件头那节"On the one case expected to fail today"、以及 `case_disk` 的失败文本,**三处**都写着"宿主服务回不去 CF,所以本用例会一直 FAIL,直到那件事被解决",并且**点了名**说 `M4-E-report.md` 有记录、`trap.c` 没有把它补回去。

**而那件事在 `5a929f2` 就已经解决了**(`vm86_host_trap` 把标志合并回帧)。我今天跑基线:**七个用例全绿,`disk` 在内**。

**为什么这条比"注释过时"重:** 它不是静止的错误,它**会说话**。我把磁盘镜像改一个字节(M4 实验),`disk` 立刻按预期报红,而它打出来的第一行是:

```
FAIL  disk: the sample printed FAIL, which is what it does when a disk read
      does not report the way INT 13h reports. As host.h and trap.c stand, a
      host service cannot return CF at all ... this failure is the interface's
      and not the disk's. See M4-E-report.md.
```

**一条真的磁盘回归,会拿到一份说"这不是磁盘的问题、去看接口"的诊断。** 这正是"描述着另一个程序的文件头比没有文件头更坏"——而它刚在 `firmware.c` 上被判过一次。

**建议:** 三处一起改。改法不必只删:把"这里曾经不能回 CF"**保留成历史**,并把**现在**的状态写清楚(§六给了模板)。`disk.asm` 里那段还可以顺手改成"这条路径的验证在 `test_bios13` 的真实路径用例里",免得下一个人以为它没人管。

### F2(声称的规则**从来没被测到**)`cursor.asm` 的第三条第 3 点

`cursor.asm` 的头写着三条主张,第 3 条是:

> **The page is real.** ... **and the page a write lands on is the one named in BH rather than the one that happens to be active.**

**后半句没有被测到。** 程序里每一次带 BH 的调用,**BH 都恰好等于当时的活动页**:

| 步 | 调用 | BH | 活动页 |
|---|---|---|---|
| 2 | `09h` 写 'A' | 0 | 0(还没换页) |
| 3 | `03h` 读光标 | 0 | 0 |
| 5 | `02h` 设光标 | 1 | **1**(第 4 步刚用 `05h` 切过去) |
| 6 | `09h` 写 'B' | 1 | **1** |

所以"用 BH"和"用活动页"这**两条规则在每一步都给出同一个答案**,一个把 BH 整个忽略掉的实现照样全绿。

**我把这句话量了出来**(M2):把视频服务里 `02h`/`03h`/`08h`/`09h`/`0Ah` 的页号全部换成活动页,然后跑两套:

| 套件 | 结果 |
|---|---|
| `test_bios_programs`(语料) | **7 个用例全绿** —— 这条主张没被它测 |
| `bios10_audit`(D 的审查套件) | **5 条断言红,跨 3 个用例** —— 那里有一条用例专门让 BH 与活动页**不一致** |

**这正是协调方预言的形状:"这个程序用到了那条通路"和"它看起来像用到了那条通路"。** 三条主张里,前两条(02h/03h 往返、09h 不动光标)是真的被测到了;第三条只测到了"页是分开的内存"(把页项整个忽略会让 'B' 落到页 0 的 163 格,那条断言会红 —— 这一半是真的)。

**建议:** 在 `cursor.asm` 里加一步 —— 换页之后,用 **BH 指回页 0** 写一个字符,再断言它落在页 0 而不在当前显示的页 1。成本是四条指令,而那句话就从"看起来测过"变成"测过"。

### F3(头里的一句话是错的)`cursor.asm` 说"两个写在同一格"

同一段的句子:

> The row and the column are chosen so that page 0 and page 1 would collide if the page were ignored: **both writes are at the same cell index.** Page 0 gets 'A' at cell 410, page 1 gets 'B' at cell 163 ...

**410 和 163 不是同一个格号。** 真正撞的是**同一个格号在两个不同的页里**(页 0 的 163 与页 1 的 163)——也就是"忽略页项"会让它们落到同一个线性地址。句子把这件事说反了,而下面那两个数字是对的、断言也是对的(页 0 的 163 被断言仍是空格 ✓)。**改一句话的事,但它恰好是一个读者会拿来理解设计的那句。**

### F4(小事)`disk.asm` 说"必须回 `CF=1`、`AH=04h`",而 AH 没人查

头里的"Expected"写着第二次读"must come back with CF set, **AH=04h**"。程序**只查 CF**(`jnc read_bad`),用例也只查 CF 与缓冲区。**AH 的那一半由 `test_bios13` 覆盖**(`bios13` 有一条专门断言几何外请求报 `04h`)——所以**不是缺口**,但两处文档的口径不一致:语料头说着一个它不查的东西,而读者会以为这里有覆盖。建议在头里注明"AH 由 `bios13` 的套件覆盖"。

### F5(设计说明,不是缺陷)`main()` 在机器建不起来时 `return 0`

`replay.h` 用 `__has_include` 判断四个服务头在不在,不在就打印一行"7 samples, none run"并**退出 0**。这是 E 有意为之(任务书:不该把别人的缺席报成语料的缺陷),而且**现在是死代码**(四个头都在)。记在这里只因为它是一种形状:**一个什么都不跑却报成功的套件**。它今天触发不了;但如果哪天四个头里少一个,`make test` 会**绿**。**不改,但要知道。**

## 三、手算:`scroll.asm` 的终屏(25×80)

按协调方的要求**用纸笔算,不读代码确认**。逐步如下(格号 = 行 × 80 + 列):

**第 1 步** 直接填整页:第 r 行 = 字母 `'A'+r`,属性 0x07 → 第 0 行 'A' …… 第 24 行 'Y'。光标设在 (24, 0)。

**第 2 步** 八十次 `0Eh` 写 'x'(BL=0x0F,文本模式下被忽略):写满 (24,0)…(24,79) 共 80 格,属性保持格子里原有的 0x07;第 80 次之后光标右移越界 → **上滚一行**。
- 滚后:第 r 行 = 原第 r+1 行(r=0..23),新第 24 行 = 空格。
- 所以 第 0 行 'B' …… 第 22 行 'X',**第 23 行 = 80 个 ('x', 0x07)**,第 24 行 = 空格。

**第 3 步** `06h AL=0` 填 CH=10,CL=0,DH=14,DL=79,属性 BH=0x20 → 第 10..14 行 = (' ', 0x20)。

**第 4 步** `06h AL=1` 滚 CH=0..DH=24、CL=0..DL=79,填入属性 BH=0x30 → 第 r 行 = 原第 r+1 行(r=0..23),第 24 行 = (' ', 0x30)。

**终屏(手算):**

| 行 | 内容 | 属性 |
|---|---|---|
| 0..8 | 'C' 'D' 'E' 'F' 'G' 'H' 'I' 'J' 'K' | 0x07 |
| 9..13 | 空格(第 3 步的清窗带) | **0x20** |
| 14..21 | 'Q' 'R' 'S' 'T' 'U' 'V' 'W' 'X' | 0x07 |
| 22 | 80 个 'x' | 0x07(**不是** BL 的 0x0F) |
| 23 | 空格(第 2 步那次上滚填进来的) | 0x07(实现的选择,不查) |
| 24 | 空格(第 4 步的填入) | **0x30** |

**与套件的断言逐条比对:完全一致。** 包括三个最容易错的:

- **第 0 行是 'C' 不是 'B'** —— 两次上滚各吃掉一行(第 2 步和第 4 步),而第 1 步的 'A' 在第 2 步就被滚掉了。
- **第 14 行是 'Q' 不是 'P'** —— 清窗带占了 10..14 五行,滚上来之后第二段字母从 'Q' 开始。
- **第 22 行是 'x'** —— 第 2 步那一行 'x' 被两次上滚推到了 22。

`.asm` 头部写的期望与这套一致,**套件与手算也一致** —— 三份独立的东西对上了。这是判据 2 的答案:**期望值是手算得出来的,而且算出来一样。**

## 四、六个注入(判据 1、4、5)

在 `/var/tmp` 的副本上跑(`cp -r dos libk tools`,改副本、`make -B`、还原)。每个注入的**改动内容都在下面写着**,模式必须恰好匹配一次,匹配不到会当场报错而不是静默跳过。

| 注入 | 改的是 | 结果 |
|---|---|---|
| **M1** 段号改回 0(`VM86_BIOS_LOAD_SEGMENT 0x1000 → 0x0000`) | `replay.h` | **只有 `vectors` 红**。失败文本:`entry 64 holds CD00:03B8, which is not the firmware's stub` —— 而 `B8 03 00 CD` 正是 `hello.asm` 的前四个字节。**独立复现了 E 的说法**(改回段 0 只有那一条红) |
| **M2** 视频服务忽略 BH,一律用活动页 | `bios10.c` 五处 | **语料全绿,`bios10_audit` 红 5 条**(见 F2) |
| **M3** `0Eh` 改写成写 NUL | `bios10.c` | 5 个用例红(hello/scroll/timer/key/disk),**失败的是 `hello: the text`,不是 `direct: the text`**;M4-8 那条比对打的是"byte 0 在 hello 之后是 00,在 direct 之后是 4D" |
| **M4** 磁盘镜像的 `'M'` 改成 `'Z'` | `test_bios_programs.c` | **只有 `disk` 红**,而它打的是 F1 那段**错误诊断** |
| **M5** 定时器中断不再链到 `INT 1Ch` | `bios1a.c` | **只有 `timer` 红**,5 条断言:机器"never finishing"、自身计数 0、BDA 计数 59 |
| **M6** `06h` 的填入属性用 0x07 而非 BH | `bios10.c` | **只有 `scroll` 红**:清窗带 5 行与第 24 行的属性各一条 |

**M3 是判据 5 的答案,而且是两侧的:** 掐掉 BIOS 的输出路径,`hello` 死、**`direct` 活** —— `direct.asm` "不用任何中断"这句话因此是**测出来的**,不是读出来的。
**M5 是判据 1 对 `timer` 的答案:** 它的计数不是自己编的,链条一断它就永远等下去。
**M4 是判据 2 对 `disk` 的答案:** 期望值绑在**磁盘内容**上,而不是绑在程序自己打印的字符串上。

## 五、断言读的是谁(判据 3)

两条读法,套件里都有,而且分得清:

- **`mem8/16/32`、`page_cell`、`expect_mem*`** → `vm86_bios_memory(machine)`。我核过 `replay.c`:`vm86_bios_memory()` 返回的**就是**挂给 `vm86_mem_attach` 的那块活数组,**不是拷贝**。所以这一类是独立读。
- **`vm86_bios_screen()`、`expect_cell`、`expect_row`** → 一个**拷贝**:`record_frame` 把 `present()` 拿到的指针 `memcpy` 进 `screen.cells`。而 `present()` 拿到的是 `bios10_active_page(cpu, &video)` 的返回值 —— **生产路径上的那个访问器**。

**所以"录下来的屏幕"离 guest 内存只隔一个访问器**,而那个访问器正是 `hello/direct` 要验的东西(`M4-8`)。按用例分:

| 用例 | 读 guest 内存的地方 | 读录屏的地方 |
|---|---|---|
| hello/direct | —— | 文本、页的其余部分、M4-8 的逐字节比对、光标 |
| vectors | 向量表(四条表项) | —— |
| cursor | 两页的格子、BDA 的每一个字、`03h` 的返回值 | —— |
| scroll | —— | 终屏逐行 |
| timer | BDA 计数、1Ch 计数 | 打印的 '5'、光标 |
| key | CPU 的 SP | 回显的 'a'、光标 |
| disk | 两个缓冲区 | "OK"、光标 |

**一个值得写的观察:`scroll` 与 `hello/direct` 只读录屏。** 那是**对的**(它们的主张就是"屏幕上出现了什么"),但要看清它依赖什么:录屏只在"后端只由 `bios10_active_page()` 喂"时才是 guest 内存的忠实拷贝。这条**今天成立**(我读了 `present_now`),而它是**约定**而不是**断言** —— 没有一条用例检查"后端拿到的指针确实指向 guest 内存"。E 在 FunnyOS 那一侧挖出的悬空指针就是这一类的另一面:**同一份数据流两级,级与级之间没人测**。留作观察,不算发现。

## 六、值得留的(审出来是好的,不要在后面几轮里改掉)

1. **M4-8 的两侧设计。** `hello` 走服务、`direct` 不走,两张**整页**(4000 字节)逐字节比对,而且"两页各自的其余部分"分别断言 —— 这让"影子屏幕"这一类错误无论藏在哪一边都会露出来。
2. **`cursor.asm` 的格子选择。** 页 0 写 410 格、页 1 写 163 格,再断言**页 0 的 163 格是空的** —— 一次写入忽略页项会在两个地方同时现形。(头里那句话写错了,设计没错 —— F3。)
3. **不对实现的选择下断言。** `scroll` 第 23 行的**属性**明确不查,理由写在注释里(参考文件只说 `0Eh` 内部转调 `06h`,没说传什么属性)。**知道哪里该停手**,和知道该查什么一样重要。
4. **`page_stride()` 从 `0040:004C` 读页间距。** 这看起来像"从被实现的账本里读期望值",但同一个用例里 **0x1000 这个字面量是被断言了的**(`cursor: the page stride`)—— 所以循环性是闭合的。而且头里写明了理由(不重复实现自己的算术)。**这是一个想过的选择,不是疏忽。**
5. **`vectors` 那条用例。** 它断言的是"表项等于固件自己的桩"(`vector * VM86_TRAP_STRIDE : VM86_TRAP_SEGMENT`),不是"看起来不像程序字节" —— 前者是定义,后者是启发式。
6. **`replay.h` 里"程序和栈都在镜像里"那段说明** —— 它解释了为什么四个段寄存器都要指过去,并给出了 `mov si, message` 配 `DS = 0` 会读到向量表这个具体后果。
