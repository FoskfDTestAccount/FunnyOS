## 二、这一层是什么,不是什么

**一块线性字节数组 + 几何参数**。`struct bios13_disk` 由调用方拥有(镜像指针、字节数、柱面/磁头/扇区数、上次状态),服务只管读写那块数组。宿主可以是测试里的一块 `malloc`、内核里的一个区域,或者将来映射的文件——**这一层不知道也不问**。

**在这一层里没有文件系统,而且是故意的。** 不做 FAT:一个懂 FAT 的实现会让"读到的东西看着像那么回事"冒充"读对了",而这层存在的全部意义就是让寻址错误暴露出来。

**服务是纯函数,不碰 `host.h`。** `bios13_service(cpu, ctx)` 只从 `cpu` 的寄存器和 guest 内存取值,所以它在 A 的中断核心落地**之前**就能编译、链接、测试——这也是 M4-README 里"B/C/D 不用等 A"那条的实现方式。注册是一行,由接入方写:

```c
vm86_register_service(VM86_INT_DISK, bios13_service, &disk);
```

本套件**不经过陷阱**,直接调服务函数;"guest 用 `INT 13h` 真的调到了"那条留给 E 的验收语料(M4-README 协调点一)。

## 三、实现了哪些 AH

| AH | 功能 | 出口 |
|---|---|---|
| `00h` | 复位 | `CF=0`、`AH=0`,**并忘掉上次的错误**;没有控制器,所以除此之外什么都不做 |
| `01h` | 取上次状态 | `AH` = 记住的状态,`CF` = 该状态是否为 0;**这条不改动记住的状态** |
| `02h` | 读扇区 | 成功 `CF=0`/`AH=0`/`AL=实际扇区数`;失败见下 |
| `03h` | 写扇区 | 同上,数据**真的落到那块数组上** |
| `04h` | 校验 | **只判驱动器与地址**,然后报成功。不做比较,也不检查 64 KiB 边界(它没有缓冲区) |
| `08h` | 取驱动器参数 | `CH`/`CL`(高 2 位 + 低 6 位)/`DH` = 三个**最大值**;`DL` = 驱动器数 1 |
| `15h` | 取磁盘类型 | **不做**,报 `01h`(第 5.6 节) |

失败路径一律:`CF=1`、`AH=` 状态码、`AL=0`,且**一个字节都不动**。

状态码只产生五个:`00h`、`01h`、`04h`、`09h`、`0Ch`。**`02h`(找不到地址标记)和 `10h`(CRC 读错误)故意不产生**:两者说的都是控制器读磁道失败,而这台机器没有控制器可以那样失败。

## 五、坑 1/2/4/5/8 各自怎么决定的

### 5.1 坑 1:`CL` 的高两位

**解出来,而不是把 `CL` 直接当扇区号。** 解码器是三个公开函数(`bios13_cylinder` / `bios13_sector` / `bios13_lba`),不是内联在服务里的表达式——因为**这条只能靠解码器本身钉住**:80 柱面的盘上,柱面号 ≥ 256 的请求无论怎么解码都会先被范围检查拒掉,示例代码看不出区别。

套件里两条:

- `bios13_cylinder(0x2C, 0x41) == 300`、`bios13_cylinder(0x00, 0x82) == 512`(0x41 是**第九**位,0x82 是**第十**位,两者可区分),外加 `bios13_cylinder(0x01, 0x00) == 1` 和 `bios13_cylinder(0x00, 0x40) == 0x100` 分别钉住"低位在 CH、高位在 CL"。
- 另外还有一条**走服务**的:给这个测试盘 1024 个柱面、5.3 MB 的镜像(堆上一块静态数组),在柱面 300 写一个扇区,断言它落在偏移 `10800 * 512`。这一条证明服务**确实用了解码器**,而不只是解码器自己是对的。

**变异验证:** 把 `BIOS13_CL_CYLINDER_SHIFT` 改成 0 → 16 个用例报红,包括这两条。

### 5.2 坑 2:`AL = 0` —— 决定:**拒绝**(`CF=1`、`AH=01h`)

**依据:** `docs/dos-refs.md` §4 明确给出取值域 1–128,并明确写着"`AL = 0` 表示 18 扇区"**在那批资料里没有出处**;§8 把这条列为"未定,由任务 D 决定"。

三个选项我这样比较:

| 选项 | 后果 |
|---|---|
| 实现成 18 | 用**一个没有出处的记忆**决定程序看到什么;而且装进一个"要 0 个扇区"的调用方**没理由开那么大**的缓冲区里——**猜错就是内存被踩**,而不是一个错误返回 |
| 当作 1 | 同样是编出来的数;若调用方真的指望 18,拿到的是**静默的少量传输**,正是这个项目最不想留的那类失败 |
| **拒绝** | **不会静默**:调用方拿到 `CF=1`,缓冲区一个字节没动。代价是一个依赖那个传说的程序会**响亮地**失败,而不是安静地出错 |

所以选拒绝,`AH=01h`(dos-refs §4 给 `01h` 的定义是"功能号**或驱动器**不可用",是这批资料里最接近的一条;`04h` 会说"扇区没找到",那是对扇区的谎话)。

**任务书要的那个后果,写在这里:** 一个用 `AL=0` 的程序在这台机器上**不会**读到 0 个扇区然后以为成功——它会拿到 `CF=1` 和 `01h`。任务书担心的那个"静默成功"在本实现里不存在,这一点有专门的用例钉着(见第 6 节)。

**顺带:`AL > 128` 不另设限制。** 128 = 一个 DMA 页,所以 129 及以上**必然**跨边界,读和写会拿到硬件自己用的那个码 `09h`;为它再编一个参数错误,只会让同一个事实有两个答案。(校验没有缓冲区,不受这条影响。) 这一条也有用例。

### 5.3 坑 3(越界)与坑 9(写路径)

**越界:** 整组扇区**在搬第一个字节之前**全部判完,任何一段越界 → `04h`、`CF=1`、缓冲区不动。多扇区请求"起点在内、终点在外"也是整次失败(用例:`4 扇区的盘 + 扇区 4 要 2 个`),并且失败时 `AL=0`。

**写路径:** 写用例是 **写 → 换一个缓冲区读**(`BUF_A = 0x20100` 写,`BUF_B = 0x30100` 读),第二个缓冲区先填 `0xFF`。**变异验证:** 把写分支改成空操作 → 6 个用例报红。

### 5.4 坑 4:64 KiB 边界

判据是 `((ES*16 + BX) & 0xFFFF) + 扇区数*512 > 0x10000` → `09h`。

**边界的两侧都钉住**:`2000:FE00` 加一个扇区正好停在页尾→**允许**;同处要两个扇区→拒绝;`2000:FF00` 一个扇区→拒绝。漏掉这条不会立刻出问题,所以两侧都要有用例,否则"`>` 写成 `>=`"这种错一辈子都不报红。**变异验证:** 去掉这个检查 → 1 个用例报红。

**`04h`(校验)不吃这条规则**,因为它没有缓冲区,见下。

### 5.5 坑 5:`08h` 的三个"最大"

返回**最后一个的下标**,不是个数——而**只有扇区那一个不减一**:

- `CH = 79`(柱面从 0 数起,所以是 79 不是 80),`CL` 高 2 位 = 79 的高位 = 0
- `DH = 1`(磁头从 0 数起,所以是 1 不是 2)
- `CL` 低 6 位 = **18**(扇区从 1 数起,所以**最大扇区号就是个数**)

写错任一个,程序按返回值算出来的容量就少一格或一片。用例除了逐个断言这四项,还**用这些值反算容量并与真实挂上去的镜像长度比对**——这是唯一能说明"这个答案描述的是这块盘"而不是"一个看起来合理的盘"的检查。**变异验证:** 把扇区那一个改成减一 → 2 个用例报红。

**一个发现:`docs/dos-refs.md` §4 只列了 `08h` 的功能名,没有它的出口。** 这一节的依据目前是任务书的坑 5,不是查证级的。建议协调方补一次查证,因为按返回值算容量的程序不只一个。

### 5.6 坑 6:`15h` —— 决定:**不做**

理由不是"不需要",是**查不到它返回什么**:dos-refs §4 把它列在功能表里,但**没有任何一条说它的出口**——类型码是什么、`CX:DX` 是什么,全都没有。任务书坑 6 允许不做,要求报 `01h` 而不是 `00h`。

**为什么不"先按记忆实现着":** 报 `01h` 会把程序送到**这条路**:它认为"这台机器没有 15h",于是退回去调 `08h`——而 `08h` 是 dos-refs 查到、本实现也答得对的。按记忆实现,程序会走**我们编出来的那条路**。一个"老 BIOS"是真实且常见的配置,退回是它本来就支持的路径;而一个猜错的类型码不是。

用例钉的两件事:15h 报 `CF=1`/`AH=01h` 且**不动 `CX`/`DH`**(先塞进可识别的值,好让"没动"看得见),以及**退回的那条路真的答得对**(紧接着 `08h` 得到 `CH=79`/`DH=1`/`18`)。

### 5.7 `BL` 与 `ES:DI` —— 决定:**不动**

`08h` 应该回驱动器类型(`BL`)和参数表指针(`ES:DI`)。**这两张表在这个仓库里都没有出处**,编一个数比留原值更坏:留原值,程序读到的是它自己放进 `BL` 的东西;编一个,程序读到一个**我们声称是真的**的常数。所以两者都保持原样,并在这里写明——这是一个已知缺口,不是疏忽。

`DL` 是个例外,写了 1:那**不是表查出来的**,是这台机器的事实(只有一块软驱,`08h` 的出口语义记作【记忆】)。按 [记忆] 实现的那一条要在报告里能被看见,这就是它。

### 5.8 坑 8:`04h` 校验 —— 决定:**只判地址,不做比较,且不做校验**

**没有真的校验,这一点必须说清楚:** 这台机器没有控制器,也就没有 CRC 可以失败。所以 `04h` 做的是它能知道的那部分——**驱动器对不对、这个地址磁盘有没有那个扇区**——然后报成功。它不碰 guest 缓冲区(它本来就没有缓冲区概念),也不检查 64 KiB 边界。

**为什么不做比较:** dos-refs §8 把"硬盘上是否与内存比较"列为**来源互相矛盾**、由任务 D 决定的条目。两个方向都试过了:

- 若**真的比较**:调用方必须先把期望的数据放进 `ES:BX`;而一个没设过 `ES:BX` 的程序(它以为校验不用缓冲区)拿到的是**莫名其妙的失败**。
- 若**不比较**:最坏情况是校验永远报成功——**一个假的"没问题"**。

后者更坏吗?考虑用途:校验是用来发现**介质坏**的,而这台机器的"介质"是宿主内存里的一块数组,**它不会坏**。所以"永远报成功"在这里与事实一致;而"可能报假失败"会破坏本来能跑的程序。选不比较,并把"它不是真的校验"写进头文件、写进用例名、写进本报告。

用例:好地址 → 成功且 `AL=1`、缓冲区原封不动;坏地址(几何外、镜像外)→ `04h`;`ES:BX` 跨页 → **仍然成功**(钉住"它不吃 DMA 规则"这个决定)。

## 六、测试:22 个用例,和它们怎么被证明会红

用例清单(`make test-bios13` 的输出顺序):扇区 1 落在偏移 0 / 磁道→磁头的接缝 / 磁头→柱面的接缝 / `CL` 的高两位 / 服务到达柱面 300 以上 / 越界读不动缓冲区 / 越界写不动镜像 / 几何外请求 / 扇区 0 / 64 KiB 边界 / 写→换缓冲区读 / 写到地址说的地方 / `AL=0` 被拒 / 成功清 CF 和 AH / `01h` 记得上次错误 / 复位忘掉错误 / 未实现的功能号 / 不是软驱的驱动器号 / 没有磁盘的机器 / `08h` 的四个最大值 / `15h` 被拒且退回 `08h` / `04h` 只判地址。

**每条用例都成对核对 `CF` 和 `AH`**,成功的用例也断言 `CF=0` **和** `AH=0`——只设 `AH` 不设 `CF` 的实现是最难发现的那一类,一个只断言 `AH` 的套件抓不住它。

| M14 `AL=0` 当作 1 个扇区 | 1 个红 |
| M15 扇区 0 当作扇区 1 | 1 个红 |
| M16 驱动器不可用改答 `01h` | 1 个红(证明用例钉住的是**决定**,不是"随便什么错误码") |

**M10 是等价变异,不是漏网。** 去掉 `sector == 0` 的拒绝之后,`sector - 1` 在 `uint32_t` 里下溢成 `0xFFFFFFFF`,而 64 位越界检查照样会拒绝它——**对任何输入,可观察行为都不变**。为了让这条用例仍然有意义,加了 **M15**:一个"扇区 0 就是扇区 1"的实现**会**报红。也就是说这条用例抓的是"有人决定给扇区 0 一个含义",不是"有人忘了写 `||`"。

**顺带一条方法论教训**(给下一份任务书):变异脚本必须**报告"模式匹配 0 次"**,不能只报"用例没红"。M12(15h 相关)在我删掉 15h 的实现之后就成了一个匹配 0 次的空操作,如果它只被记成"存活",那一行会看起来像一个覆盖缺口,而实际上它什么都没做。

## 七、`tools/mkfloppy.py` 怎么用

```
mkfloppy.py <输出文件> [--size-bytes N] [--put <偏移> <文件>]...
```

- 默认造 **1 474 560 字节**的全零镜像。
- `--put` 把一个文件放到指定的**线性字节偏移**,可以给多次;偏移接受十进制和 `0x` 前缀。
- **放不下就报错退出(返回码 2),并且不写输出文件**——输出文件已存在时**保持原样**,不截断。

```
tools/mkfloppy.py disk.img                                  # 空盘
tools/mkfloppy.py disk.img --put 0 boot.bin --put 0x200 d.bin
tools/mkfloppy.py short.img --size-bytes 1024 --put 0x300 d.bin
```

**偏移是线性字节偏移,不是柱面/磁头/扇区。** 从 CHS 到偏移的换算是 `INT 13h` 自己做的事,不该换个语言再实现一遍——两份迟早会不一致,而那种不一致正是这一层要消灭的东西。

验证过的行为(手工跑过):默认大小正确;`--put 0` 与 `--put 0x200` 分别落在 0 和 512(镜像里只有那 12 个非零字节);偏移越界 → 返回码 2、**不创建输出文件**、已有文件内容不变;正好放得下(1024 字节盘、偏移 1016、8 字节文件)→ 成功;输出文件不存在 → 返回码 1;`--size-bytes -1` 与坏偏移 → 返回码 2。

**给 E:** 任务书说你的套件**不要调这个脚本**,把期望的镜像字节直接写在测试里——同意,而且 `bios13_init(&disk, image, size)` 就是为这个准备的:**镜像可以是几十个字节的一小块**。几何是结构体里的字段,不跟着镜像长度走,所以"镜像短于一块盘"是合法状态,越界请求会得到 `04h`。

## 八、没实现的 AH,以及那些程序的后果

未实现的一律 `CF=1`、`AH=01h`,而且**记住这个状态**(下一次 `01h` 会取回 `01h`)。

| AH | 功能 | 用它的程序会怎样 |
|---|---|---|
| `05h`/`06h`/`07h` | 格式化 | 拿到 `01h`。**这台机器不能格式化**——M4 不在范围内,但要知道:M5 之后想跑 `FORMAT` 是跑不起来的 |
| `09h`/`0Ah`/`0Bh` | 初始化驱动器、长读、长写 | `01h`。长读/长写用来碰 ECC 字节,几乎只有诊断程序会调 |
| `0Ch`/`0Dh`/`0Eh`/`0Fh` | 寻道、控制器内存诊断等 | `01h`。**寻道失败通常被程序忽略**(真正要的数据在 `02h` 里),所以这条大概率无害 |
| `10h` | 测试驱动器就绪 | `01h`。**这条要留意:** 一段用 `10h` 逐个探测驱动器的引导代码会认为**没有驱动器**。它没有出现在查到的功能表里,所以按"未实现"处理;如果 M5/M6 碰到,这是一行就能补的 |
| `11h` | 重新校准 | `01h` |
| `12h`/`14h` | 控制器自检 | `01h`。程序据此认为控制器有毛病——对一台没有控制器的机器,这个判断很难说错 |
| `16h` | 检测盘片是否换过 | `01h`。程序无法知道"盘被换过"——**这是事实**,这台机器上没有盘可以换 |
| `17h`/`18h` | 设置驱动器/介质类型 | `01h` |
| `19h` | 磁头归位 | `01h`。和寻道一样,通常被忽略 |
| `1Ah` | 格式化 ESDI | `01h` |
| `15h` | 取磁盘类型 | `01h`,**故意**,见第 5.6 节:程序会退回 `08h`,那是它本来就支持的路 |

**没有被 `INT 13h` 覆盖、但要知道的**:`0Ch` 这个码在 dos-refs §4 里**不存在**(见第十节),`AL` 出口"不总是可靠"所以本实现不靠它做判断,以及 `04h` 不是真的校验。

## 九、给 E 和给验证的人

- **注册:** `vm86_register_service(VM86_INT_DISK, bios13_service, &disk)`,`ctx` 是 `struct bios13_disk *`。
- **`disk.asm` 只要用 `AH=02h`、`AL=1`**(别用 `AL=0`,那会拿到 `CF=1`/`01h`,见第 5.2 节)。

## 十一、我踩到的新坑(给下一份任务书)

1. **"接缝"用例容易写成"同一个位置"。** 我第一版把 `(0,0,18)` 和 `(0,1,1)` 当成一个地方写了——它们其实是**相邻**的两个扇区(LBA 17 和 18),写一个读另一个当然读不到。正确的形状是:**两个地址各写各的模式,断言它们落在相邻的偏移上**。这条值得写进任务书,因为"下一扇区"这句话本身就容易被读成"同一个"。
2. **`AL=0` 这一类"查不到出处的历史怪癖",任务书应该从一开始就要求写明来源等级。** 这份任务书后来自己改了(坑 2),但改动传到我这里之前,我已经按那个"18"写了一版实现和一条用例——**改动的代价是重写一条用例和两处注释**。如果 M5 的任务书里还有类似"真机上就是这样"的句子,建议**先标注来源等级再发**。
3. **变异脚本要能报"模式匹配 0 次"**(第 6 节),否则一个失效的变异会被记成"存活",看起来像覆盖缺口。
4. **等价变异会被误判成漏网。** 报"存活"之前先问一句"这个变异真的改变了任何可观察行为吗"——M10 就是下溢被另一个检查兜住了。
